# 暂不处理的小问题（可排期）

各 PR 终审时记下、当时没修的小问题。修掉一条就删一条；排进某个 PR 时在条目后面写上 PR 号。

## 兑换码与邀请（PR #36）

- 旧接口 `POST /account/invite-code` 仍会覆盖邀请码（前端不调用）。
- 被邀请人在多个区服都达到等级时，奖励发到先被扫到的那个区服，金额不受影响。
- 邀请奖励缺少跨月重新计数的测试。
- 后台兑换码页：自定码重复时，提示不够明确。
- 后台兑换码页：选"当前区服"但还没选区服时，点按钮没有反应。
- 兑换框不会去掉码里的空格和连字符。
- 某个区服扫描出错时，同一轮里后面的区服会被跳过（原有写法）。

## 厨具数值和小修（PR #37）

- 历史数据里强化记录不全或有多余记录的厨具，重算后再回退，扣回的数可能不准。只影响老数据。
- 说明里的数字没改成功时，构建不会报错。
- `tower_fix.json` 里同一层写了两次，不会报错，后一条生效。
- 首页签到后只显示"今天已签到"，看不到领了什么奖励。

## 举报审核（PR #38，6B-1）

- NPC 店和自己的匿名帖旁边也显示举报按钮，点了会被拒。
- 默认改名"餐厅{id}"如果已被占用，后台只提示"处理失败"，没有说明原因。
- 同一内容被驳回、改过并处理、又改回原样后，再被举报只会记数，不会开新案。
- 内容已经不在时，被处理人收到的邮件措辞别扭；后台确认框也仍按"会清空/删除"来描述。
- 后台举报列表只显示最近一次举报时间，没有显示最早一次。
- 错误码 `report_retry`（正常不会出现）没有中文。
- 举报和处理同时发生时，可能对刚删掉的内容开一个空案。
- 处理举报时读举报人列表用了事务外的连接，多占一个数据库连接。

## 可疑数据、数值说明、上线检查（PR #39，6B-2）

- 上线检查遇到版本冲突（409）后，页面仍拿着旧版本号，要刷新页面才能再点。
- 区服数值页搜索：区分大小写。
- 区服数值页搜索：不搜分组说明，也不过滤功能开关；功能开关的勾选框没有悬停说明。
- 区服数值页搜索：清空搜索时，手动展开的分组会被收起。
- 可疑数据·多号：先取前 N 个 IP 分组再取设备分组，设备分组可能被挤掉；每组账号数不设上限。
- 可疑数据页：快速切换区服时偶尔会显示旧区服的数据（没有丢弃过期响应）；加载中显示"没有数据"。
- 可疑数据·资源暴涨：网址里填不存在的日期（如 2026-02-30）会报 500，应报 400。
- 仓库（StoreView）和教室（ClassroomPanel）的剩余时间还是只显示到小时，可改用 `utils/remain.ts`。
- e2e `launch.spec.ts` 新建的测试区服编号可能和以前关掉的撞车；中途被杀掉会留下一个开着的测试区服。
- 性能：兑换码被锁查询对每个键单独 GET/TTL；`cleanLoginTrace` 全表扫描；资源暴涨每种资源扫 3 次。现在的数据量下不影响。

## 游玩指引、新手码、菜园姐、我的账号（feat/guide-account）

- 指引页新手码接口每次都调 `npcAccountId`（insert … on conflict），白白消耗一个账号自增 id。
- 新手码同步用 `JSON.stringify` 比较奖励，jsonb 键顺序不同，多字段的码每次重启都会"更新"一次（结果无害）。
- 改密码：审计没记 IP 和设备，且和改密码不在一个事务；改密码后旧的重置密码链接仍有效（最多 1 小时）；会话轮换失败时提示"修改失败"，但密码其实已改。
- 首页新手提示 10 级就消失，XINSHOU20 在首页没有提示。
- 区服关了兑换码功能时，指引页仍显示"领取"，点了报错。
- 启动同步失败时，所有新手码显示"已结束"直到下次重启；同步成功时没记结果日志。
- 后台兑换码列表只列最近 100 个通用码、不能按码搜，以后可能找不到新手码来停用；停用后没有重新启用的办法。
- 仓库里两种未知类型的道具可能交错，出现重复的"其他"标题。
- `main.css` 里新样式插在"更多"注释和它的规则之间。
- 缺少 `/guide/codes`、`/account/profile` 未登录、未开店时的接口层测试。

## 快速数值模拟（feat/sim-fast，问题记录 160）

- 快速机器人买菜后会减少缺口，全真机器人不减：同一种菜在日常和特价货架都有时，全真会买两遍。核对时有一点差异。
- 未穿戴的厨具在快速模型里不占仓库格（真实会占 `store_num`），快速机器人"仓库满了"会来得晚一点。
- `buyable` 判断"永久"用的是 `invalidHours`，真实用 `goodsEffectHours`（还看 `value.time`）。机器人目前不买勋章，不影响。
- 开局几个小时的天气和巡街和全真模拟不同：全真开局就按最近时段重掷，快速模型要到下一个天气时刻和巡街时刻。
- 旁支的常驻加成要到第二天第一次上线才换等级段，最多晚一天。
- 分位数用 `floor(p·n)`，偶数个时中位数取偏上的那个。
- 核对表按字符串排序，第 10 天会排在第 2 天前面。
- 机器人整局用一个随机流：两套数值的决策一分叉，之后的随机数就不再对齐，公共随机数会变弱。可以改成按（种子, 机器人, 轮）派生。
- 命令行：
  - `--calibrate` 时显式写 `--days 30` 或 `--bots 20` 会被换成 5；
  - 数字和画像名没有校验；
  - 重复写 `--set` 只取最后一个；
  - 用法提示里没写 `fast`；
  - 线程正常退出但没发回结果时会卡住；
  - fast 模式也要求环境里有 `REDIS_URL`。
- `docs/sim-fast.md`：
  - 没说明 `--seed` 不改变天气、菜场、老鼠、痞老板和体力恢复；
  - 没写 `--start`；
  - 卡点原因里的 `level` 现在不会出现。
