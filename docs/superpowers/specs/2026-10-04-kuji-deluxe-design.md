# 豪华一番赏 设计（货币回收 240-2 第二项）

- 日期：2026-10-04
- 来源：问题记录 240——“一番赏奖券（非常高价，超出其本身价值，主要为了让他们抽出来某个赏被播报装逼）”。
- 用户已定（2026-10-04）：
  - 小池：每池 20 张签，每张 30 万银币；
  - 奖品以面子为主，一池返还的价值约为券价的 30%；
  - 下面五节的规则、奖品、数据、页面、测试；
  - A 赏、最后赏的称号按月轮换（用户在设计审阅时追加）。
- 依据：普通一番赏的设计 `docs/superpowers/specs/2026-10-02-kuji-design.md`。豪华池沿用它的全部规则，只列不同的地方。
- 不涉及菜园。

## 1. 玩法规则

- 每个区服每天一条豪华奖池线，和普通池并行、互不影响。规则和普通池相同：抽完开下一池，当天 24 点没抽完的池作废，没抽到的大赏一起作废。
- 豪华签券是单独的道具（90202），只能在一番赏页用银币买。默认每张 30 万，每人每天限购 10 张，一次最多抽 10 张，每个区服每天最多开 3 池。
- 每池 20 张签；抽走最后一张的人另得最后赏。
- 活跃度送券只送普通券，不送豪华券。
- 豪华池不跟普通池的月度主题和手办；它有自己的按月轮换称号（见第 2 节）。

## 2. 奖品（默认值，写在区服数值里）

| 档 | 张数 | 奖品 | 播报 |
|---|---|---|---|
| A 赏 | 1 | 限定称号“豪华一番赏 A 赏得主”（`kuji_dx_a`） + 50 钻石 | 全服广播 |
| B 赏 | 2 | 30 万银币 | 小镇新闻 |
| C 赏 | 5 | 10 万银币 | — |
| D 赏 | 12 | 5 万银币 | — |
| 最后赏 | 抽走最后一张的人 | 限定称号“豪华一番赏最后赏得主”（`kuji_dx_last`） + 50 钻石 | 全服广播 |

一池券价合计 600 万，返还银币 170 万（约 28%），另有 100 钻石和两个称号。差额约 430 万就是回收掉的银币。

### 2.1 称号按月轮换

- 每个月的 A 赏、最后赏发当月的限定称号，按游戏日期的年月（如 `2026-10`）取，不是按 1~12 月循环：每个称号只属于那一个月，攒得越多越有面子。
- 配置写在 `kuji.json` 的 `deluxeMonths`：每项是一个年月和“档位 key → 称号”的对照，比如 `{ "month": "2026-10", "icons": { "A": "kuji_dx_2610_a", "last": "kuji_dx_2610_last" } }`。对照里只能写 `deluxe` 的档位 key 或 `last`。
- 开池时按当月的对照替换这些档的称号，再把奖品快照存进奖池（和普通池存主题的方式一样），之后改配置不影响这一池。
- 哪个月没写，就用区服数值里的称号（上表的 `kuji_dx_a`、`kuji_dx_last`），忘了配置也不会出错。
- 银币、钻石不跟着变；不做手办。
- 首批：

  | 月份 | A 赏 | 最后赏 |
  |---|---|---|
  | 2026-10 | `kuji_dx_2610_a`“金秋鸿运” | `kuji_dx_2610_last`“金秋压轴” |
  | 2026-11 | `kuji_dx_2611_a`“初冬鸿运” | `kuji_dx_2611_last`“初冬压轴” |

  说明写明是哪年哪月豪华一番赏的 A 赏或最后赏得主。以后每月上新，和称号商店一样改配置合并即可。

## 3. 数据和接口

### 3.1 区服数值

`tuning.kuji` 下加一组 `deluxe`：

```
deluxe: {
  price: 300000,
  dailyBuy: 10,
  maxDraw: 10,
  maxPools: 3,
  tiers: [A, B, C, D],   // 和普通池同样的结构：key、count、award、icon、news
  last: { award, icon, news }
}
```

- 校验和普通池共用 `kujiErrors`：档位 key 不重复、不能叫 `last`，引用的道具、食材、称号存在，一池总张数不超过 1000。错误信息里写 `tuning.kuji.deluxe...`，区分是哪条线。
- `setting_docs.json` 为新字段写说明（漏写配置构建失败）。

### 3.2 道具和称号

- 道具 90202“豪华签券”：写在 `kuji.json`，和普通券同一种生成方式，不出售、不能卖。
- 称号 `kuji_dx_a`、`kuji_dx_last` 和每月轮换的称号都写进 `looks.json`，不带 `shop`。
- `kuji.json` 的 `deluxeMonths`：构建时检查年月格式、不重复，引用的称号存在于 `looks.icons`，对照的 key 是 `deluxe` 的档位或 `last`。
- 道具和称号都写简中、英、法、西；繁中自动生成。

### 3.3 数据库（迁移 0044）

- `kuji_pool` 加列 `line text not null default 'normal' check (line in ('normal', 'deluxe'))`。
- 唯一约束 `(shard_id, day, seq)` 改成 `(shard_id, line, day, seq)`。
- 按区服查进行中的池的索引带上 `line`。
- 现有的池都是 `normal`。

### 3.4 服务端

- 开池、找当前池、作废过期池、按天编号、每天最多开几池，都按 `line` 分开；区服的开池锁也按线分开。
- 买券、抽签用对应线的价格、限购、券道具；每日限购的计数键分线。
- 开豪华池时按当月的 `deluxeMonths` 替换称号再存快照（2.1）。
- 发奖、最后赏、称号、播报流程不变。新闻参数多一个 `line: 'deluxe'`；普通池不写，和以前一样。
- 接口沿用现有三个：
  - `GET /kuji?line=deluxe`
  - `POST /kuji/buy { num, line }`
  - `POST /kuji/draw { num, line }`

  `line` 可选，默认 `normal`，旧前端不受影响。

### 3.5 页面

- 一番赏页顶部加“普通 / 豪华”两个切换，记在网址参数里，刷新后保持。
- 豪华这边的看板和普通的一样：剩余张数、各档剩几张、买券、抽签。没有月度主题和手办展示。
- `kuji.big`、`kuji.win` 两种新闻：`line` 是 `deluxe` 时写“豪华一番赏”。

## 4. 不做

- 豪华池的月度主题、手办；
- 活跃度送豪华券；
- 豪华券的其他获取途径（兑换码、邮件附件照常能发，后台可以选到这个道具）。

## 5. 测试

- **配置：** 真实数据带豪华配置和十月、十一月的轮换称号；豪华档位重复 key、引用不存在的称号会报错，错误信息写明是 `deluxe`；`deluxeMonths` 年月重复、称号不存在、key 不是豪华档位时报错。
- **迁移 0044：** 现有的池都是 `normal`；同一天两条线可以各有第 1 池。
- **服务端：**
  - 豪华池独立开池、编号，不影响普通池；
  - 买豪华券扣 30 万、受豪华的每日限购，和普通券的限购互不影响；
  - 豪华池只能用豪华券抽；
  - 抽走最后一张发最后赏和称号；A 赏、最后赏全服广播，新闻带 `line: 'deluxe'`；
  - 当天没抽完的豪华池第二天作废；
  - 十月开的豪华池，A 赏、最后赏发十月的称号；没有配置的月份发固定称号；
  - 不传 `line` 时和以前完全一样。
- **前端：** 切换到豪华时请求带 `line=deluxe`、看板显示豪华池；新闻里豪华的写“豪华一番赏”。
