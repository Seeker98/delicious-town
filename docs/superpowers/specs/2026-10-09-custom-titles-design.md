# 定制称号（后台新建、邮件和兑换码发放，2026-10-09）

问题记录 539：“需要一个发限定称号/个性图标的系统”。分析后用户 2026-10-09 定的：

1. **新称号在后台直接新建**：以后大量是给玩家的定制称号，不走配置和部署；
2. **发放**：定制的发邮件，可以一次发给一家或几家店，邮件里能新建称号也能选已有的；广泛发的走兑换码；
3. **永久和限时都支持**，限时有“领取后 N 天”和“到某个时间”两种；
4. **不发小镇新闻**，邮件本身就是通知；
5. **暂时不配图**，记进 backlog；
6. **称号文字支持 emoji**，名字最多 10 个字、说明最多 30 个字；
7. **样式统一成访问好友页那种黄底徽章**，首页也改（推翻问题记录 198 改的浅色描边）；
8. **繁中不转换**：定制称号在所有语言里都照原样显示。

“个性图标”和“称号”在代码里是同一个东西（`rest_icon`、`looks.icons`），下面统一叫称号。

## 一、现状

- 配置称号 23 个（`game/looks.json` + `i18n/*/icons.json`）：通用、称号商店、一番赏、发展基金。都有名字（title）和说明（desc），没有图。
- 来源：称号商店（永久）、一番赏 A 赏和最后赏（永久）、发展基金（限时）、后台玩家页单店发放（只能永久）。
- 显示：首页自己的展示中称号（`.dt-icon-tag` 浅色描边）、访问好友页（`badge bg-warning text-dark`）、装扮页“我的称号”（带说明、到期时间）。最多同时展示 5 个。
- 附件（邮件、兑换码、活动奖励共用 `rewardItems` + `grantRewardOp`）：银币、钻石、经验、道具、食材、命名帽子，没有称号。

## 二、定制称号

### 存储

新表 `custom_icon`（迁移 0062）：

| 列 | 说明 |
| --- | --- |
| id | 自增主键 |
| title | 名字，1~10 个字 |
| descr | 说明，可空，最多 30 个字 |
| note | 后台备注（给谁、为什么），只有后台看，最多 100 字，可空 |
| retired | 停用，默认 false |
| created_by / created_at / updated_at | 谁建的、时间 |

- 称号键：定制称号在 `rest_icon.icon_key`、附件里写成 `c<id>`（如 `c12`）。配置构建加检查：配置称号的 key 不能是 `c` 加数字。
- 不做内存缓存（API 有多个副本、worker 也在用），按 id 查，主键查询很便宜。

### 文字规则（名字、说明、备注共用）

- 去掉首尾空白；去掉控制字符、换行、零宽空格（U+200B、U+FEFF）、方向控制字符（U+202A~202E、U+2066~2069）；**保留** emoji 要用的零宽连接符（U+200D）和变体选择符（U+FE0F）。
- 长度按“看上去的字”数（`Intl.Segmenter` 按字素切分），👨‍🍳 算 1 个。前后端用同一个函数（放 shared）。
- 名字去完以后不能为空；和已有称号（配置或定制、没停用的）重名时，后台提示但允许。

### 改、停用、删

- **改**：名字、说明、备注都能改，已经拥有的人看到的也跟着变（用于改错字）。已经发出去的邮件、兑换码里的附件摘要显示发送时的名字（见四）。
- **停用**：不在发放的下拉里出现，已拥有的人照样保留；已经发出的邮件、兑换码照样能领。可以再启用。
- **删**：只有没人拥有、也没有任何邮件或兑换码附件引用时才能删（查 `rest_icon` 和 `mail.items`、`redeem_code.items` 里的 `icons`）；否则提示改用停用。

### 后台“称号”页（新）

- 列出所有称号：定制的在上面（名字、说明、备注、拥有人数、停用状态、建的人和时间），配置的在下面只读（名字、说明、来源：商店/一番赏/基金/通用、拥有人数）。
- 能按名字、备注搜。
- 新建、改、停用/启用、删。写审计。
- 只有管理员能建、改、删；运营能看。

## 三、发放

### 附件里的称号

`rewardItems` 加一项 `icons`，最多 5 个：

```ts
icons?: Array<{
  key: string;            // 配置 key 或 c<id>
  title: string;          // 发送时的名字快照，服务端按 key 重新填，不信前端
  days?: number;          // 领取后 N 天（1~3650）
  until?: string;         // 到某个时间（ISO），和 days 二选一；都不填是永久
}>
```

- 发送邮件、建兑换码时检查：key 存在、没停用、不重复；`until` 必须晚于现在。
- **活动奖励不支持称号**（活动的奖励 schema 拒绝 `icons`），后台活动编辑器也不显示这一栏（和命名帽子一样）。补偿（`admin_grant`）也不支持，补偿页不变。

### 领取规则（邮件、兑换码、后台玩家页直接发、一番赏共用一个函数）

新的到期时间：`days` → 现在 + N 天；`until` → 那个时间；都没有 → 永久。

| 已有的 | 这次发的 | 结果 |
| --- | --- | --- |
| 没有，或已过期 | 任意 | 按这次的写入；`granted_at` 更新 |
| 永久 | 任意 | 不变 |
| 限时 | 永久 | 变永久 |
| 限时 | 限时 | 取两个到期时间里晚的那个 |

- `until` 在领取时已经过了：这个称号跳过，同一封邮件、同一个码里别的东西照发；领取结果里标出“已过期”。
- **新拿到时自动展示**：展示中的不满 5 个就自动展示（和发展基金一样），满了就不展示。续期、变永久不改展示状态。
- 一番赏原来用 `doNothing`：改用这个函数（发永久），修掉“后台先发了限时的一番赏称号，再抽中时还是限时”的问题。
- 发展基金的“先删掉别的基金称号、替换到期时间”是它自己的规则，不动。

### 邮件

- 后台邮件页的“单家餐厅”改成**一家或几家餐厅**：填多个餐厅 id（最多 50 个，逗号或空格分开），每个 id 后面显示店名、店主（沿用现在的查询），有查不到或不在当前区服的就不能发。
- 发的时候给每家店各写一封“单店邮件”（同一个事务），收件人互相看不到；邮件列表里一家一行。审计记一条，带全部店 id。
- 附件编辑器加“称号”一栏（邮件页和兑换码页开，其他地方不开）：
  - 下拉选已有的（定制的在前，配置的分组在后；停用的不出现），可搜索；
  - 旁边“新建称号”：填名字、说明、备注，**点保存就建好**并选中（不等发信）；没用上的可以在称号页删；
  - 每行选有效期：永久 / 领取后 N 天 / 到某个时间。
- 区服、全部区服两种范围也能带称号（就是一般的附件）。

### 兑换码

- 共享码、一次性批量码都能带称号，规则同上。
- 后台兑换码页提示：共享码可以被转发，只想给特定的人用一次性码。
- “到某个时间”早于兑换码截止时间时，后台提示（码还能兑、称号已经过期，领取时会跳过）。

### 后台玩家页（原来的单店发放）

- 保留，改成能选定制称号，加有效期（永久 / N 天 / 到某个时间），走上面的领取规则（修掉现在重发时总是改回永久的问题）。不发邮件、玩家没有通知。

## 四、玩家看到的

- **邮件、兑换结果的附件摘要**：`称号「金牌大厨」`，限时的后面加 ` (领取后 7 天)` 或 ` (到 10-31 23:59)`。配置称号用当前语言的名字，定制称号用快照里的名字。五种语言都加文案。
- **领取后**：和现在一样进“我的称号”，不满 5 个就已经在展示。领取结果里过期跳过的写“称号「X」已过期”。
- **名字、说明**：定制称号在所有语言里显示原文（不转繁体、不翻译）。服务端返回称号的地方（首页、访问页、装扮页、后台）把定制称号的名字、说明一起带上；前端现在就是“配置里有就用配置的，没有就用服务端给的”，不用改。
- **样式**：新建一个称号徽章组件，用访问好友页的样式（`badge bg-warning text-dark`），首页和访问页都用它；删掉 `.dt-icon-tag`。装扮页的列表样式不变。

## 五、接口

| 接口 | 说明 |
| --- | --- |
| `GET /admin/titles?q=` | 称号列表（定制 + 配置），带拥有人数 |
| `POST /admin/titles` | 新建定制称号，返回 `{ key, title, ... }` |
| `PATCH /admin/titles/:id` | 改名字、说明、备注、停用 |
| `DELETE /admin/titles/:id` | 删（有人拥有或被引用时报错） |
| `POST /admin/mails` | `scope: 'rest'` 时可以传 `restIds`（1~50）代替 `restId` |
| `POST /admin/restaurants/:id/icons` | 加 `days` / `until` |

## 六、测试

- **文字规则**：emoji（含 👨‍🍳、国旗）按 1 个字算；10 个字通过、11 个拒绝；方向控制字符、零宽空格被去掉；保留 ZWJ；去完是空的拒绝；换行拒绝。
- **领取规则**：表里每一行；`until` 已过跳过、别的照发；自动展示满 5 个不展示；续期不改展示状态。
- **一番赏**：已有限时的同一称号，抽中后变永久。
- **邮件**：多家店各一封、收件人互相看不到；有一家不在区服整个拒绝；附件里称号不存在、停用、重复、`until` 已过都拒绝；名字快照由服务端填。
- **兑换码**：共享码带限时称号，两家店各自从领取时起算。
- **定制称号**：改名后首页、访问页、装扮页显示新名字；删有人拥有或被邮件引用的报错；停用后下拉里没有、旧邮件照样能领。
- **活动**：奖励里带称号被拒绝。
- **配置构建**：key 是 `c12` 这样的报错。
- **网页**：附件编辑器选称号、新建称号、三种有效期；多店 id 输入；徽章组件在首页和访问页；附件摘要五种语言。
- **迁移**：建表、回退删表。
