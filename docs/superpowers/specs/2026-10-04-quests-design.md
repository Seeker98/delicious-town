# 主线、支线、每周任务和活跃度重新设计（问题记录 318）

## 1. 目标

用任务把游戏里的各个玩法串起来，覆盖四件事（用户确认）：

- **新手引导**：主线按解锁顺序把玩法一个个带出来，每步说清去哪做。
- **中后期目标**：等级、星级高了以后，主线和支线仍有可做的目标，串起新街道、交易所、事件合约、一番赏、限时活动等新玩法。
- **每日循环**：活跃度覆盖新玩法，每天有一组合理的事做。
- **玩法互相带动**：支线中段和每周任务把几种玩法放在一起。

## 2. 用户确认的裁定

1. **结构**：章节主线 + 玩法支线。主线分章节，按等级或星级解锁，章末有大奖；主线引出某个玩法后，开启这个玩法的支线。
2. **每日**：原游戏的活跃度 24 项保留，补上新玩法，重新排档位；另加一层每周任务。
3. **老号**：按当前状态，已达成的任务直接算完成，奖励可以领；当前章节之前的章节只发章末大奖。
4. **奖励**：主线、支线奖励总量和现在差不多，按章节和难度重新分配；每周任务另给一份不大的奖励，先上线再调。

## 3. 现状

| 部分 | 现状 |
|---|---|
| 主线 | 46 步，必须按顺序一步步做（`restaurant.main_task_step`）；前 31 步是"每个系统点一下"，后面是数量门槛 |
| 支线 | 22 个，主线到第 N 步后出现（`task_done` 记完成） |
| 活跃度 | 原游戏 24 项，满分 170；档位 50 / 100 / 120 / 150 |
| 计数 | 动作事件 → `event_counter`（全历史）+ 活跃度按天计数；状态条件现算（等级、星级、已学食谱、各品级数等） |
| 新玩法 | 交易所、事件合约、一番赏、限时活动、搬家、论坛回复都没有发动作事件，任务和活跃度用不上 |

现在的奖励总量：
- 主线：银币 1,149.5 万、经验 114.95 万，外加若干道具；
- 支线：银币 8.3 万、经验 1.2 万，外加若干道具。

  - 当前章没做完，后面的章不出现。

  - 档位按顺序推进，后面的档可能要求更高的等级或星级，不满足时显示"X 星解锁"。
- **奖励**：大多沿用现在支线和主线中段的道具，银币按难度给。

## 6. 每周任务

- **刷新**：每周一 0 点（游戏时间）刷新。
- **怎么分组**：按领取时的星级给一组 4 个任务，进度从本周一起算。

| 组 | 星级 | 任务（每个奖励） |
|---|---|---|
| A | 0 星 | 签到 5 天 · 菜场买菜 10 次 · 学习或升级食谱 10 次 · 合成或分解 5 次 |
| B | 1~2 星 | 探险 10 次 · 烹制特色菜 5 次 · 厨塔挑战 20 次 · 学习或升级食谱 20 次 |
| C | 3 星起 | 配送外卖 10 次 · 交易所成交 3 次 · 探险 20 次 · 学习或升级食谱 30 次 |

- **奖励**：
  - 每个任务：钻石 5 + 神秘礼券×10；
  - 4 个全部完成再给一份：A 组探险图×1，B 组厨塔挑战券×2，C 组一番赏抽赏券×1。
- **跨组**：一周之内星级变了，已经领过的不变，没领的按领取时所在的组计算。

## 7. 活跃度

- **保留**：原来的 24 项全部保留。
- **新增 5 项**（新的设计数据文件，构建时和原始数据合并）：

| 项目 | 分值 × 每日次数 |
|---|---|
| 交易所成交 | 5 × 1 |
| 事件合约交易 | 5 × 1 |
| 一番赏抽赏 | 5 × 1 |
| 领取限时活动奖励 | 5 × 1 |
| 论坛发帖或回复 | 3 × 1 |

- **满分和档位**：满分从 170 变成 193。档位 50 / 100 / 120 / 150 不变，新增 180 档：神秘礼券×10。

## 8. 新的动作事件

| 动作键 | 什么时候发 |
|---|---|
| `exchange.fill` | 交易所成交（买卖双方各一次；卖给系统也算） |
| `predict.trade` | 事件合约买入或卖出一次 |
| `predict.win` | 事件合约判定后，持有押中一方的结算到账 |
| `kuji.draw` | 一番赏每抽一张（`n` = 张数） |
| `kuji.last` | 拿到最后赏 |
| `activity.claim` | 领取一次限时活动奖励 |
| `rest.move` | 搬家 |
| `post.reply` | 论坛回复 |
| `bar.darts` / `bar.memory` / `tower.rank` | 已有，补进活跃度映射之外的任务 |

新的状态条件：
- `cookbooks.foreignLearned`：14~29 号街已学数之和；
- `cookbooks.grade10`：已有的 `cookbooks.gradeN` 写法，覆盖到 10。

## 9. 数据和计数

- **配置**（`designed/` 下新文件，替换 `designed/tasks.json`）：
  - `quest_chapters.json`：章（id、名称、解锁等级/星级、章末奖励）；
  - `quest_main.json`：主线任务（id、章、顺序、名称、条件、奖励、链接）；
  - `quest_lines.json`：支线（key、名称、开启章、功能）和档位（id、支线、顺序、需要星级、名称、条件、奖励、链接）；
  - `quest_weekly.json`：每周任务分组和全完成奖励；
  - `activation_extra.json`：新增的活跃度项目和 180 档奖励。
- **任务 id**：新任务 id 从 2001 起，避免和老的 `task_done` 记录混淆。
- **"全部"门槛**：沿用 `"all"` 写法。
- **数据库**（新迁移）：
  - `quest_done`：店、任务 id、完成时间。主线、支线通用；章末奖励用"章 id + 100000"记。
  - `weekly_counter`：店、周（周一日期）、动作键、次数。
  - `weekly_claim`：店、周、任务 id。
  - `restaurant.quest_version`：老号换算标记。
- **换算老号**（第一次打开任务时，在同一个事务里做）：
  1. 从第 1 章往后，整章任务都已达成的章，把这些任务记为已完成、不发奖励，章末奖励留着可领；
  2. 遇到第一个有任务没达成的章，它就是当前章，章内已达成的任务照常可领；
  3. 支线按当前档位往后看，已达成的档照常可领；
  4. 写 `quest_version = 1`。
  - 老的 `main_task_step` 和 `task_done` 不再使用，保留不删。
- **翻译**：章名、主线、支线、每周任务的名字进英、法、西翻译数据（任务翻译已有 `tasks` 一类，章名新增 `chapters` 一类），繁中自动转换。

## 10. 界面

- **任务页（`/rest/tasks`）**分成四块：
  - **主线**：当前章名、进度"3/6"，本章任务列表（可领的在前），章末奖励按钮；
  - **支线**：各支线的当前一档；
  - **每周**：本周 4 个任务、进度、剩余时间、全完成奖励；
  - **活跃度**：和现在一样。
- **首页"今日待办"的主线行**：显示当前章里第一个可领的任务；没有可领的时，显示第一个没完成的任务。
- **新手指引页**：说明主线分章节。

## 12. 测试要点

- 构建：
  - 章、任务、支线、每周的引用都存在；
  - 任务 id 不重复；
  - "all" 能换算；
  - 每个条件键都有来源，即动作键在动作映射里，或状态键能算出来。
- 主线：
  - 同章任务不分先后都能领；
  - 全领完才能领章末；
  - 等级或星级不够时下一章不出现。
- 支线：一次只显示一档；档位要求星级时显示锁定原因。
- 每周：
  - 计数只算本周；
  - 跨周清零；
  - 按领取时的星级分组；
  - 全完成奖励只能领一次。
- 老号换算：
  - 整章已达成的章只能领章末；
  - 当前章已达成的照常领；
  - 换算只做一次。
- 新动作事件：交易所成交、事件合约交易和押中、一番赏抽和最后赏、活动领奖、搬家、论坛回复，都会让计数和活跃度增加。
