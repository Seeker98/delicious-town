# 食材理财 设计

- 日期：2026-10-10
- 来源：用户 2026-10-10 提出的“金融化”新食材来源。顺序：① 食材期货（PR #255，已合并）→ ② 食材理财（本文）→ ③ 供应商竞价众筹（以后）。
- 用户已定：
  - 锁银币 N 天，到期本金全退，利息发“街市补给包”；开包时按**开包时所在街道**挑食材，不按存入或领到时的街道。
  - 产品形式：自选金额（100 万一档）和期限（3 / 7 / 14 天），期限越长包的等级越高。
  - 每个包给 1 个食材；一到五级各一个道具，默认只用三~五级。
  - 名字：「N 级街市补给包」。
  - 可以提前取出：退 95% 本金、没有利息。
  - 到期自己点“领取”，仓库放不下时报错。
  - 20 级才能存。放在“发展基金”旁边。
  - 缺料的口径和缺料倾向一样，只算“下一品级”。
- 不碰菜园。

## 1. 玩法

- 协会页“发展基金”下面加一个入口“理财”（`/society/wealth`），和发展基金是同一位 NPC（盖乐瑞），台词换成讲理财的。
- 存入：
  - 选期限：3 天、7 天、14 天。
  - 填金额：100 万的整数倍。
- 利息：每 100 万给 1 个街市补给包。等级按期限定：

  | 期限 | 每 100 万的利息 | 价值（系统价中位，普通 / 稀有） | 折合每天（按稀有） |
  |---|---|---|---|
  | 3 天 | 1 个三级街市补给包 | 7,200 / 8,400 | 0.28% |
  | 7 天 | 1 个四级街市补给包 | 14,400 / 16,200 | 0.23% |
  | 14 天 | 1 个五级街市补给包 | 30,000 / 43,200 | 0.31% |

- 额度：
  - 同时最多 3 笔存着；
  - 存着的本金合计不超过 1,000 万。
- 到期：点这一笔的“领取”，本金全退，补给包进仓库。到期不领就一直留着，什么都不会丢。
- 提前取出：退 95% 本金，没有补给包。到期后不能提前取出，只能领取。
- 门槛：20 级。没到时页面写明，存入按钮不能点。

### 1.1 街市补给包

- 新道具 10211~10215：一级~五级街市补给包。编号 = 10210 + 等级，放在“食材随机券”小类里，接在 10210 后面。
- 使用后得到 1 个**本街正缺的** N 级食材：
  - 缺料清单就是缺料倾向用的那份（缺料设计 §3.1）：使用时所在街道的每道菜，取下一品级要的食材合计，减去橱柜里已有的；满级的菜不算。
  - 在清单里 N 级的食材中，按缺口大小加权抽。
  - 一次用多个时，每抽到一个就从缺口里扣 1，缺口扣完的不再抽。这样不会把只缺 1 个的食材一次给 5 个。
  - 本街不缺 N 级食材（或者都扣完了）时，和 N 级食材随机券一样，在 N 级食材里按掉落权重抽。
- 和随机食材券一样：
  - 能批量使用；
  - 卖店价 0，不能卖店；
  - 不在商店卖。
- 道具说明（简中）：“使用后获得 1 个本街正缺的三级食材（按使用时所在街道）；本街不缺三级食材时随机给一个三级食材”。

## 2. 数值评估

按存满 1,000 万算，和现有来源比：

- **只存 3 天期**：每天约 3.3 个三级。菜场特价货架每天约 0.21 个某种三级稀有（稀有食材供给分析 §2）。
- **只存 14 天期**：每天约 0.7 个五级。菜场每天约 0.16 个。
- **期货**：每天最多 50 份，要花银币买；理财白拿，但量只有期货的零头。

谁能存多少（快速模拟）：

- 勤快玩家第 90 天约有 440 万，能存 400 万，3 天期每 3 天拿 4 个三级。
- 长期玩家手上 2,000 万以上，被 1,000 万的上限挡住，不会越有钱拿得越多。

套利：

- 补给包里的稀有食材能卖给交易所系统收购（参考价的七成，每人每天 20 份）。存满时，每天最多变出约 2 万银币。结算每天是 20~70 万，这点可以忽略。
- 期货要花钱，补给包白拿，两者之间没有套利。
- 补给包本身不能卖店。

和发展基金的关系：

- 基金退 90% 本金，给经验勋章；理财退 100%，给食材。
- 两样能同时存。会有人从基金转到理财，基金回收的银币会少一些。

## 3. 数据和接口

### 3.1 配置

- 道具主表 `data/master/goods.json` 加 10211~10215：
  - `src: "wealth"`（新来历）、`group: "foodVoucher"`；
  - `type` 0、`coin` 0、`onSale: false`、`stackable: true`、`maxNum` 9999；
  - `use: { "kind": "needFood", "level": N }`。
- `raw.ts` 的 `use` 加 `needFood` 一种，等级 1~5。
- 构建检查：`needFood` 的等级里要有能抽的食材（和 `randomFood` 一样）。
- 英、法、西三种语言的道具名和说明写在 `data/i18n/*/goods.json`。
- 区服数值 `tuning.wealth`：

  ```
  wealth: {
    minLevel: 20,          // 几级能存
    unit: 1000000,         // 一档的金额；存入金额是它的整数倍，每档给 perUnit 个包
    maxActive: 3,          // 同时存着的笔数上限
    maxTotal: 10000000,    // 存着的本金合计上限
    earlyRate: 0.95,       // 提前取出退回的比例
    terms: [
      { days: 3,  goods: 10213, perUnit: 1 },
      { days: 7,  goods: 10214, perUnit: 1 },
      { days: 14, goods: 10215, perUnit: 1 }
    ]
  }
  ```

- 检查（构建和后台保存区服数值都跑）：
  - `unit ≥ 1`，`maxTotal ≥ unit`，`maxActive ≥ 1`，`minLevel ≥ 1`；
  - `0 < earlyRate ≤ 1`；
  - `terms` 至少一项，`days ≥ 1`，同一个 `days` 不重复；`perUnit ≥ 1`；
  - `goods` 必须是 `needFood` 道具。
- `setting_docs.json` 写说明（组 `tuning.wealth`，每个字段一条）。
- 区服功能开关加 `wealth`，默认开；`action_map.json` 加 `"wealth.": "wealth"`。关掉时接口报“功能关闭”，协会页不显示入口。

### 3.2 数据库（迁移 0064）

`wealth_deposit` 表：

| 列 | 说明 |
|---|---|
| `id` | 主键 |
| `shard_id`、`rest_id` | 哪家店（删店时一起删） |
| `coin` | 存入的银币 |
| `days` | 期限 |
| `goods_id`、`packs` | 到期给的补给包和个数，存入时按 `coin ÷ unit × perUnit` 算好写进来 |
| `started_at`、`matures_at` | 存入、到期时间 |
| `status` | `active` 存着 / `claimed` 已领 / `withdrawn` 已提前取出 |
| `settled_at`、`returned` | 领取或取出的时间、退回的银币 |

- 索引 `(rest_id) where status = 'active'`。
- 笔数和合计上限在 `runOp` 里检查。`runOp` 锁住店铺这一行，同一家店两个请求同时存入时会排队，不会一起超过上限。
- 期限、补给包、个数按存入时写进来，之后改区服数值不影响已有的存款。提前取出的比例按取出时的区服数值算（和基金一样）。

### 3.3 服务端

- 新模块 `modules/wealth`，全部操作走 `runOp`，功能开关 `wealth`：
  - `GET /wealth`：
    - 数值（门槛、一档金额、笔数和合计上限、提前取出比例、各期限的天数、补给包、每档个数）；
    - 我存着的各笔（金额、期限、补给包和个数、存入和到期时间、是否到期、提前取出能退多少）；
    - 我的等级、银币。
  - `POST /wealth/deposit { days, coin }`：
    - 等级不够报 `wealth_level`（带 `need`）；
    - `days` 不在期限里报 `bad_term`；
    - `coin` 不是 `unit` 的正整数倍时报 `VALIDATION_FAILED`；
    - 已有 `maxActive` 笔报 `limitReached('wealth_count', { max })`；
    - 合计超过 `maxTotal` 报 `limitReached('wealth_total', { max, left })`；
    - 扣银币，不够报 `NOT_ENOUGH`，什么都不扣；
    - 写存款。
  - `POST /wealth/:id/claim`：
    - 不是自己的或者不存在报 `wealth_none`；
    - 不是 `active` 报 `wealth_none`（领过、取出过）；
    - 没到期报 `wealth_not_mature`；
    - 退回全部本金，发补给包。仓库放不下时整笔回滚，报 `store_full`（同一番赏买券）；
    - 状态改成 `claimed`。
  - `POST /wealth/:id/withdraw`：
    - 不存在、不是自己的、不是 `active` 报 `wealth_none`；
    - 已到期报 `wealth_mature`（要走领取）；
    - 退回 `floor(coin × earlyRate)`（和基金同一个取整方法）；
    - 状态改成 `withdrawn`。
- 流水和日志来源：`wealth.deposit`、`wealth.claim`、`wealth.withdraw`。
- 补给包的使用写在 `store/use.ts`，新加 `needFood` 一种：
  - 缺料清单用 `core/scarcity.ts` 的 `needMapOf` 算，抽成一个函数和缺料倾向共用；
  - 按 §1.1 的规则抽（等级过滤、按缺口加权、抽一个扣一个、没有就按掉落权重抽）。
- 首页待办要用的“已到期的理财笔数”：餐厅概览加 `wealthDue`（到期没领的笔数）。功能关闭时为 0。

### 3.4 页面

- 协会页：“发展基金”下面加“理财”入口，区服关掉时不显示。说明写“锁银币几天，到期领回本金，再拿本街缺的食材”。
- 理财页（`/society/wealth`）：盖乐瑞的 NPC 卡片，头像、名字同发展基金页，台词另写三句讲理财。
  - 规则说明（折叠）：期限和对应的补给包、每 100 万给几个、额度、提前取出的比例、补给包按开包时的街道挑食材。
  - 存入框：
    - 期限三选一（写天数和“每 100 万得 1 个三级街市补给包”）；
    - 金额输入框，以 100 万为单位，写还能存多少；
    - 写明到期时间和到期能拿几个包；
    - 钱不够、额度满了、等级不够时按钮禁用并写明原因；
    - 点了弹确认框。
  - 我存着的：每笔写金额、期限、补给包和个数、到期时间或倒计时。
    - 到期了显示“领取”；
    - 没到期显示“提前取出（退 95%，没有利息）”，点了弹确认框。
- 首页待办：有到期没领的理财时多一行“理财到期 N 笔”，链接到理财页。旧服务端没有这个字段时不显示。
- 道具页的补给包：照普通可用道具显示，“使用”后提示拿到了什么。
- 文案写简中、英、法、西，繁中自动生成。玩家能看到，所以加一条更新记录（五种语言）。

## 4. 不做

- 自动到期发放、邮件补发；
- 新闻、广播；
- 后台专门页面：数值都在区服数值页里改；
- 快速模拟的机器人存理财；
- 一、二级的期限：道具先做好，需要时在区服数值里加期限就能用。

## 5. 测试

- **配置：**
  - 真实数据的三个期限、五个补给包；
  - 期限重复、`goods` 不是补给包、比例越界、`maxTotal < unit` 时报错。
- **迁移：** 表能建，删店时一起删。
- **补给包（服务端）：**
  - 只抽本街、下一品级缺的、对应等级的食材；
  - 别的街的菜要的食材不抽；满级的菜不算；
  - 按缺口加权：缺口大的抽中多（固定随机数）；
  - 一次用多个时抽一个扣一个：只缺 1 个的食材，用 5 个包最多拿到 1 个；
  - 本街不缺这一级时按掉落权重随机给；
  - 搬家后用，按新街道挑。
- **理财（服务端）：**
  - 存入扣钱、写存款，补给包个数按金额算；
  - 银币不够什么都不扣；
  - 等级不够、期限不对、金额不是整数倍时报错；
  - 第 4 笔、合计超过 1,000 万时报错，`left` 对；
  - 两个请求同时存入，不会一起超过上限；
  - 领取：没到期不能领；到期退全部本金、发补给包；不能重复领；
  - 仓库放不下时整笔回滚，银币和存款都不变；
  - 提前取出：退 95%、没有补给包；到期后不能提前取出；
  - 不能领、取别人的；
  - 改区服的期限、补给包后，已有存款不变；
  - 功能关闭时报功能关闭；
  - 餐厅概览的 `wealthDue`。
- **前端：**
  - 理财页：没存、存着没到期、已到期三种状态；
  - 金额输入（空、0、不是整数倍、超额度）时按钮禁用；
  - 确认框；
  - 首页待办行；
  - 协会页入口按功能开关显示。
