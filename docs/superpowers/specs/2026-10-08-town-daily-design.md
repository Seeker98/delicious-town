# 小镇日报（AI 写稿，2026-10-08）

用户 2026-10-08 提的：用 DeepSeek V4.1 Flash 每天给每个区服写一份前一天的“小镇日报”。方案草案看过后，用户定了四条：

1. **语言**：AI 只写简中和英文；
2. **上线**：先人工审核再放出来，以后改成自动发布；
3. **点名**：直接写店名；
4. **入口**：小镇页放日报，首页也加一个入口。

## 一、玩家看到什么

- **小镇页“新闻”标签最上面**：一张日报卡片，内容是标题、正文（3~5 段）和日期。
  - 可以往前翻 7 天。
  - 文中的店名可以点，进那家店的页面（`/friends/:restId`）。
- **首页新闻卡片第一行**：“📰 小镇日报: <标题>”，点了去小镇页的新闻标签。
  - 只有昨天的日报已经发布时才显示这一行。
- **各语言显示哪一版**：

| 玩家的语言 | 显示 |
| --- | --- |
| 简中 | AI 写的简中 |
| 英文 | 简中由 AI 翻成英文 |
| 繁中 | 简中经 OpenCC 转成繁中，和界面文字的生成方式一样，不花钱 |
| 西语、法语 | 英文版，标题旁写一行小字“仅英文”（这行用各自语言） |

- **还没发布时**（人工审核期间，或者 AI 失败）：卡片显示“今日要闻”，直接列出挑出来的 5 条新闻，用现有新闻文案，各语言都正常。
  - 首页不显示这一行。

## 二、素材（不用 AI）

**取哪一天**：区服前一个游戏日 00:00~24:00 的新闻。新闻表保留 30 天。

**挑什么**

| 类别 | 新闻类型 | 怎么用 |
| --- | --- | --- |
| 大事（权重高） | 一番赏大赏和中赏 (kuji.big/win)、收购和赎身 (acquire.big/redeem)、大额基金 (fund.big)、预测开奖 (predict.result)、升星 (star.up)、特色菜冠军 (mc.champion)、猜酒杯通关 (bar.cup.big)、神殿稀有 (temple.explore.rare / guardian.rare)、厨塔周榜 (tower.rank.week)、痞老板被赶走 (plankton.driven) | 逐条给 |
| 一般 | 强化 (equip.stress)、宝石升阶 (gem.levelUp)、油壶扩容 (oil.expand)、搬家 (rest.move)、特色菜出锅 (mc.cook)、商店特价 (shop.special) | 按权重补到上限 |
| 刷屏 | 新开店 (restaurant.open)、菜场进货 (market.restock)、天气变化 (weather.change) | 只给一句汇总，如“新开 23 家店”“天气: 晴转小雨” |
| 不用 | 小镇广播 (town.broadcast)、论坛相关 (forum.*) | 这些是玩家自己写的文字，不进 AI |

**另外给的汇总**：
- 昨天收入最高的 3 家店（rest_income_day，不含 NPC 店）；
- 区服开店总数。

**上限**：逐条的新闻最多 30 条。按权重从高到低取，同权重的取时间最近的；同一家店同一类新闻只取一条。

**怎么写给 AI（防注入的关键）**
- 店名不进 AI：素材里的店写成 `{r:123}` 这样的记号，AI 原样写在文中。
- 前端显示时把记号换成那家店现在的名字，带链接；店后来改名，显示的也是新名字。
- 店名里写什么都影响不了 AI，所以店名能放心直接展示。
- 道具名写成 `{g:10704}`，同时给出它的简中名字，让 AI 知道是什么东西。前端按玩家的语言显示道具名，翻译那一步不用管道具名。
- 其他内容都是可信的：街名、天气名、特色菜名直接写简中，预测题目是后台或系统出的。

素材是一段 JSON，大约 1,500 token：

```json
{ "day": "2026-10-07", "shopCount": 412,
  "summary": ["新开 23 家店", "菜场进货 18 次", "天气: 晴 → 小雨"],
  "topIncome": [{ "rest": "{r:12}", "coin": 382000 }],
  "events": [{ "kind": "一番赏大赏", "rest": "{r:88}", "text": "{r:88} 在豪华一番赏抽中 A 赏 {g:10704}×1" }] }
```

`text` 由服务端按类型生成，用一份简中模板，只覆盖第一张表里列的类型。有测试保证每个类型都有模板。

## 三、AI 两次调用

- **模型**：DeepSeek V4.1 Flash，接口与 OpenAI 兼容，关掉思考模式，要求输出 JSON（`response_format: json_object`），temperature 1.0。
  - 地址、模型名、密钥都用环境变量。

**第一次：写简中**
- 系统提示约 600 token：
  - 小镇日报的口吻：友好、轻松调侃，不挖苦人。
  - 只写素材里有的事，数字照抄。
  - 记号原样保留，不得自己编店名。
  - 输出格式：`{ "title": 不超过 24 字, "body": 3~5 段、段落间空一行、共 250~500 字 }`。
- 用户消息就是素材 JSON。

**第二次：翻成英文**
- 系统提示约 300 token：自然的英文报纸口吻，记号原样保留，输出同样的 JSON。
- 用户消息是简中的 title 和 body。

**检查**（不通过就当失败，走重试）：
- JSON 格式正确，title 和 body 长度在范围内；
- 文中所有 `{r:…}`、`{g:…}` 都出现在素材里；
- 英文版的记号和简中版一模一样（个数、内容）；
- 不含网址（http、www、常见域名后缀）；
- 不含 `<`、`>`，防 HTML。

**繁中**：检查通过后，服务端用 opencc-js（cn → twp）转出繁中一起存。服务端要新加这个依赖，网页端已经在用。

## 四、用量和费用

DeepSeek V4.1 Flash 的价格（每 100 万 token）：

| 时段 | 输入 | 输出 |
| --- | --- | --- |
| 平时 | $0.15 | $0.60 |
| 高峰（工作日 UTC 01:00–04:00、06:00–10:00） | 翻倍 | 翻倍 |

任务在游戏时间 00:10 以后跑，即北京时间 00:10、UTC 16:10，不在高峰。

| 每区服每天 | 输入 | 输出 |
| --- | --- | --- |
| 写简中 | 约 2,100 | 约 500 |
| 翻英文 | 约 900 | 约 450 |
| **合计** | **约 3,000** | **约 950** |

- 按上表算：3,000 × 0.15/10⁶ + 950 × 0.6/10⁶ ≈ **$0.001 每区服每天**，约 **$0.03 每区服每月**。
- 算上重试、后台“重新生成”，按 5 倍余量也不到 $0.2 每区服每月。
- 每次调用的输入、输出 token 数存在表里，后台能看到每天实际用了多少。

## 五、存储

新表 `town_daily`，每区服每天一行：

| 列 | 说明 |
| --- | --- |
| shard_id, day | 主键；day 是游戏日 YYYY-MM-DD |
| status | `pending` 还没生成成功 / `draft` 待审 / `published` 已发布 / `hidden` 撤下 |
| facts | 素材 JSON，原样存，方便重新生成和排查 |
| content | `{"zh-CN": {title, body}, "en": {…}, "zh-TW": {…}}`；没生成成功时为 null |
| model | 模型名 |
| tokens_in, tokens_out | 累计，含重试和重新生成 |
| attempts | 调用了几轮 |
| error | 最近一次失败的原因 |
| generated_at, published_at, published_by | 时间和发布人 |

- 保留 60 天，由每天的任务顺手删除更早的行。
- 新加迁移，加之前先停开发服。

## 六、任务

- 周期任务 `town-daily`，功能名 `daily`：
  - 游戏时间 00:10 以后，每区服每天跑一次（周期键是游戏日）；
  - 开 `retry`，失败 10 分钟后再试，最多 5 次。
- 每次运行的步骤：
  1. 这一天已经是 `draft`、`published` 或 `hidden` 就跳过；
  2. 生成素材，写入 `pending` 行；
  3. 依次调两次 AI，过检查；
  4. 成功就写入内容，状态按区服数值 `daily.autoPublish` 定：false（默认）记成 `draft`，true 记成 `published`；
  5. 失败就记下 error，抛错让周期任务重试。5 次都失败，这一天就停在 `pending`，玩家看到“今日要闻”，后台可以手动重试。
- **没配密钥**（开发环境默认）：只生成素材，状态停在 `pending`，任务记成功（stats 写 `noKey`），不重试。
- **前一天新闻少于 3 条**：照常生成，素材少时 AI 写得短；body 的下限放宽到 80 字。
- 调 AI 用任务的中止信号，单次超时 60 秒。worker 退出时中止，下次重试补上。

## 七、接口

**玩家**
- `GET /api/v1/town/daily?day=`：返回本区服某天的日报。不带 day 就取最近一个已发布的。
  - 返回内容：日期、状态（已发布或今日要闻）、当前语言的标题和正文、记号里的店现在的名字。
  - 记号里的店已经不存在时，名字显示“已关店”，不带链接。
  - 只能看最近 7 天；功能关闭的区服返回 404。
- 首页头条接口 `headlines` 加一个字段 `daily: { day, title } | null`。
- 返回的语言跟着玩家当前语言，西语、法语回英文。

**后台**（admin 权限，写审计日志）
- `GET /api/v1/admin/daily?shardId=`：最近 30 天的列表，包括状态、标题、token 数、错误。
- `GET /api/v1/admin/daily/:shardId/:day`：详情，含素材和三种语言的内容。
- `POST …/publish`、`POST …/hide`：发布、撤下。
- `PUT …`：手改简中和英文的标题、正文。保存时同样做第三节的检查，繁中重新转换。
- `POST …/regenerate`：重新调用 AI 生成，结果是 `draft`。每区服每天最多 10 次。

**后台页面**：区服详情加一个“小镇日报”入口。列表点进去：左边是素材，右边是简中和英文可编辑；记号按店名预览；底下是发布、撤下、重新生成三个按钮。

## 八、开关和数值

- 功能 `daily` 加进 `DEFAULT_OFF_FEATURES`，默认关，在区服覆盖里打开。
- 区服数值 `tuning.daily`，后台数值说明里写上：
  - `autoPublish`：默认 false；
  - `runAfter`：默认 "00:10"；
  - `maxEvents`：默认 30。
- 环境变量（`apps/server/src/env.ts`，都可以不配）：
  - `DAILY_AI_KEY`；
  - `DAILY_AI_BASE_URL`：默认 `https://api.deepseek.com`；
  - `DAILY_AI_MODEL`：默认是 V4.1 Flash 的模型名，开发时到官方文档确认。
- 线上要在 `/opt/dt` 的环境文件里加密钥，这一步由用户自己来。

## 九、测试

- **AI 客户端**作为依赖传进去，测试用假客户端，不用 vi.mock，也不真的调用 AI。
- **素材**：
  - 挑选、权重、上限、同店去重；
  - 刷屏类变成汇总；
  - 广播不进素材；
  - 店名变成记号；
  - 每个类型都有模板。
- **检查**：
  - 记号不在素材里、英文记号对不上、含网址、超长，都判失败；
  - 繁中转换正确。
- **任务**：
  - 草稿和自动发布两种模式；
  - 没配密钥；
  - 失败后重试；
  - 已有草稿就跳过；
  - 60 天清理。
- **接口**：
  - 7 天范围；
  - 语言回退；
  - 记号换成店名，关店的情况；
  - 功能关闭返回 404；
  - 后台权限、编辑后重新检查、重新生成的次数限制。
- **网页**：日报卡片（有日报、今日要闻、翻页）；首页入口在有日报和没日报时的显示。

## 十、范围外

- 不做西语、法语的 AI 版本。
- 不做按玩家个人定制的日报。
- 不做评论和点赞。
- 不做推送。
- AI 不碰任何数值或奖励。
- 自动发布只是一个开关，打开的时机由用户决定。

## 十一、更新记录

功能对玩家打开时加一条五种语言的更新记录，随这个 PR 一起写。区服默认关，所以文案写成“小镇日报上线”。
