# 酒吧新游戏 1「最后一颗糖」设计（Nim 博弈）

- 日期：2026-10-06
- 状态：待用户审
- 来源：问题记录 427 第 1 项（酒吧新增游戏：Nim 博弈套皮）
- 上位文档：`2026-10-01-subproject4c3-bar-games-design.md`（魔鬼辣杯、记忆调酒、飞镖；本游戏沿用它的局面存储、每日次数、奖励方式）

## 1. 一句话

桌上一堆糖果，玩家和调酒师轮流拿，每次拿 1~k 颗，拿到最后一颗的人赢。

## 2. 用户已定的方向（2026-10-06）

| # | 问题 | 决定 |
|---|---|---|
| 1 | 难度 | 两张桌子：新手桌、高手桌 |
| 2 | 筹码和奖励 | 礼券入场；赢了给声望和一份酒吧随机奖励 |
| 3 | 次数 | 每天 10 局，两张桌子合计 |

## 3. 为什么分两张桌子

这个游戏有固定的必胜法：轮到你时，桌上剩的糖果数如果是 k+1 的倍数，你必输；否则拿到剩下的是 k+1 的倍数就必赢。

- 调酒师按必胜法下、玩家又能自己选先后时，懂诀窍的人每局必赢，游戏就成了每天固定领奖。
- 调酒师按必胜法下、玩家不能选时，不懂诀窍的人几乎赢不了。

所以分成两张桌子：

- **新手桌**：让新手也能赢一部分。
- **高手桌**：只奖励懂诀窍的人，但懂也不是每局都赢。

模拟 20 万局的胜率：

| 桌子 | 不会算的玩家（随便拿，能一把拿完时拿完） | 会算的玩家 |
|---|---|---|
| 新手桌 | 44% | 100% |
| 高手桌 | 约 0.1% | 78% |

> 和问卷选项的出入：选项里写高手桌"抛硬币定先后，会算的人约 3/4 能赢"，那句算错了。抛硬币时，会算的人只能赢一半：先手时 k/(k+1)，后手时 1/(k+1)，平均 1/2。要做到约 3/4，得让玩家固定先拿，本文按这个写。如果你想要抛硬币（会算的人赢一半），把高手桌的"先拿"改成随机就行，奖励可以相应调高。

## 4. 规则

### 4.1 两张桌子

| | 新手桌 | 高手桌 |
|---|---|---|
| 入场 | 1 张神秘礼券 | 2 张神秘礼券 |
| 每次最多拿 k 颗 | 3 | 每局随机 3、4 或 5 |
| 糖果数 | 每局随机 10~20 | 每局随机 20~40 |
| 先后 | 玩家看到糖果数和 k 以后，自己选"我先拿"或"让调酒师先拿" | 玩家先拿 |
| 调酒师 | 一半时候失手（见 4.2） | 不失手 |
| 赢了 | 声望 +1，奖励等级 2 的随机奖励 | 声望 +3，奖励等级 5 的随机奖励 |
| 输了 | 什么都没有 | 什么都没有 |

- 两张桌子合计每天 10 局，开局时计数。
- 每局都计每日活跃"酒吧娱乐"。
- 没有平局。
- 随机奖励就是酒吧共用的那份：食材、物品、银币、经验，不出礼券，幸运照常翻倍。
- 奖励等级的参照：
  - 新手桌的 2 和记忆调酒第 1 关一样；
  - 高手桌的 5 和飞镖赢一局一样。
- 声望的参照：好友切磋赢一局 +5。高手桌每天最多 +30，实际约 +23，比切磋少很多。

### 4.2 调酒师怎么拿

设轮到调酒师时桌上剩 n 颗，余数 r = n mod (k+1)：

- **r ≠ 0（调酒师占优）**：
  - 高手桌：拿 r 颗，让剩下的是 k+1 的倍数。
  - 新手桌：50% 照这样拿；另外 50% 失手，在 1~min(k, n) 里随便拿。失手概率是区服数值。
- **r = 0（调酒师处在必输的局面）**：在 1~min(k, n) 里随便拿，拖着等玩家犯错。

随机数在服务端。调酒师在玩家拿完后立刻接着拿，同一个请求里返回两步。

### 4.3 一局的流程

1. **开局**：选桌子。扣礼券，计每日次数；服务端定下糖果数和 k。整个局面都是公开的，没有要藏的东西。
2. **先后（只有新手桌）**：开局后先显示糖果数和 k，玩家点"我先拿"或"让调酒师先拿"。选"让调酒师先拿"后，调酒师先拿一次。
3. **拿**：玩家选拿 1~min(k, 剩余) 颗。如果拿完了，玩家赢；否则调酒师接着拿，拿完了调酒师赢。
4. **结束**：返回输赢、声望、奖励和整局的拿法记录。
5. **中途离开**：局面存在服务端，刷新后能接着下；同一个游戏同时只有一局。

### 4.4 不做的

- 不在游戏里写必胜法。诀窍靠玩家自己发现；游戏资料里只写规则。
- 不做新闻和排行。如果要，可以以后加"高手桌连赢 5 局上新闻"。
- 没有时间限制：局面全公开，没有反应时间这回事，脚本也只能每天打 10 局。

## 5. 数据

- **不加迁移**。用现有的 `bar_round` 表，`game = 'nim'`。
- **state**：`{ table: 'novice' | 'expert', k, pile, left, started: boolean, log: Array<{ who: 'me' | 'bartender', take }> }`
  - `started`：新手桌还没选先后时为 false。
- **每日次数**：每日计数 `bar.nim`，和记忆调酒、飞镖同一种做法。
- **tuning** 在 `bar` 下新增：

```
nim: {
  dailyMax: 10,
  tables: {
    novice: { cost: 1, k: [3, 3], pile: [10, 20], mistake: 0.5, choose: true,  renown: 1, awardLevel: 2 },
    expert: { cost: 2, k: [3, 5], pile: [20, 40], mistake: 0,   choose: false, renown: 3, awardLevel: 5 }
  }
}
```

- `choose`：能不能自己选先后，false 时玩家先拿。
- 校验：
  - `k`、`pile` 的下限都不大于上限；
  - `pile` 的下限大于 `k` 的上限，免得一开局就能一把拿完；
  - `mistake` 在 0~1 之间。

## 6. 接口

| 方法 | 路径 | 请求 | 返回 |
|---|---|---|---|
| GET | `/bar` | – | 原有 `BarDto` 加 `nim`：进行中的局（或 null）、今天已玩局数、上限、两张桌子的入场费和奖励 |
| POST | `/bar/nim/start` | `{ table }` | `NimDto` |
| POST | `/bar/nim/first` | `{ who: 'me' \| 'bartender' }` | `NimDto`；选调酒师先拿时，返回里已经有他拿的那一步 |
| POST | `/bar/nim/take` | `{ num }` | `NimDto`；含玩家这一步和调酒师接着的一步；结束时带 `result`、`renown`、`award` |

`NimDto` 的内容：
- `table`、`k`、`pile`（开局的糖果数）、`left`（剩余）；
- `log`；
- `needFirst`：要不要先选先后；
- 结束时多带 `result: 'win' | 'lose'`、`renown`、`award`。

**错误**（沿用 4C-3 的写法）：

| 情况 | 错误 |
|---|---|
| 同一个游戏已有进行中的局 | `ALREADY_DONE` `what: 'bar_round'` |
| 今天 10 局用完了 | `limitReached('bar_daily', { max })` |
| 礼券不够 | 原有的 `NOT_ENOUGH` |
| 没有进行中的局 | `invalidState('no_round')` |
| 新手桌还没选先后就拿，或高手桌、已经开始了还选先后 | `invalidState('need_first')` / `invalidState('started')` |
| `num` 小于 1、大于 k 或大于剩余 | `badInput` |
| 区服关了酒吧 | 原有的功能开关 |

## 7. 前端

- 酒吧页的游戏胶囊加一个"最后一颗糖"，排在飞镖后面。
- **开局前**：
  - 两张桌子各一行：入场费、每次最多拿几颗、赢了给什么；
  - 写一句"今天还能玩 n 局"；
  - 新手桌下面写"调酒师有时会走神"。
- **桌面**：
  - 糖果用小圆点画，每行 10 个，最多 40 个。
  - 上方写"还剩 n 颗，每次拿 1~k 颗"。
  - 下面是"拿 1""拿 2"……"拿 k"几个按钮，超过剩余数量的按钮变灰。
  - 新手桌开局先显示"我先拿""让调酒师先拿"两个按钮。
- **调酒师的那一步**：玩家拿完先划掉自己拿的；约 0.6 秒后，再划掉调酒师拿的那几颗并写"调酒师拿了 3 颗"，这段时间按钮不能点。减少动态效果时直接显示。
- **记录**：下方一行写本局的拿法，如"你 2 · 调酒师 2 · 你 3 · …"。
- **结束**：写输赢，用酒吧现有的方式显示奖励和声望；"再来一局"回到选桌子。
- 礼券不够或今天的次数用完时，开局按钮变灰并写原因。

## 8. 测试

**服务端**
- 调酒师的拿法：
  - 占优时高手桌一定拿 n mod (k+1)；
  - 新手桌按失手概率分两种（固定随机数覆盖两边）；
  - 必输局面在 1~min(k, n) 里拿；
  - 永远不会拿超过剩余数量。
- 开局：
  - 两张桌子扣的礼券不同；
  - k 和糖果数在范围里；
  - 计每日次数，第 11 局被拒绝；
  - 已有进行中的局被拒绝。
- 先后：
  - 新手桌没选先后不能拿；
  - 选调酒师先拿后，他拿了一步；
  - 高手桌不能选，直接拿。
- 拿：
  - 越界的数量被拒绝；
  - 玩家拿完就赢，发声望和奖励、删掉局面；
  - 调酒师拿完就输、没有奖励；
  - 刷新后局面还在。
- 数值校验：不合法的 nim 配置被拒绝。
- 查询条数：`/bar` 的预算不变（nim 的局面和次数并进现有读 `bar_round`、每日计数的查询）。

**前端**
- 面板的组件测试：
  - 选桌子；
  - 新手桌的先后按钮；
  - 拿的按钮超过剩余就变灰；
  - 调酒师那一步的延迟显示（假时钟）；
  - 结束的显示；
  - 次数用完和礼券不够。

**端到端**：高手桌按必胜法打一局，直到结束。
