## 3. 游玩指引页（150）

### 3.1 入口和路由

- 新路由 `/guide`，页面 `GuideView.vue`，标题"游玩指引"。只要求登录，不要求选区服或开店。不开店也能看规则；新手码那一块要有店才能领。
- 入口：
  - "更多 → 其他"加"游玩指引"（图标 `bi-signpost-2`），放在"兑换码"前面；
  - 首页：店铺等级 < 10 时，在等级那行下面显示一行链接"新手看这里 → 游玩指引（有新手兑换码）"，testid `guide-hint`；
  - 选区服页：底部"退出登录"旁边加"游玩指引"链接。

### 3.2 内容

页面由几块可折叠的 `details` 组成，testid 为 `guide-<key>`。"新手兑换码"和"开店第一天"默认展开，其余默认收起。文案在实现时按代码和配置里的实际规则写，不写原版有、但本作没实现的东西。

1. **新手兑换码**（`guide-codes`）：见 §4.3。
2. **开店第一天**（`guide-start`）：
   - 结算怎么来钱：客人按轮来，餐桌数、菜谱等级、橱柜里的食材决定收入；
   - 体力：干什么要花体力，怎么补；
   - 第一天先做的几件事：加属性点、去菜场买食材、学菜谱、签到。
3. **每天的固定事项**（`guide-daily`）：签到、任务和活跃、广场 NPC、菜园、酒吧、厨塔、外卖，以及菜场的进货时间。每项一句话加一个跳转链接。
4. **常见问题**（`guide-faq`）：
   - 万能食材能换什么（问题记录 140 的困惑：只有二级万能食材能换稀有食材）；
   - 厨具强化和穿戴等级；
   - 搬家和街道勋章；
   - 店名、公告的规则。
5. **游戏规则**（`guide-rules`）：
   - 禁止一人多号刷资源、互相转移资源；
   - 禁止利用漏洞，发现了请在论坛"建议"版或通过邮件报告；
   - 禁止辱骂、广告和不当内容，玩家可以举报；
   - 违规会被封号 1 天、7 天或永久，严重的会清空违规所得；
   - 后台的可疑数据只作提醒，不会只凭它处罚。

## 4. 新手兑换码（150）

### 4.1 配置

新文件 `packages/config/data/game/newbie_codes.json`。照现有 overlay 的做法：不进 prettier；`raw.newbieCodesFile`；source 为 `'game/newbie_codes'`；`ConfigBundle.newbieCodes`。格式如下：

```json
{
  "codes": [
    { "code": "XINSHOU", "minLevel": 1, "items": { "coin": 50000, "goods": [{ "id": 28, "num": 3 }, { "id": 1, "num": 3 }] }, "note": "新手码 1 级" }
  ]
}
```

`items` 和邮件附件、兑换码奖励的格式（`RewardItems`）完全一致，`goods` 和 `foods` 写成 `{ id, num }`。

**构建时检查**，不通过就报错 `newbie_codes <code>: <原因>`：
- 码符合 `REDEEM_CODE_RE`，并且没有重复；
- `minLevel` 是正整数；
- `items` 能通过 `rewardItems` 的校验（不为空、同一种不重复、不超过上限）；
- 道具和食材的 id 在配置里存在。

**奖励初稿**（用户已看过，可以再改）：

| 码 | 等级 | 奖励 |
|---|---|---|
| XINSHOU | 1 | 银币 5 万、小体力卡（28）×3、神秘礼券（1）×3 |
| XINSHOU10 | 10 | 银币 10 万、体力卡（29）×2、随机万能食材礼包（131）×2、钻石 10 |
| XINSHOU20 | 20 | 银币 20 万、体力卡（29）×3、小扩容卡（3）×1、钻石 20 |

### 4.2 同步进兑换码表

新函数 `syncNewbieCodes(db, config, log)`，放在 `modules/redeem/newbie.ts`。`main.ts` 在迁移之后、`listen` 之前调用；不管 `MIGRATE_ON_START` 是什么都调用。同步失败只打错误日志，不阻止启动。

- 操作者用系统账号（就是现在蟹老板用的 `~krab`，把 `npcAccountId` 导出复用）。
- 对配置里的每个码：
  - **表里没有**：插入。`kind = 'shared'`、`shard_id = null`、`max_uses = null`、`starts_at` 和 `ends_at` 为空、`min_level`、`items`、`note` 来自配置。
  - **表里有，操作者是系统账号**：如果 `items`、`min_level` 或 `note` 和配置不同就更新；`disabled_at` 不碰。后台停用过的码保持停用，`used_count` 也不动。
  - **表里有，操作者不是系统账号**（后台手动建过同名的码）：不覆盖，打一条警告日志。
- 配置里删掉的码不处理：表里那一行留着，要停用就去后台停用。
- 每家店只能领一次，靠现有的 `redeem_use(code_id, rest_id)` 唯一约束保证。

### 4.3 指引页上的新手码

- 新接口 `GET /api/v1/guide/codes`（要求已开店）。返回 `GuideCodeDto[]`，顺序和配置一致：
  `{ code, minLevel, items, state: 'ok' | 'level' | 'used' | 'off' }`。
  - `used`：本店已经领过；
  - `off`：表里不存在、已停用，或者被手动建的同名码占用；
  - `level`：等级不够；
  - 其他情况是 `ok`。
- 页面每行显示码、"N 级可领"和奖励文字（复用 `rewardText`），右边按状态显示：
  - `ok`：显示"领取"按钮（testid `guide-redeem-<code>`），点了调用现有的 `POST /redeem`，成功后弹提示并刷新列表；
  - `level`：显示"N 级可领"；
  - `used`：显示"已领"；
  - `off`：显示"已结束"。
- 领取完全走现有的兑换流程，失败计数、按店去重、奖励发放都不变。新手码都是真实存在的码，不会被计入失败次数。

### 4.4 测试

- 配置：
  - 坏的码、重复的码、不存在的道具、空奖励都会报错；
  - 真实的 `newbie_codes.json` 能通过检查。
- 同步：
  - 第一次插入；
  - 第二次不重复插入；
  - 改了配置后会更新奖励；
  - 停用过的保持停用；
  - 手动建的同名码不被覆盖。
- 接口：四种状态都能正确返回；领取后变成 `used`。

## 5. 菜园姐（176）

### 5.1 显示

- 新组件 `components/market/GardenSis.vue`，放在菜场页的最上面（在 `HiphopCard` 之前）。样式是一张小卡片：
  - 左边是头像：`GameImg path="npc/菜园姐"`，图片缺失时显示 `bi-flower2`；
  - 右边写"菜园姐："加一句台词。
- 点头像或者台词就换一句（testid `garden-sis`）。随机，但不会连着两次说同一句。

### 5.2 台词

台词放在 `utils/gardenSis.ts`，是一个纯函数 `gardenLines(data: MarketDto, now: Date): string[]`。它返回当前能说的所有台词，组件从里面随机挑一句。

- **看菜场状态说的**（满足条件才加进来）：
  - 特价菜有货：特价菜还剩 N 样，手快有手慢无；
  - 特价菜没货：特价菜卖光了，下次 HH:MM 进货；
  - 日常菜场下次进货的时间；
  - 竞猜开着但本店还没下注：提醒去竞猜；
  - 有手动进货卡：提醒可以手动进货。
- **固定的闲聊和小贴士**：大约 20 句，比如推荐看游玩指引、提醒菜放久了会坏、天气会影响客人、二级万能食材能换稀有食材。
- 状态台词出现的概率比闲聊高：组件挑的时候，状态台词各算 2 份权重。

字段名以实现时的 `MarketDto` 为准。

### 5.3 测试

- `gardenLines`：
  - 特价有货和没货时，分别出现对应的台词；
  - 有手动进货卡时出现提醒；
  - 没下注时出现竞猜提醒；
  - 闲聊一直都在。
- 组件：用固定的随机数，点一下会换一句不同的。

## 6. 我的账号（178）

### 6.1 服务端

- `GET /api/v1/account/profile`（要求登录，不要求选区服），返回 `AccountProfileDto`：

  ```ts
  { username, email, emailVerified, role, createdAt, inviteCode: string | null,
    rests: Array<{ shardId, shardName, shardOpen: boolean, restId, name, level }> }
  ```

  `rests` 只列本账号的非 NPC 店，按区服 id 排序。
- `POST /api/v1/account/change-password`，请求体为 `{ oldPassword, newPassword }`。
  - `newPassword` 用注册时的密码规则；
  - 走 `rateLimit: 'auth'`。
  - 旧密码不对：报 `invalidState('wrong_password')`，前端提示"旧密码不对"。这里不用登录的 401 `INVALID_CREDENTIALS`，因为前端可能把 401 当成"已退出登录"。
  - 新旧密码相同：报 `invalidState('same_password')`。
  - 成功后：更新 `password_hash`，再调用 `sessions.destroyAll(accountId)` 让其他设备下线。然后给当前设备新建一个会话，设置 Cookie，并把原会话里选的区服和店写回去，这台设备保持登录、不用重选区服。
  - 写一条审计，动作是 `account.password`，不记密码。

### 6.2 页面

- 新路由 `/account`，页面 `AccountView.vue`，标题"我的账号"。只要求登录。
- 入口：
  - "更多 → 其他"加"我的账号"（图标 `bi-person-circle`），放在第一位；
  - 选区服页加"我的账号"链接。
- 页面内容：
  - **账号**：
    - 用户名、注册日期；
    - 身份：只有协管和管理员才显示；
    - 邮箱：已验证显示绿色"已验证"；未验证显示"未验证"和"重发验证邮件"按钮；
    - 邀请码：没有的话显示"去邀请页生成"，链接到 `/invite`。
  - **我的店**：每个区服一行，显示区服名、店名和等级。点"进入"调用 `selectShard`，再跳到首页。已关闭的区服灰掉。testid 为 `acc-rest-<shardId>`。
  - **修改密码**：旧密码、新密码、确认新密码。两次输入不一致时，前端直接提示。成功后提示"密码已修改，其他设备已下线"。testid 为 `acc-old`、`acc-new`、`acc-new2`、`acc-change`。
  - 底部放"切换区服"和"退出登录"。

### 6.3 测试

- 服务端：
  - `profile` 能返回各区服的店；
  - 旧密码错误时报错，密码不变；
  - 改密码后用新密码能登录，旧会话失效；当前请求拿到的新 Cookie 能用，而且保留了选的区服；
  - 新旧密码相同时报错。
- 组件：
  - 确认密码不一致时不发请求；
  - 未验证邮箱显示重发按钮。

## 8. 仓库排序（186）

- `StoreView` 在网页端排序，服务端不改。
- 分组顺序：消耗品（0）→ 道具（1）→ 礼包（2）→ 设施（3）→ 勋章（9），其他类型排在最后。
- 组内排序：
  1. 有剩余时间的先排，剩余时间短的在前；
  2. 再按名字排，用 `localeCompare(..., 'zh-Hans-CN')`，相当于按拼音；
  3. 最后按道具 id。
- 选"全部"时，每组前面加一个小标题（类名 `dt-section`，testid `store-group-<type>`）。选了某个分类时不显示标题。
- 排序函数抽成 `utils/storeSort.ts` 里的 `sortStoreItems(items, catalog)`，做单元测试。

## 10. 部署注意

- 服务端启动时会自动把新手码写进兑换码表（3 行）。开发库也会写，不动其他数据。
