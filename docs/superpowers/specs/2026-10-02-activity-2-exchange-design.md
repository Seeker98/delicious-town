# 限时活动 148-2：兑换活动（代币、集字/集碎片）+ 纪念品 设计

日期：2026-10-02
状态：待用户审阅

## 1. 范围

问题记录 148 的第三个子项目（顺序 1 → 4 → 2 → 3）。一个 PR，分支 `feat/activity-exchange`。包含两部分：

- 活动类型 **兑换活动**（`exchange`）：常规玩法按概率掉落活动货币，到活动商店兑换奖励。"活动代币"和"集字/集碎片"是同一种机制，代币就是只有一种货币。
- **纪念品**：配置里新增一种道具类型和第一批 12 件节日纪念品，可以当任何奖励发放。

## 2. 用户已确认的裁定

1. 代币和集字合并成一种类型"兑换活动"。
2. 活动货币**不是道具**，只存在活动计数里，活动结束、兑换期过后自然作废，不占仓库，也不需要清理。
3. 活动结束后留一段**兑换期**（后台可填，0~168 小时，默认 24）：这段时间不掉落，但还能兑换。
4. 纪念品在**配置里定义**（不是后台动态建），第一批 12 件节日主题，名字和描述见 §6.3。
5. "期间限定道具"不需要新机制：在兑换表里选原版就有有效期的道具即可。

## 3. 活动定义

shared 的 `ACTIVITY_KINDS` 加 `'exchange'`，`ActivitySpec` 加 `{ kind: 'exchange'; def: ExchangeDef }`。迁移 0023 放开 `activity.kind` 的检查约束。

```ts
ExchangeDef = {
  currencies: { name: string }[1..8],            // 名字 1~6 字，互不相同；键为 m<下标>
  drops: {
    key: ActionKey,                               // 和 148-1 共用 ACTIVITY_ACTIONS
    chance: number,                               // 每次行为的掉落概率，0 < p ≤ 1，最多 4 位小数
    currency: number,                             // currencies 的下标
    num: int 1..99,                               // 每次命中掉几个
    dailyCap: int 1..9999,                        // 这条规则每人每天最多掉几个
  }[1..20],
  shop: {
    cost: { currency: number; num: int 1..9999 }[1..4],  // 同一货币不重复
    award: rewardItems,                           // 现有奖励结构，可以选纪念品
    limit: int 1..999,                            // 每人最多换几次
  }[1..30],
  graceHours: int 0..168,                          // 兑换期，默认 24
}
```

校验错误带字段路径：
- 货币名为空、超长或重名；
- 规则或兑换引用了不存在的货币下标；
- 概率超出范围；
- 兑换消耗为空，或同一货币在一项里出现两次。

开始后定义不能改（148-1 规则），所以下标稳定。

## 4. 掉落

挂在 148-1 的 `action` 事件处理器上（`modules/activity/handler.ts`），和计数在同一个事务里。窗口、区服、等级、功能开关的判断都沿用原来的。对兑换活动：

1. 找出 `key` 等于本次行为的每条规则；
2. 掷 `n` 次（`n` 是事件里的次数），每次 `rng.next() < chance` 算命中，得到命中次数 `hits`；
3. 掉落数 `add = min(hits × num, dailyCap − 今天已掉)`，`add ≤ 0` 就跳过；
4. 今天已掉的数量记在 `daily_counter`，键 `act<活动id>:d<规则下标>`，日界用 `gameDay`；
5. 余额加在 `activity_counter (活动, 店, 'm<货币下标>')`。

随机数用 `GameDeps.rng`（测试可以注入固定序列）。处理器拿不到 op 的随机源，所以直接用 `d.rng`。

## 5. 兑换

`POST /activities/:id/exchange`，请求体 `{ index: number, times: int 1..99 }`。在锁店事务（`runOp`，功能 `activity`）里：

1. 活动存在、本区服、已开始、类型是 `exchange`，否则 `NOT_FOUND`，或者 `invalidState('not_exchange')`；
2. `现在 < ends_at + graceHours`，否则 `invalidState('exchange_closed')`；
3. 这一项存在，否则 `invalidState('no_item')`；
4. 已换次数 + `times` ≤ `limit`，否则 `limitReached('activity_exchange', { limit, left })`；
5. 每种消耗：余额 ≥ `num × times`，否则 `notEnough('activity_currency', need, have, 货币下标)`；
6. 扣余额（`activity_counter` 减），已换次数（键 `x<下标>`）加 `times`；
7. 发奖：奖励按 `times` 倍放大（新的纯函数 `scaleRewards`，数量相乘，帽子重复 `times` 次），用 `grantRewardOp`，来源 `activity`，个人日志 `activity.exchange`（参数：活动标题、货币名、次数、奖励）。日志要有中文文案。

扣余额用 `update … set count = count - x where count >= x returning`，在锁店事务里与同一家店的其他操作串行，并发兑换不会扣成负数。

## 5.1 状态和补发

- 兑换活动没有"达成奖励"：`rewardsOf` 返回 `[]`。148-1 的补发任务对它什么都不做，只写一条补发完成记录。
- 玩家 DTO 新增字段 `exchangeUntil: string | null`（兑换活动是 `ends_at + graceHours`，其他类型是 null）。
- 玩家列表的保留期仍是结束后 7 天，兑换期最长也是 7 天，所以兑换期内一定在列表里。
- 首页横幅的"进行中"仍然只算没结束的活动。兑换期内不算进行中，但活动页里有入口。

## 6. 纪念品

### 6.1 配置

- 新文件 `packages/config/data/game/souvenirs.json`：`[{ id, name, desc, holiday }]`。
- 构建时把它们并进道具表，新类型 `GOODS_TYPE.souvenir = 10`：
  - `coin` 和 `diamond` 都是 0，`maxNum` 99，没有 `value`、加成、用途；
  - id 不能和已有道具冲突，构建时检查，冲突就报错。
- 道具的中文类型名（前端用到的地方）加上"纪念品"。

### 6.2 规则

- **不占仓库格子**：计算仓库种类数时排除纪念品，和勋章一样。
- **不能出售**：`sellPrice` 返回 null；**不能使用**：没有用途；**不能丢弃**：丢弃接口拒绝，`invalidState('souvenir_keep')`。
- 发放走 `grantGoodsOp`，数量上限 99。
- 仓库页新增"纪念品"标签页：只列纪念品，每件显示图片（`GameImg`，没有图片时用图标）、名字、数量、描述和节日。原来的"仓库"标签页不再显示纪念品。

## 7. 前端

- **后台编辑器**（类型下拉加"兑换活动"）：
  - 货币表：名字，可以增删，最多 8 个；
  - 掉落规则表：行为、概率（按百分比输入，提交时除以 100）、货币下拉、每次几个、每天上限；
  - 兑换表：每项是"消耗"（若干行"货币下拉 + 个数"）+ 奖励编辑器 + 每人次数；
  - 兑换期（小时）。
  - 奖励编辑器的行用稳定 key（沿用 148-1 终审 I1 的 `rowKeys`）。
- **玩家活动页**的兑换活动卡片：
  - 各货币余额；
  - 今天各掉落规则还能掉多少，例如"菜场买菜 5% 掉 福 ×1（今天 3/10）"；
  - 兑换表：消耗、奖励、已换和上限、次数输入和"兑换"按钮（余额或次数不够时禁用）。
  - 结束后显示"兑换期，还剩 X 小时"；兑换期过后显示"已结束，活动货币已作废"。
- **仓库页**：新增"纪念品"标签页（§6.2）。

## 8. 测试

- 定义校验：§3 列出的每种错误都带路径。
- 掉落（固定随机数）：
  - 命中和不命中；
  - n 次事件掷 n 次；
  - 每天上限、跨游戏日重置；
  - 结束后不掉；
  - 别的规则和行为不掉；
  - 别的类型的活动不受影响。
- 兑换：
  - 余额不够、超过次数、兑换期内能换、兑换期过后不能换、不是兑换活动、项目不存在；
  - 换 3 次时奖励按 3 倍发放，余额和已换次数正确；
  - 同时发两个兑换请求，只成功到余额允许的次数。
- `scaleRewards` 纯函数。
- 纪念品：
  - 构建后道具表里有 12 件，类型是纪念品，id 冲突时构建报错；
  - 发放后不占仓库格子；不能卖、用、丢；
  - 仓库的"纪念品"标签页只显示纪念品，"仓库"标签页不显示。
- 个人日志 `activity.exchange` 有文案（现有的日志文案测试会检查）。
- 前端：后台三块编辑器（增删、百分比换算、提交内容），玩家卡片（余额、今日掉落、兑换、兑换期），仓库的纪念品标签页。

## 9. 不做的事

- 后台动态新建道具或纪念品。
- 兑换期过后把剩余货币折算成补偿。
- 148-3 全服合力。
