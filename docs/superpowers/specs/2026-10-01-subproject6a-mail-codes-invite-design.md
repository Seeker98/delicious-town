## 1. 目标与范围

**目的**：正式开服前，运营者能给玩家发东西、发通知、做拉新，赞助者能拿到专属帽子。

**完成标志**：
1. 管理员在后台给一服发一封带附件的全服邮件。已有的店在邮箱里领到附件；邮件发出后才开的店看不到它。
2. 管理员发一条"重要"公告。玩家进游戏时弹窗一次，首页顶部一直显示。
3. 管理员建一个通用兑换码，玩家在邮箱页兑换，当场到账；第二次兑换提示"已经用过"。
4. A 把邀请链接发给 B，B 注册开店后邮箱里有新手礼包。B 验证邮箱、升到 10 级后一分钟内，A 在同一区服的店收到邀请奖励邮件。
5. 管理员给赞助者发一顶名为"大橘"的玉级帽子，厨具页显示"玉•大橘之帽"。这家店升到六星后一分钟内，收到同名的铉级帽子邮件。

### 1.1 包含

| 功能 | 内容 |
|---|---|
| 邮箱 | 单店、区服、全部三种收件范围；带附件；领取、一键全领、删除；30 天过期；后台发送、撤回；补偿页可改为发邮件 |
| 公告 | 按区服和时间段发布；首页横幅；重要公告弹一次；登录页显示 |
| 兑换码 | 通用码、一次性码；后台创建、停用、导出；玩家兑换当场到账 |
| 邀请 | 新手礼包；被邀请人 10 级、30 级时邀请人得奖励；每月上限；邀请好友页 |
| 赞助帽子 | 新增玉级、铉级两件帽子，可按件命名；六星自动换铉 |

### 1.2 不包含

| 内容 | 归属 |
|---|---|
| 举报和审核、可疑数据页、区服数值说明、上线前开关检查 | 6B |
| 邮件里玩家互发、回复 | 不做 |
| 公告富文本、图片 | 不做，纯文字加换行 |

## 2. 规则裁定

| # | 问题 | 裁定 |
|---|---|---|
| 1 | 全服邮件怎么存 | 一封一行，每家店的已读、已领、已删另存一行，只在有操作时写（用户选 A） |
| 2 | 谁能收到全服邮件 | 发送时刻已经存在的餐厅（`restaurant.created_at <= mail.created_at`），区服匹配。后开的店收不到，防止开小号反复领补偿 |
| 3 | 等级门槛按什么时候算 | 按查看和领取那一刻的等级。等级不够时邮件照样能看到，但不能领，并写明要几级；30 天内升上去就能领 |
| 4 | 邮件过期 | 发出后 30 天（`mail.expiresDays`），过期后看不到、领不了，没领的附件作废 |
| 5 | 领取并发 | 锁店后先写"已领"记录，`(mail_id, rest_id)` 唯一，`claimed_at` 只从空改一次；重复点、多开标签页都只到账一次 |
| 6 | 附件怎么发 | 复用补偿发放 `grantItemsOp`：橱柜满了进冰箱，仓库满了照发；流水来源 `mail.claim`，个人日志 `mail.claim` |
| 7 | 附件上限 | 和补偿一样：银币、经验 ≤ 1 亿，钻石 ≤ 10 万，道具、食材每种 ≤ 9999，每种最多 50 项；命名帽子每封最多 5 顶 |
| 8 | 撤回 | 后台撤回后，没领的人看不到也领不了；已领的不追回 |
| 9 | 删除邮件 | 附件已领或本来没附件才能删；删除只影响自己 |
| 10 | 补偿页"改为发邮件" | 单店补偿改为发一封单店邮件，全区服补偿改为发一封区服邮件，都带同样的附件和原因 |
| 11 | 公告的范围 | 指定区服或全部区服。登录页只显示"全部区服"的公告，因为登录前不知道玩家在哪个区 |
| 12 | 重要公告弹窗 | 按账号记已看。同一账号在多个区服只弹一次；关掉弹窗就算看过 |
| 13 | 兑换码区分大小写吗 | 不区分。统一存成大写，玩家输入时也转成大写 |
| 14 | 通用码每家店一次 | `(code_id, rest_id)` 唯一。同一账号在不同区服的店可以各用一次，区服限制由码自己设定 |
| 15 | 一次性码 | 每个码只能被用一次，`used_count` 只能从 0 加到 1，并发兑换只有一个成功 |
| 16 | 防暴力猜码 | 每个账号每小时最多失败 10 次（Redis 计数），超过后返回 `too_many_tries` |
| 17 | 兑换的到账方式 | 当场到账，不经过邮箱。流水来源 `redeem`，个人日志 `redeem`，返回得到的东西 |
| 18 | 新手礼包 | 被邀请人账号开出第一家店时发进这家店的邮箱，每个账号只发一次 |
| 19 | 邀请人奖励的条件 | 被邀请人已验证邮箱，并且名下有一家店达到 10 级（或 30 级）。每个被邀请人每档只算一次，按最先达到的那家店 |
| 20 | 邀请人奖励发到哪 | 发到邀请人在"达到等级的那家店所在区服"的餐厅。邀请人在该区还没有店时，奖励记为待发，等他在该区开店后补发 |
| 21 | 每月上限 | 每个邀请人每个自然月（游戏时间）最多计 20 个被邀请人。按"本月有 `sent` 或 `pending` 记录的被邀请人"去重计数（同一被邀请人两档只算一人），超出的记为 `capped`，不发奖励 |
| 22 | 触发方式 | worker 每分钟扫描一次，不挂在升级、升星、验证邮箱、开店的代码里。最多延迟一分钟，换来的是不改结算和升级的核心代码，也不会漏掉"先升级后验证邮箱"这种情况 |
| 23 | 命名帽子显示 | 厨具实例上存名字。有名字时，显示名是"玉•{名字}之帽"或"铉•{名字}之帽"；没名字时显示道具原名"玉•赞助之帽" |
| 24 | 帽子名字的限制 | 1~8 个字，去掉首尾空格，不能含换行；名字不进新闻 |
| 25 | 六星换铉 | 店里有命名的玉级帽子，店升到 6 星后，给这家店发一封邮件，附件是同名的铉级帽子。每顶玉帽只换一次，记在玉帽上；玉帽保留，不收回 |
| 26 | 功能开关 | 新增区服功能 `mail`、`redeem`、`invite`，默认开。关掉 `mail` 时邮箱接口返回 `FEATURE_DISABLED`，但邮件照样写入，重新打开后能看到；关掉 `invite` 时扫描跳过该区服的邀请部分，邀请好友页返回 `FEATURE_DISABLED`；关掉 `redeem` 时兑换接口返回 `FEATURE_DISABLED` |
| 27 | 权限 | 邮件、公告、兑换码的写操作只有 admin；mod 能看列表。全部写操作进审计日志 |

## 4. 附件格式

在现有 `grantItems` 上加一项，共用于邮件和兑换码：

```ts
type RewardItems = GrantItems & {
  /** 命名帽子：档次和名字；每封最多 5 顶 */
  hats?: Array<{ tier: 'jade' | 'xuan'; name: string }>;
};
```

- 发放函数 `grantRewardOp(op, items, source)`：前五项沿用 `grantItemsOp` 的逻辑，流水来源和日志类型改为参数；帽子用 `createEquips` 生成实例后写 `custom_name`。
- 原 `grantItemsOp` 改成调用它，来源仍是 `admin.grant`，行为不变。
- 校验：沿用 `grantItems` 的上限、去重、非空；`hats` 的名字按裁定 24 校验。

## 6. 接口

玩家接口都要登录并有餐厅；写操作走 POST。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/mail` | 邮件列表（未过期、未撤回、未删除、对本店可见），带未读数 |
| POST | `/mail/:id/read` | 标记已读 |
| POST | `/mail/:id/claim` | 领取附件 |
| POST | `/mail/claim-all` | 领取所有能领的附件，返回领了几封、得到了什么 |
| POST | `/mail/:id/delete` | 删除 |
| POST | `/redeem` | `{ code }` 兑换 |
| GET | `/invite` | 我的邀请码（没有就生成）、本月已计人数、被邀请人列表 |
| GET | `/announcements` | 本区服和全部区服的有效公告，带"未看的重要公告" |
| POST | `/announcements/:id/seen` | 标记重要公告已看 |
| GET | `/public/announcements` | 不用登录；全部区服的有效公告，给登录页用 |

- 餐厅概况加 `mailUnread`，顶栏信封用。
- 后台接口前缀 `/api/v1/admin`：
  - `mails` 列表、发送、撤回；
  - `announcements` 增删改查；
  - `codes` 列表、创建通用码、批量生成一次性码、停用、导出某批的码。
- 补偿创建接口加 `asMail: boolean`。

**兑换失败原因**（`INVALID_STATE` 的 `reason`）：`code_not_found`、`code_not_started`、`code_expired`、`code_used_up`、`code_used`、`code_wrong_shard`、`code_level`、`code_disabled`、`too_many_tries`。

**领取失败原因**：`mail_claimed`、`mail_no_items`、`mail_level`（带所需等级）、`mail_expired`。

## 7. 邀请和换铉扫描

worker 新增任务 `ops-scan`，每 60 秒运行一次，遍历开放的区服：

1. **新手礼包**：找出有邀请人、在本区服有店、还没有 `newbie` 记录的被邀请人账号。给这家店发礼包邮件，写 `newbie`（`status = sent`）。同一账号在多个区服开店时，只按最先开的那家发。
2. **邀请人奖励**：找出已验证邮箱、有邀请人、本区服有店达到 10（或 30）级、还没有对应档记录的被邀请人。
   - 先算邀请人本月已计人数：本月有 `sent` 或 `pending` 记录的被邀请人去重，不论档次。
   - 已满 20 人，并且这个被邀请人不在本月已计名单里：写 `capped`。
   - 邀请人在本区服有店：发邮件，写 `sent`。
   - 邀请人在本区服没店：写 `pending`。
3. **补发待发**：`pending` 的记录，如果邀请人现在在该区服有店，就发邮件并改成 `sent`。待发不再重新判断月上限，因为写入时已经计过。
4. **六星换铉**：找出本区服星级 ≥ 6、有命名玉帽且 `xuan_sent_at` 为空的店。在一个事务里写 `xuan_sent_at` 并发邮件，附件是同名铉帽。

**失败处理**：每条记录单独一个事务，一条失败只记日志，不影响其他；下一分钟会再扫到。记录表的主键和 `xuan_sent_at` 保证不会重复发放。

奖励内容放在 `tuning.invite`：

```json
"invite": {
  "monthlyCap": 20,
  "stages": [{ "key": "lv10", "level": 10 }, { "key": "lv30", "level": 30 }],
  "newbie": { "coin": 50000, "goods": [{ "id": 1, "num": 5 }] },
  "rewards": { "lv10": { "diamond": 20 }, "lv30": { "diamond": 50, "coin": 200000 } }
}
```

具体数值先按这个上线，以后在后台按区服调。构建时校验引用的道具存在。

## 8. 前端

**玩家端**
- **顶栏**：信封图标和未读数，点开进邮箱页。

  - 顶部是兑换码输入框。

  - 被邀请人列表：店名、区服、等级、各档状态。

- **公告**：
  - 首页顶部横幅显示最新一条有效公告，点开是公告列表。
  - 有未看的重要公告时，进游戏弹窗一次。
  - 登录页显示"全部区服"的有效公告。

**后台**
- **邮件页**：收件范围、区服、店 id、等级门槛、标题、正文、附件编辑器（复用补偿页的，加"命名帽子"一行）；发送前确认，写明收件范围；列表和撤回。
- **公告页**：列表、新建、编辑、删除。
- **兑换码页**：新建通用码、批量生成一次性码、列表（使用次数）、停用、复制或导出一整批。
- **补偿页**：加"改为发邮件"开关。

## 9. 错误处理和边界

- 邮件正文、公告正文按纯文本显示，保留换行，不解析 HTML。
- 邮件列表最多返回最近 100 封（30 天内）。
- 撤回、过期和领取同时发生时：领取在锁店事务里重新读邮件状态，撤回或过期后就领不了。
- 后台删公告是软删除，弹窗记录保留。
- 兑换码的总次数用 `update ... set used_count = used_count + 1 where used_count < max_uses` 一条语句判断，并发下不会超发。
- 一次性码导出只给 admin。

- **单元测试**：附件校验（帽子名字、上限）、显示名、月份计算、扫描各分支的判定函数。
