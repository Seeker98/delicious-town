# 成就系统和成就点排行榜（设计稿 2026-10-19）

## 1. 要做什么、为什么

给玩家一个长期目标：现在做的每一件事（营业、学菜、打蟑螂、划拳、登塔……）都在一面成就墙上留下进度，攒下的成就点在区内排名。参考了另一个小镇复刻站点的成就页（563 个、31,865 点、99 个奖杯，抓包见附录 B），深度向它看齐，但按我们自己的玩法和每日上限定门槛。

**用户已定的（2026-10-19）**
- 只给成就点和装饰（奖杯、称号、头像框、展示位），不给任何加成、银币、道具
- 食谱品级只做到佳肴（第 7 级，也是现在的上限 cookbookMaxGrade），菜系节点也只做到佳肴
- 规模不设上限：本稿 483 个成就、19,590 点、88 个奖杯、16 个称号
- 隐藏成就多做、做离谱一点
- 现在仓库里的「成就」荣誉分组（Big胆、肝帝、外卖之星等 7 个，带加成）改名「勋章」，「成就」两个字留给新系统
- 自动达成，不用手动领取
- 成就点排行榜不发任何奖励（包括限时称号）
- 全服首达的高档成就发小镇新闻
- 补发时大家同分，按店铺编号小的在前
- 第 4 节各条成就线的门槛和点数已过目
- 门槛按线上真实数据定（只读查询，见附录 A）

**不做的**
- 不卖成就：绝版成就只进成就墙、不计点（参考站点可以“赞助”补绝版，我们不学）
- 不按金额计的金融成就：交易所、预测、收购这些两个号能对倒，只按次数或事件数，点数最高 20
- 厨具战力：随厨具重标会变，也最接近花钱
- “当前持有 X 银币”：鼓励囤钱，换成“累计营业银币”
- “成就点达到 X 再送成就点”：点数自己生自己，里程碑只解锁装饰

## 2. 概念

| 名词 | 意思 |
|---|---|
| 成就 | 一个达成条件 + 点数，达成后记下时间，永久保留 |
| 成就线 | 同一个口径的一串成就（比如“打蟑螂 100 / 1,500 / 5,000 …次”），每一档是一个单独的成就 |
| 档 | 成就线上的一级；点数由“认真玩家要花多久”决定（第 3 节） |
| 成就点 | 所有计点成就的点数之和，排行榜就排它 |
| 奖杯 | 装饰。部分档位附带，摆在展示柜里给别人看（88 个） |
| 称号 | 永久称号，沿用定制称号的黄底徽章（16 个），只给“一年档”以上和少数传说成就 |
| 头像框 | 新的一类装扮，按成就点里程碑解锁（第 5 节） |
| 隐藏成就 | 达成前只显示 ???，点数固定 |
| 绝版成就 | 限时活动、开服纪念，不计点，只进成就墙 |
| 全服首达 | 每个区第一个达成某个 ≥ 40 点成就的店，成就墙上标“全服首达”和日期，不多给点 |

**达成方式（已定）**: 自动达成，不用手动领取。达成后进餐厅动态，成就入口亮红点。

## 3. 难度模型：按时间定档、按档给点

先说一个前提：一轮营业 4 分钟，全天开着一天 360 轮。很多“次数”在我们这里涨得比参考站点快得多，必须用线上实际日均来定，不能照抄它的数字。

| 时间档 | 认真玩家大约要多久 | 点数 |
|---|---|---|
| d | 一天以内 | 5 |
| w | 一周 | 10 |
| m | 一个月 | 20 |
| q | 三个月 | 40 |
| h | 半年 | 60 |
| y | 一年 | 80 |
| Y | 两年以上 | 100 |

- “认真玩家”取线上活跃店日均的 p90 左右（大约前一成的玩家）；中位玩家大约要两倍时间
- 有每日上限的（换食材 10 次、魔鬼辣杯 20 局、一掷千金 3 局……），最后一档就是“天天打满两年”，谁都追得上，拼的是坚持
- 天数类（签到、许愿、吃白食）一天一次，档位就是天数本身
- 纯运气的（许愿树中奖、隐藏成就）点数固定，不按时间档

**参照**: 参考站点那个签到 334 天的老号拿到 40% 的点数，它的奖杯档大约一年、最高档两三年。我们的结构一样：第一个奖杯多在 q~y 档，最高档 Y。

**上线时会怎样（估算）**: 线上最老的店才两周。补发后头部店大约 600~800 点（总量的 3~4%），中位店 100~200 点。先来的有优势，但远没到锁死排行榜的程度。

## 4. 成就清单

“来源”一栏：
- **现有计数**：event_counter 里已有的全历史计数（任务系统的 action 事件，开服起就有），可以直接补发
- **状态**：从现有表直接查（等级、星级、食谱品级、厨塔层数……），可以直接补发
- **新计数**：要在结算或对应玩法里新加计数，补发只能用还保留的明细，算不全的从上线日起计

## 7. 实现要点（给做的人）

**定义**: 放配置 `packages/config/data/designed/achievements.json`，一条成就一行：id、分类、成就线、档序号、口径（counter / state / custom）、计数键或状态查询名、门槛、点数、奖杯 id、称号 id、是否隐藏、是否绝版。名字和说明按成就线写模板（“累计打蟑螂 {n} 次”），只有成就线名、奖杯名、称号名需要逐条翻译，英文、法文、西文三种照常，繁中最后生成。

**存储**:
- `rest_achievement(rest_id, ach_id, achieved_at, first_in_shard, backfilled)`
- `restaurant` 加 `ach_points`、`ach_points_at`（排行榜用）
- 新计数复用 event_counter（键名见清单里的“新计数”）

**达成判定**:
- 计数类：在任务系统的 action 处理器里顺带查这个键对应的成就线，跨过门槛就写达成（同一个事务）
- 状态类：等级、星级在升级时查；食谱、特色菜、厨塔、套装、好友数、基金、赛厨榜每天 04:30 扫一遍（和备份错开）
- 结算类新计数（满意挑剔顾客、满座轮数、一轮 1 油）在结算写 income_round 时一起累加

**补发**: 用迁移跑一次，按 event_counter、状态表、rest_income_day 算；标记 backfilled，不发动态和新闻。要算的新计数（划拳胜场、被抓次数等）能从保留的明细补多少补多少，其余从上线日起计，成就说明里写“从 X 日起计”。

**页面**:
- 「我 → 成就」：顶部总进度（个数、点数、奖杯），按分类分页，每条成就线展开看各档和当前进度
- 好友访问页的展示柜
- 排行榜加两个榜：成就点、本周新增
- 游戏资料（wiki）里加成就分类

**动态和新闻**: 达成进餐厅动态；全服首达且 ≥ 80 点的发小镇新闻（已定发新闻，80 点这条线是我的建议）。

**旧分组改名**: goods_groups 里 honorAchieve 的显示名「成就」改成「勋章」，道具本身、编号、加成都不动；荣誉道具说明里写“颁发的成就”的几条（星光熠熠、登峰造极等）一起改成“颁发的勋章”。
