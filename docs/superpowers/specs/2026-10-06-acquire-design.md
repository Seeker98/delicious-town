# 收购玩法 设计（问题记录 421）

- 日期：2026-10-06
- 来源：问题记录 421。原提议：初始身价 10 万、每被收购一次 +20%，被收购方得 90%、系统扣 10% 税；被收购方每天给老板打理一次；最多拥有 10 家；被收购期间不能收购别人；可以回购自己；打折出售由系统立刻付 50%。
- 原提议的问题（路线图 421 已分析）：
  - 打折出售由系统付钱、比例超过税率，两家串通每转一圈净赚 40% 身价（“互折法”）。
  - 身价每次 ×1.2，指数膨胀，和店本身无关。
  - 小号收打理奖励；收着不放锁死别人。
- 用户已定（2026-10-06）：
  - 身价、热度、税、分红、打理、各项限制、榜单都按路线图 421 写定的方案。
  - 收购不用对方同意：谁都能按身价买下，钱给现在的主人（没被收购的给餐厅自己）。
  - 取消系统付钱的打折出售，改成**打折挂牌、玩家接手**：老板按身价打折挂牌，别的玩家按挂牌价买下，钱都由买家付。
  - 打折挂牌被买下后热度 −0.1（不低于 1.0）；新老板没有保护期。
  - 入口：身价榜上直接收购，对方餐厅页也能收购。
  - 分红每天自动到账；打理是点一下。
- 不涉及菜园。

## 1. 玩法

### 1.1 身价

身价 = 基础身价 × 热度。

- **基础身价**：近 7 天日均结算银币 × 5，不低于 10 万（`minPrice`）。每天 00:05 按前 7 个完整游戏日重算一次。只看店的真实经营，买卖、赎身、放手都不改它。
  - 刚开的店不满 7 天：按 7 天平均（没结算的日子算 0），所以新店身价低。
- **热度**：从 1.0 起，最高 3.0。
  - 被强收一次 +0.2。
  - 打折挂牌被买下 −0.1，不低于 1.0。
  - 赎身、放手不变。
  - 每天 00:05 往 1.0 回落 10%：热度 = 1 + (热度 − 1) × 0.9。
- 身价按银币取整。页面写身价和热度（例如“身价 1,240,000（热度 1.24）”）。

### 1.2 五个操作

所有操作在一个事务里按店 id 升序锁住涉及的店（买家、目标店、原主人），和结算、别的操作不会死锁。

1. **强收（收购）**：任何人按当前身价买下一家店。
   - 买家付身价；原主人（目标店没被收购时就是目标店自己）得 90%，10% 是税，不进任何人口袋。
   - 目标店归买家；热度 +0.2；目标店的挂牌（如果有）作废。
2. **买挂牌**：按挂牌价买下别人挂牌的店。
   - 挂牌价 = 当前身价 × 挂牌折扣（折扣存的是比例，身价每天变，挂牌价跟着变）。
   - 买家付挂牌价，原老板得 90%，10% 是税；店归买家；热度 −0.1（不低于 1.0）；挂牌清掉。
3. **赎身**：被收购的店按当前身价把自己买回来。
   - 付身价，老板得 90%，10% 是税；店变回自主经营；3 天内（`protectDays`）不能被强收、也不能被买下；挂牌作废。
4. **放手**：老板免费放掉名下一家店，店变回自主经营；不退钱、热度不变、没有保护期。
5. **挂牌 / 撤牌**：老板把名下一家店按身价的 50%~100%（5% 一档，`listMinRate`）挂牌，挂 3 天（`listDays`）自动到期；随时可以撤牌。

### 1.3 限制

强收和买挂牌都要满足：

- 买家自己没有被收购（被收购期间不能收购别人）；买家名下不满 10 家（`maxHoldings`）。
- 目标店不是自己、不在自己名下；2 星及以上（`minStar`）；不在赎身保护期。
- 目标店今天被强收、买下合计不到 3 次（`maxPerDay`）。
- 同一对店（买家和目标店，不分方向）7 天内（`pairDays`）没有收购、买下过。
- 买家账号和目标店账号、和原主人账号都没有共用过设备或 IP（30 天内，`linkDays`）：
  - 拦下来，报“不能收购关联账号的店”；
  - 记一条到“收购关联账号拦截”，后台可疑数据页能看。
- 目标店的账号没被封；不是蟹老板（NPC）。

其他：

- 名下有店的人自己被收购时，名下的店照旧归他、分红照发，只是被收购期间不能再收购新的店。
- 赎身、放手、挂牌只有当事人能做：赎身是被收购的店自己，放手、挂牌、撤牌是现在的老板。

### 1.4 分红和打理

- **分红**：每天 00:05 收入汇总之后，给每家被收购的店的老板发：
  - 前一天这家店结算银币 × 5%（`dividendRate`）；
  - 前一天打理过 ×1.5（`tendBonus`）；
  - 前一天结算不满 90 轮（`minRounds`，约开店 6 小时）的不发。
- **封顶**：一个老板一天的分红合计不超过他自己近 7 天日均结算银币 × 25%（`dividendCapRate`），超了按比例压下来。老板自己是新店、收入很低时，封顶也低。
- 发给的是 00:05 时的老板。
- 银币直接加到老板身上，写一条日志（“昨天名下 N 家店分红共 X 银币”），流水来源 `acquire.dividend`。每家的分红记下来，给“昨天分了多少”和投资榜用。
- 老板的账号被封时不发；被收购的店账号被封时照常算（分红只看结算）。
- **打理**：被收购的店每天能点一次“替老板打理”：
  - 自己得 5 份食材（`tendFoods`）：等级和随机奖励的食材池一样（按店的等级），带个人缺料倾向；
  - 标记当天已打理，老板第二天拿这一天的分红时 ×1.5；
  - 没有老板时没有这个按钮。

### 1.5 榜单、页面、新闻

- **收购页**（“更多”里新入口），四个标签：
  - **身价榜**：本区服身价最高的 50 家：店名、身价、热度、现在的老板；能收购的带“收购”按钮，不能的写原因（星级不够、保护期、今天已被收购 3 次等）。
  - **在售**：正在挂牌的店：店名、老板、折扣、挂牌价、剩余时间，带“买下”按钮。
  - **投资榜**：按名下店的身价合计排前 50，旁边写名下几家、累计分红。
  - **我的**：
    - 我的身价、热度、老板；被收购时有“替老板打理”“赎身”按钮。
    - 名下的店：身价、昨天分红、是否打理过、挂牌状态；每家有“挂牌 / 撤牌”“放手”。
    - 名下几家（上限 10 家；被收购时写“被收购期间不能收购”）。买家自己没有每天的收购次数限制，每天 3 次是一家店被收购的上限。
- **对方餐厅页**：写身价、老板（有的话）、挂牌状态；带“收购”或“买下”按钮。
- **自己的首页**：被收购时显示一行“你的餐厅归【老板】所有”，带打理、赎身入口。
- **新闻**：
  - 强收、买下身价 1,000 万以上（`newsMinPrice`）的：“【买家】以 X 银币收购了【店】”。
  - 赎身：“【店】以 X 银币赎回了自己”。
- **确认框**：每个付钱的操作都先弹确认，写清价格、对方得多少、税多少。

### 1.6 为什么串通不赚钱

- 所有的钱都是玩家付的，系统只收 10% 税、不出一分钱；每转一手全体银币少 10%。
- 两个号来回强收：每次付 P、对方拿回 0.9P，一圈亏 0.2P，热度上去以后亏得更多；同一对 7 天内不能再收；共用设备、IP 的直接拦下。
- 打折挂牌给自己的小号：只是把价值从大号挪给小号，还要交 10% 税。
- 被收购的店紧接着赎身：赎身也收 10%。
- 分红只看真实结算，又有每人封顶，身价锚在真实收入上，刷不出来。

## 2. 数值（区服数值 `tuning.acquire`，后台可改）

| 键 | 默认 | 说明 |
|---|---|---|
| priceDays | 7 | 基础身价按近几天的日均结算银币 |
| priceMultiple | 5 | 基础身价 = 日均 × 这个数 |
| minPrice | 100,000 | 基础身价下限 |
| heatStep | 0.2 | 被强收一次热度加多少 |
| heatListDrop | 0.1 | 挂牌被买下热度减多少（不低于 1.0） |
| heatMax | 3 | 热度上限 |
| heatDecay | 0.1 | 每天热度超出 1.0 的部分回落的比例 |
| taxRate | 0.1 | 税 |
| protectDays | 3 | 赎身后几天不能被收购 |
| maxHoldings | 10 | 每人最多名下几家 |
| maxPerDay | 3 | 一家店每天最多被强收、买下几次 |
| pairDays | 7 | 同一对店几天内不能再交易 |
| linkDays | 30 | 关联账号看近几天的登录记录 |
| minStar | 2 | 几星以上才能被收购 |
| listMinRate | 0.5 | 挂牌最低折扣（5% 一档） |
| listDays | 3 | 挂牌几天到期 |
| dividendRate | 0.05 | 分红 = 前一天结算银币 × 这个数 |
| tendBonus | 0.5 | 打理过的那天分红多加的比例 |
| minRounds | 90 | 前一天结算满几轮才发分红 |
| dividendCapRate | 0.25 | 老板每天分红合计 ≤ 自己日均结算银币 × 这个数 |
| tendFoods | 5 | 打理得几份食材 |
| newsMinPrice | 10,000,000 | 多少银币以上的收购上新闻 |

- 校验：比例都在 0~1；heatMax ≥ 1；listMinRate 在 0.05~1；天数、次数是正整数。
- 功能开关 `acquire`，默认关；最后一个 PR 改成默认开。

## 3. 数据和接口

### 3.1 新表（一个迁移）

- `rest_income_day (rest_id, day, coin, rounds)`，主键 (rest_id, day)：每家店每个游戏日的结算银币合计和轮数。
  - 每天 00:05 的任务从 `income_round` 汇总前一天（`income_round` 只留 3 天，所以要另存），保留 14 天。
  - 结算本身不改，结算的查询条数不变。
- `acquire_state (rest_id 主键, shard_id, owner_rest_id 可空, base, heat, protected_until 可空, list_rate 可空, list_until 可空, acquired_at 可空)`：
  - 只给 2 星以上、或被收购过的店建行：每天任务给新到 2 星的店补行，其余在第一次被收购时建。
  - 索引：(shard_id, base × heat) 给身价榜用；(owner_rest_id) 给“名下的店”用；(shard_id, list_until) 给在售用。
- `acquire_log (id, shard_id, kind, buyer_rest_id 可空, target_rest_id, seller_rest_id 可空, price, tax, heat_after, created_at)`：
  - kind：acquire / buy_listed / redeem / release。
  - 7 天同一对、每天 3 次的检查都查它；保留 30 天。
- `acquire_tend (rest_id, day)`：打理记录，主键防一天两次（PR 2 从 `acquire_state.tended_day` 改成单独的表：00:00~00:05 打理今天会盖掉昨天的标记）。
- `acquire_dividend (owner_rest_id, rest_id, day, coin, tended)`：每家每天的分红（压过封顶以后的），给“昨天分红”和累计分红用；累计数另外存在 `acquire_holder (rest_id 主键, dividend_total)`，免得投资榜每次加总全表。
- `acquire_block (id, shard_id, buyer_rest_id, target_rest_id, reason, created_at)`：关联账号拦下来的记录，后台可疑数据页读它。

### 3.2 周期任务（feature `acquire`，每天一次）

00:05 以后，依次三个任务（周期键 `<任务>-YYYY-MM-DD`，每天一次）：

1. `income-day`（挂在 `settlement` 上，收购关着也跑）：汇总前两天的 `rest_income_day`（覆盖写，前一天漏了下一天补上）。
2. `acquire-day`：再汇总一次；按前 7 天重算所有 `acquire_state.base`，给新到 2 星的店补行；热度回落，清掉到期的挂牌和 30 天前的记录。
3. `acquire-dividend`：发前一天的分红（每个老板一个事务，锁自己的店加银币）。
   - 分红记录主键 (rest_id, day)，重跑不重复发；已经发给这个老板的从封顶里扣掉。
   - 某个老板失败只记日志，不影响别人；整个任务失败当天不补发（补发时已经不知道 00:05 的老板是谁）。
   - 前一天的收入一行都没汇总上时报错，不按 0 发。

### 3.3 接口（都要登录、选区服、开店，功能开关 `acquire`）

- `GET /acquire`：我的身价、热度、老板、今天打理没有；名下的店（身价、昨天分红、打理、挂牌）；名下上限、税率、挂牌最低折扣和天数、赎身保护天数。
- `GET /acquire/rank?board=price|invest`：身价榜、投资榜前 50。
- `GET /acquire/market`：在售的挂牌。
- `GET /acquire/rest/:restId`：一家店的身价、热度、老板、挂牌、我能不能收购（不能时给原因）——对方餐厅页用。
- `POST /acquire/buy { restId, expect }`：强收或买挂牌。`expect` 是页面上看到的价格：价格变了就报错让玩家重新确认，免得点下去时身价刚好变了。
- `POST /acquire/redeem { expect }`、`POST /acquire/release { restId }`、`POST /acquire/list { restId, rate }`、`POST /acquire/unlist { restId }`、`POST /acquire/tend`。
- 每个付钱的操作走正常的流水（来源 `acquire.buy`、`acquire.sale`、`acquire.redeem`、`acquire.dividend`），后台的银币流入流出统计、可疑数据的暴涨榜都能看到。

### 3.4 后台

- 区服数值页：`tuning.acquire` 每个键的说明。
- 可疑数据页：加“收购关联账号拦截”一节。
- 区服功能开关：`acquire`。

## 4. 不做

- 不改结算：分红由系统另发，被收购的店自己的收入一分不少。
- 不做“只能好友之间收购”“收购要对方同意”。
- 不做系统付钱的打折出售。
- 不做收购相关的成就、称号（以后要加另说）。
- 不碰菜园。

## 5. 分几个 PR

1. **数据和五个操作**：迁移、每天的收入汇总和身价、热度、挂牌到期；强收、买挂牌、赎身、放手、挂牌 / 撤牌；各项限制和关联账号拦截；接口和后台数值说明。功能开关默认关。
2. **分红和打理**：分红任务（含封顶）、打理、分红记录和累计。
3. **页面**：收购页四个标签、对方餐厅页、首页提示、确认框、新闻、后台可疑数据页、更新记录（五种语言）、游戏资料的攻略加一条；功能开关改成默认开。

每个 PR 开之前派 opus 审查。

## 6. 测试

- **身价**：
  - 7 天平均（不满 7 天的按 0 算）、下限；
  - 热度 +0.2、−0.1 不低于 1、上限 3、每天回落；
  - 赎身、放手不改热度。
- **强收**：
  - 钱的流向：买家付 P、原主人得 0.9P、税 0.1P；目标店独立时钱给目标店自己；
  - 店归买家、挂牌作废。
- **限制逐条**：被收购的人不能收购；满 10 家；星级不够；保护期；一天 3 次；同一对 7 天；共用设备、IP（拦下且记录）；NPC；封号；收自己、收自己名下的。
- **其他操作**：
  - 买挂牌：价格按折扣跟身价走；热度 −0.1；
  - 赎身：保护期；
  - 挂牌：折扣档位、到期、撤牌，只有老板能做。
- **并发**：两个人同时收购同一家，只有一个成功、钱不重复扣；收购和赎身同时发生。
- **分红**：
  - 5%、打理 ×1.5；
  - 不满 90 轮不发；
  - 封顶按比例压；
  - 换过老板发给 00:05 时的老板；
  - 老板封号不发；
  - 任务重跑不重复发。
- **打理**：每天一次、食材数和等级、没有老板时不能打理。
- **收入汇总**：和 `income_round` 对得上；跨天、重跑不重复。
- **查询条数预算**：`/acquire`、身价榜加进 `perf/budget.test.ts`。
- **串通算账**：用两家店来回强收、挂牌给小号、收完立刻赎身各走一遍，断言全体银币只减不增（减少量 = 税）。
- 页面：各标签、按钮可点和不可点的原因、确认框的数、英法西文案。
