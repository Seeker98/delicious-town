# 许愿树 设计（问题记录 589）

- 日期：2026-10-11
- 来源：问题记录 589："纯添头玩法……每天随机一种道具，第二天发给已经许愿玩家中选择一个"。
- 用户已定：
  - 做 B 方案（每日开奖），不做"玩家自己选道具、当场按概率判定"的 A 方案。
  - 入口放在小镇页，加一个"许愿树"标签。
  - 道具清单先用一份初始列表，之后用户在后台区服数值页里自己改。
  - 10 级以上才能许愿。
  - 中奖的人另得一个 3 天的限时称号。
  - 每天 20 点开奖（游戏时间），和大宗认购开批同一时刻。
  - 方案细节（一轮的时间、邮件发奖、安慰奖、页面内容、清单初始内容）用户已确认。
- "慕雪残年"：按提出这个点子的玩家理解，用后台现有的定制称号给他发一个感谢称号，不写进代码。
- 和已有的"许愿得星愿"（持有神灯的人每天第一个许愿，决定全镇当天的星愿）是两个玩法：新的叫"许愿树"，页面、日志、新闻、邮件都写"许愿树"。
- 不碰菜园。

## 1. 玩法

### 1.1 一轮

- 一轮从游戏日 D 的 `hour` 点（默认 20 点）到 D+1 的同一时刻。
- 开新一轮时，按权重从道具清单里抽一种（道具 + 数量），这就是这一轮树上"结出"的东西，全区服看到的都一样。
- 这一轮里，满 `minLevel` 级（默认 10）的店可以许 1 次愿。许愿就是报名，不花任何东西，也不能撤。
- 到点开奖：
  - 从这一轮许过愿的店里等概率抽 1 家；已被封号的店的账号跳过。
  - 中奖的店收到一封系统邮件，附件是这一轮的道具，外加一个限时称号（领取后 `titleDays` 天有效，默认 3）。
  - 发一条全服广播样式的小镇新闻："××在许愿树下许愿成真，得到了××"。
  - 没中的店每家得一份 `consolationLevel` 级（默认 1）的随机奖励（和厨塔、任务等用的随机奖励同一套），直接发到身上，个人日志里写明是许愿树的安慰奖。
  - 开奖后立刻开下一轮。
- 一轮没人许愿就不开奖、不发新闻，直接开下一轮。
- 定时任务停了很久的话：到点后只把上一轮开奖，再开当前这一轮，不补中间缺的轮。

### 1.2 限时称号

- 新称号 `wish_tree`，名字"许愿成真"，写进 `data/game/looks.json` 的 icons，说明"许愿树开奖中奖（限时）"，不上架。
- 随中奖邮件发放，领取后 `titleDays` 天有效（用定制称号设计里"领取后 N 天"的那套）。已经有这个称号时，领取刷新到期时间。

## 2. 数值

区服数值 `tuning.wishTree`：

```
wishTree: {
  hour: 20,              // 几点开奖、开新一轮（游戏时间）
  minLevel: 10,          // 几级才能许愿
  titleDays: 3,          // 中奖称号领取后几天有效
  consolationLevel: 1,   // 没中的安慰奖：几级随机奖励
  prizes: [ { goods, num, weight }, ... ]   // 初始见 §1.3
}
```

检查（构建和后台保存区服数值都跑同一套）：

- `0 ≤ hour ≤ 23`，`minLevel ≥ 1`，`titleDays ≥ 1`，`consolationLevel ≥ 1`；
- `prizes` 至少一项；每项的道具存在、没下架，`num ≥ 1`，`weight > 0`；同一道具不重复。

另外：

- 道具编号登记进区服数值的编号改写规则（`TUNING_ID_PATHS`）和道具整理工具的来源（`tuningRefs`，"许愿树"）。
- `setting_docs.json` 写说明。
- 区服功能开关加 `wishtree`，默认开。

## 3. 数据和接口

### 3.1 数据库（新迁移）

- `wish_round`：每轮一行。
  - 列：`id`、`shard_id`、`day`（开这一轮的游戏日）、`goods_id`、`num`、`opens_at`、`ends_at`、`status`（`open` / `drawn` / `empty`）、`winner_rest_id`、`entries`（许愿人数，开奖时写）、`drawn_at`。
  - 同一区服同一天只有一轮：唯一约束 `(shard_id, day)`。
- `wish_entry`：每家店每轮一条。
  - 列：`round_id`、`rest_id`（主键是这两列）、`created_at`、`won`、`award`（安慰奖内容，jsonb）、`settled_at`。
  - 删店时一起删。

### 3.2 服务端（新模块 `modules/wishtree`）

- `GET /wishtree`：
  - 这一轮：道具、数量、许愿人数、开奖时间；我许过没有；
  - 门槛（`minLevel`）、我的等级；
  - 最近 7 轮的结果：道具、中奖店名、许愿人数；我参加的写明中没中、安慰奖是什么。
- `POST /wishtree/wish`：
  - 不够等级报 `requirement('level', { need })`；
  - 这一轮已许过报 `wish_already`；
  - 没有进行中的一轮报 `wish_closed`；
  - 区服关了许愿树报功能关闭。
  - 成功写一条 `wish_entry`，日志 `wishtree.wish`。
- 定时任务 `wishtree-draw`（每分钟）：
  - **开奖**：到了 `ends_at`、状态还是 `open` 的轮锁住，抽中奖店，写 `winner_rest_id`、`entries`、`status = 'drawn'`（没人许愿写 `empty`）；在同一个事务里给中奖店发邮件（模板 `wishtree.win`，附件道具 + 称号）、发新闻 `wishtree.win`。
  - **安慰奖**：开奖后，没中、还没处理的许愿逐家发（每家店一个事务；写 `award`、`settled_at`；重跑只补没处理的；单家失败记日志，下一分钟重试）；日志 `wishtree.lost`，写明安慰奖。中奖的那条也写 `settled_at`。
  - **开新一轮**：区服开着许愿树、到了 `hour` 点、这一天还没有一轮时，按权重抽道具开一轮。
  - 开奖和安慰奖挂在 `restaurant` 上，区服关了许愿树也照常收尾已有的一轮；开新一轮只在开着许愿树时做。
- 新闻类型 `wishtree.win` 加进新闻类型清单和全服广播样式；邮件模板 `wishtree.win`；店铺动态不加。

### 3.3 页面

- 小镇页加第四个标签"许愿树"（`?tab=wishtree`），区服关了时不显示。
- 内容：
  - 这一轮：树上结的道具和数量，"已有 N 人许愿"，"每天 20:00 开奖"（时间从数据取）；
  - "许愿"按钮：许过的显示"已许愿，等待开奖"；不够等级的写明要几级；
  - 说明（折叠）：一轮怎么走、10 级门槛、中奖得道具和 3 天称号、没中有安慰奖；数字都从数据取；
  - 最近几轮的结果。
- 文案写简中、英、法、西，繁中自动生成。新闻、邮件模板、日志、报错、称号都要四种语言。加一条更新记录（五种语言）。

## 4. 不做

- 花钱多许几次、用道具提高中奖概率；
- 玩家自己选道具（A 方案）；
- 单独的后台页面（清单在区服数值页改）；
- 快速模拟里的机器人许愿。

## 5. 测试

- **配置：** 默认值合法；`hour` 越界、清单为空、道具不存在或已下架、数量或权重不对、同一道具重复时报错；称号在 looks.icons 里。
- **迁移：** 两张表能建；同区服同一天只有一轮；同一家店同一轮只能许一次；删店一起删。
- **许愿：** 够等级能许、写一条；不够等级、重复许、没有进行中的一轮、关了功能时报错。
- **开新一轮：** 到点前不开；到点开一轮，道具来自清单；同一天重跑不多开；关了功能不开。
- **开奖：**
  - 只从许过愿的店里抽；中奖店收到邮件，附件是这一轮的道具和称号；
  - 发新闻（广播样式）；
  - 没中的店每家得一份随机奖励，日志写明；
  - 没人许愿时状态 `empty`、不发新闻、照样开下一轮；
  - 重跑不重复开奖、不重复发安慰奖；某家失败下一轮补上；
  - 被封号的店不会被抽中；
  - 抽中的概率大致相等（固定随机数，多轮统计）。
- **看板：** 这一轮、我许过没有、最近结果、门槛都对。
- **前端：** 标签按开关显示、`?tab=wishtree` 直接打开；许愿按钮的三种状态；最近结果；说明里的数字来自数据。
