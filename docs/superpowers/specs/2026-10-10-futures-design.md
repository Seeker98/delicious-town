# 食材期货 设计

- 日期：2026-10-10
- 来源：用户 2026-10-10 提出“食材来源太单一（买、合、随机事件），加几个现代化、financial 的来源，和发展基金、交易所、事件预测成一个系列”。目标定为“C：既有能点名要某种食材的，也有偏玩法、给范围内食材的”。
- 顺序（用户已定）：① 食材期货（本文）→ ② 食材理财（锁银币、利息发本街缺料包，另写设计）→ ③ 供应商竞价众筹（以后再做）。
- 背景：稀有食材难拿的主因不是概率低，而是“想要的那一种被几十种摊薄”，3~5 级能直接买的渠道又被限购卡住（[稀有食材供给-分析-2026-10-09.md](../../design/稀有食材供给-分析-2026-10-09.md)）。现有来源几乎都是随机给一种。期货让玩家点名要某一种，代价是贵一点、等 3 天、占着定金、有违约风险。
- 不涉及菜园。

## 1. 用户已定的取舍

1. 可下单的食材列表可配置，带一份初始列表；后台有页面，能按等级、是否稀有筛选、勾选上架下架。1、2 级也有很多缺的，不只 3~5 级。
2. 交割期 3 天。
3. 定价用“锚点 B 加上下限”（第 3 节）。
4. 付款：下单付定金，到期付尾款。到期前撤单也算违约，定金不退；撤单不退额度。不另收处理费，违约的代价全靠定金（比例做成区服数值）。
5. 额度：每人每天合计 50 份；区服每种每天 1、2 级 500 份、3~5 级 100 份。
6. 列表全服一份（数据库），额度、比例这些数值按区服可调。
7. 初始列表：1~5 级里菜谱用得到的稀有食材全部，加上 2 级普通食材。
8. 交割时橱柜放不下的进交易所账户。
9. 单独的功能开关“期货”，默认开。

## 2. 玩法

- 交易所页加一个“期货”标签。门槛和交易所一样：等级 ≥ `exchange.minLevel`、注册满 `exchange.minAccountDays` 天、验证过邮箱；交易所被冻结的店不能下新单。
- 选一种上架中的食材、填份数，看到单价、定金、尾款、到期时间，确认后：
  - 当场扣定金（店里的银币）；
  - 生成一张期货单，到期时间 = 下单时间 + `futures.deliverHours`（72 小时）；
  - 占用这种食材今天的区服额度和自己今天的个人额度。
- 到期自动交割（第 6 节）：银币够就扣尾款、给食材；不够就违约，定金没收。
- 到期前可以撤单：算违约，定金没收，额度不退。
- 下单的银币、尾款、没收的定金都直接消失（付给系统），是一个回收口；食材由系统新给，靠两层额度限量。

## 3. 定价

下单时锁定单价，之后参考价怎么变都不改：

```
等级价 = round(食材系统定价 × market.levelPriceRate[等级 − 1])   // 日常货架的定价公式，这一级不在日常货架卖也照算
基准   = clamp(今天的交易所参考价, 等级价, 等级价 × futures.capRate)
单价   = ceil(基准 × futures.premium)
总价   = 单价 × 份数
定金   = ceil(总价 × futures.depositRate)
尾款   = 总价 − 定金
```

- 默认 `premium` 1.2、`capRate` 2、`depositRate` 0.3。
- 天气、菜场价格倍率（`market.priceFactor`）都不算进等级价：期货价一天内只跟参考价变。
- 参考价用交易所现有的 `refPrice`（本区服今天的）；交易所关着的区服也照常能算参考价。
- 锚点的理由（分析见对话记录，摘要）：
  - 只用参考价时，3~5 级没人交易，参考价就等于系统定价，期货比 240-1 定下的菜场等级价便宜很多，比高级货架便宜 5 倍；
  - 用等级价兜底以后，期货落在等级价和高级货架之间，和 240-1 一致；
  - 参考价会被想马上拿到货的玩家一点点抬高，所以加上限：期货价最多是等级价的 2.4 倍，对稀有食材的市价是一个硬天花板。
- 防套利：
  - 交易所系统收购价 ≤ 参考价 × 0.7，而且不超过菜场最低价 × 0.9，永远低于期货价；
  - 期货买进再卖给别的玩家可以，这是期货本来的玩法，也给交易所添了货源。

参考数（默认数值、参考价等于系统定价时）：

| 食材 | 系统定价 | 等级价 | 期货单价 |
|---|---|---|---|
| 2 级普通（2,200） | 2,200 | 2,860 | 3,432 |
| 3 级火腿 | 4,500 | 9,000 | 10,800 |
| 4 级（5,400） | 5,400 | 16,200 | 19,440 |
| 5 级长胡椒 | 9,300 | 37,200 | 44,640 |

## 4. 额度

- 区服额度：每种食材每个游戏日一共能订多少份。默认按等级 `futures.dailyQuota`：`[500, 500, 100, 100, 100]`（1~5 级）；列表里单独设了额度的用单独的。
- 个人额度：每家店每个游戏日所有食材合计最多订 `futures.personDaily`（50）份。
- 都按下单那一刻的游戏日算；撤单、违约都不退。
- 下单时在一个事务里原子地占额度，超了整单拒绝，告诉玩家还剩多少：
  - 区服额度：`futures_quota (shard_id, foods_id, day)` 主键、`used` int；插入或加数时带条件 `used + qty ≤ quota`，没加上就是超了；
  - 个人额度：每日计数 `futures.qty`（下单锁着店，不会并发）。
- 后台改小额度以后，今天已经订出去的不收回；剩余按新额度算（可能是 0）。

## 5. 期货食材列表

### 5.1 数据

`futures_food`：

| 列 | 说明 |
|---|---|
| `foods_id` int 主键 | 食材 |
| `enabled` bool | 是否上架 |
| `daily_quota` int null | 单独的区服每日额度；空 = 按等级默认 |
| `updated_at`、`updated_by` | 最后修改 |

- 全服一份。不在表里的食材等于没上架。
- 下单时这种食材必须在表里、`enabled`、配置里存在且没下架（`retired`）。

### 5.2 初始列表

迁移按规则写入：1~5 级、没下架、有菜谱用得到的食材里，

- 全部稀有食材（出现权重 < 100）：1 级 11、2 级 25、3 级 41、4 级 37、5 级 9，共 123 种；
- 加上 2 级普通食材 62 种（日常货架平均约 10 天才上一次架）。

一共 185 种，全部上架、额度按默认。1 级普通食材（几乎天天能买到）、3~5 级普通食材（有特价货架）先不放，后台随时可以加。迁移只写这一次，以后配置里新加的食材不会自动进表。

### 5.3 后台“期货食材”页

- 位置：后台“交易所”下面一个新页。`mod` 能看，`admin` 能改，每次修改写审计（改了哪些食材、改前改后）。
- 筛选：等级、稀有 / 普通、上架 / 下架 / 不在表里、名字搜索、“哪条街的菜谱要用”。
- 每行：编号、名字、等级、是否稀有、要它的街道数；当前区服今天的参考价、等级价、期货单价；额度（默认值灰字，单独设的黑字）；当前区服今天已订份数。
- 操作：
  - 勾选多行（含“全选当前筛选结果”），一键上架或下架；不在表里的上架时加进表；
  - 单行改额度，清空恢复默认。
- 区服用后台顶部现有的区服选择（价格、已订份数按它显示）。

## 6. 到期交割

`futures_contract`：

| 列 | 说明 |
|---|---|
| `id` bigserial | |
| `shard_id`、`rest_id`、`foods_id` | |
| `qty` int | 份数 |
| `unit_price`、`deposit`、`balance` bigint | 下单时锁定 |
| `created_at`、`due_at` timestamptz | |
| `status` | `open` / `delivered` / `defaulted` / `cancelled` |
| `settled_at` timestamptz null | |
| `to_cupboard`、`to_wallet` int | 交割时进橱柜、进交易所账户各几份 |

索引：`(status, due_at)`（找到期的）、`(rest_id, created_at desc)`（我的期货单）。

周期任务 `futures-deliver`：每分钟一次，不按区服设开关（关了期货功能的区服也要交割已有的单）。

- 找 `status = 'open' and due_at <= now` 的单，按店分组，每家店一个事务（`runSystemOp`，锁店）：
  - 按到期先后逐张处理；
  - 店里银币 ≥ 尾款：扣尾款（流水来源 `futures.balance`），`addFoods(..., { keepDropped: true })` 进橱柜，放不下的进交易所账户（`exchange_wallet_food`）；状态 `delivered`；
  - 不够：状态 `defaulted`，什么都不扣也不给（定金早已扣过）。
  - 写个人日志和餐厅动态：`futures.delivered`（食材、份数、几份进了交易所账户）、`futures.defaulted`（食材、份数、没收的定金）。
- 一家店失败只记错误日志，不影响别的店，下一分钟重试；状态只从 `open` 改一次（`where status = 'open'`），重跑不会重复交割。
- 尾款只从店里的银币扣，不动交易所账户的银币。
- 配置里这种食材不存在了（极端情况）：状态 `cancelled`，定金退回，写日志。

撤单（玩家）：`open` 且没到期才能撤；锁店，状态改 `cancelled`，什么都不退；写个人日志。

## 7. 开关和边界

- 功能开关 `futures`，默认开，后台按区服关。关着时不能下单，能撤单；期货标签只在有进行中的单时显示（只有“我的期货单”）；已有的单照常到期交割。交易所功能（`exchange`）关着时期货也不能下单。
- 交易所被冻结的店不能下单、能撤单；已有的单照常交割，进交易所账户的部分照常进（冻结只限制交易所操作）。
- 店主被封号：不能下单撤单（账号层面挡）；已有的单照常按规则交割或违约。
- 下单后这种食材被下架、改了额度、改了区服数值：已下的单不受影响。

## 8. 区服数值

`tuning.futures`（`tuning.json`、zod、`setting_docs.json`）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `deliverHours` | 72 | 下单后几小时交割 |
| `premium` | 1.2 | 期货单价 = 基准 × 这个数 |
| `capRate` | 2 | 基准最多是等级价的几倍 |
| `depositRate` | 0.3 | 定金占总价的比例 |
| `dailyQuota` | `[500, 500, 100, 100, 100]` | 1~5 级每种每天的区服额度 |
| `personDaily` | 50 | 每家店每天所有食材合计最多订几份 |

校验：`premium ≥ 1`、`capRate ≥ 1`、`0 < depositRate ≤ 1`、`dailyQuota` 正好 5 个非负整数。

## 9. 接口

玩家：

- `GET /futures`：可下单的食材（编号、单价、区服今天还剩多少）、我今天还能订多少、交割小时数、定金比例；我的期货单（进行中的全部，已结束的最近 30 张）。
- `POST /futures/order {foodsId, qty, unitPrice}`：`unitPrice` 是玩家看到的单价，服务端重算，不一样就报 `futures_price_moved` 带新价格（参考价跨天变了）。
- `POST /futures/:id/cancel`。

后台：

- `GET /admin/futures/foods?shardId`：全部 1~5 级食材（含不在表里的），带第 5.3 节的各列。
- `POST /admin/futures/foods {items: [{foodsId, enabled?, dailyQuota?}]}`：批量改；`dailyQuota: null` 恢复默认。

## 10. 页面

- 交易所页的“期货”标签：
  - 上半部分：可下单的食材，能按等级、稀有、“本街要的”筛选、搜名字；每种写单价、交割时间、区服今天还剩多少。顶部写“我今天还能订 N 份”。
  - 点一种弹出下单框：数量（不超过三个上限里最小的）、总价、定金、尾款、到期时间；写明“到期时店里银币不够付尾款、或者到期前撤单，都算违约，定金不退”。
  - 下半部分“我的期货单”：进行中的写倒计时、尾款、撤单按钮（撤单要确认）；已交割、已违约、已撤单的写结果。
  - 交易所说明里加一段“期货怎么算”。
- 餐厅动态（首页卡和好友页动态卡）加 `futures.delivered`、`futures.defaulted` 两种。
- 后台“期货食材”页见 5.3。

## 12. 测试

- 定价：参考价低于、介于、高于等级价 × capRate 三种；四舍五入和向上取整。
- 下单：门槛、开关、冻结、不在列表、下架、超额度（区服、个人）都拒绝；价格变了报错；定金扣对。
- 额度并发：两家同时订同一种只剩 1 份的额度，只有一家成功。
- 交割：银币够时扣尾款、给食材；橱柜放不下的进交易所账户；银币不够违约；重跑不重复；关了功能的区服照常交割。
- 撤单：只能撤自己的、进行中的、没到期的；定金和额度都不退。
- 后台：mod 只读、admin 能改；批量上下架；改额度、恢复默认；写审计；不在表里的能加进表。
- 迁移：三张表和初始列表的种数（185）、各等级分布。
- 网页：期货标签的列表、筛选、下单框的上限和文案、我的期货单、撤单确认；后台页的筛选和批量操作；动态的文案（五种语言）。
