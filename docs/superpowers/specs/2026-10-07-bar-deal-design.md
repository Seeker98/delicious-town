# 酒吧新游戏 3「一掷千金」设计（开箱子、银行家买断）

- 日期：2026-10-07
- 状态：待用户审
- 来源：问题记录 427 第 3 项（一掷千金电视节目套皮）
- 做法照前两个酒吧新游戏（`2026-10-06-bar-nim-design.md`、`2026-10-06-bar-spice-design.md`）：局面存 `bar_round`，有每日次数，不加迁移。

## 1. 一句话

桌上 10 个编号箱子，每个里面是一份食材，从“1 级食材×1”到“五级万能食材×5”不等。玩家先选一个自己的箱子，再一轮轮打开别的箱子。每轮开完，小镇银行家按剩下的箱子报一个银币买断价：成交就拿银币走人，不成交就继续开。一直不成交，最后拿到自己箱子里的食材。

## 2. 用户已定的方向（2026-10-07）

| # | 问题 | 决定 |
|---|---|---|
| 1 | 买断价用什么付 | 银币 |
| 2 | 入场 | 1 万银币 |
| 3 | 次数 | 每天 3 局 |

## 3. 箱子里有什么

10 个箱子，每局开局时洗牌，奖品固定是这 10 份：

| # | 奖品 | 约值多少银币（按商店价） |
|---|---|---|
| 1 | 1 级食材 ×1 | 1,200 |
| 2 | 1 级食材 ×3 | 3,600 |
| 3 | 2 级食材 ×2 | 4,400 |
| 4 | 一级万能食材 ×2 | 6,000 |
| 5 | 3 级食材 ×2 | 7,200 |
| 6 | 4 级食材 ×2 | 10,800 |
| 7 | 5 级食材 ×2 | 15,000 |
| 8 | 三级万能食材 ×2 | 15,000 |
| 9 | 五级万能食材 ×2 | 28,000 |
| 10 | 五级万能食材 ×5 | 70,000 |

- 平均每箱约 1.6 万。
- “N 级食材”具体是哪一种，开局时就从这一级的普通食材里随机定下，存进局面。抽法和酒吧随机奖励的食材一样：不出下架的，按出现权重抽。
- 箱子的价值按这种食材的商店价 × 数量算，万能食材也按它的商店价。所以每局的价值会略有浮动。
- 奖品表是区服数值，见 §6。

## 4. 一局的流程

1. **开局**：扣 1 万银币，计每日次数（每天 3 局）。服务端洗好 10 个箱子，结束前不告诉前端每个箱子装什么。
2. **选自己的箱子**：玩家点一个箱子当自己的，之后不能换。
3. **开箱子**：一共 4 轮，每轮要开的个数依次是 3、2、2、1。
   - 玩家一次点开一个别的箱子，马上看到里面是什么。
   - 这一轮开够了，银行家报买断价。
4. **银行家报价** = 剩下所有没开的箱子（含自己的）的平均价值 × 0.5 × 本轮的系数。
   - 本轮系数依次是 0.5、0.65、0.8、0.95。
   - 0.5 是“银行家只按商店价的一半估价”，见 §5。
   - 结果四舍五入到百位。
   - **成交**：得到这么多银币，本局结束，公布所有箱子。
   - **不成交**：进入下一轮。
5. **4 轮都不成交**：这时还剩自己的箱子和另一个箱子。打开自己的箱子，得到里面的食材，公布所有箱子。
6. **中途离开**：局面存在服务端，刷新后接着玩。没有时间限制，也没有放弃，因为不管成交还是继续，几步内都会结束。
7. 每局都计每日活跃“酒吧娱乐”。
8. **新闻**：一路不成交、最后自己的箱子是最大奖（五级万能食材×5），写一条新闻。每家店每天最多一条。

## 5. 收支

模拟 20 万局（入场 1 万银币）：

| 玩法 | 平均拿到 |
|---|---|
| 一直不成交，拿自己的箱子 | 约 1.6 万银币价值的食材（按系统收购价七成卖约 1.1 万） |
| 最后一轮一定成交 | 约 7,600 银币 |
| 买断价到 8,000 就成交 | 约 9,300 的银币和食材，其中银币约 4,400 |

- 银行家按商店价的**一半**估价。如果按全价，最后一轮成交的人平均能拿约 1.5 万银币，每局净赚约 5 千银币，就成了刷银币的途径。
- 按一半估价时，拿买断的人平均拿回的银币比入场费少，整体是在**回收银币**。
- 敢赌到底的人平均能开出比入场费多一些的食材。
- “要稳稳的银币，还是赌一把食材”就成了真正的取舍。后两轮剩的箱子少、差距大，买断价也接近这个一半估价，最有意思：例如剩 7 万和 1,200 两个箱子时，报价约 1.7 万银币。
- 每天 3 局；每局都开到底的话，一天平均多出约 1.8 万银币价值的食材。

## 6. 数据

- **不加迁移**。用 `bar_round`，`game = 'deal'`。
- **state**：

```
{
  boxes: Array<{ foodsId: number; num: number; value: number }>,  // 10 个，已洗牌
  mine: number | null,      // 自己的箱子编号；还没选为 null
  opened: number[],         // 已开的箱子编号，按开的顺序
  round: number,            // 第几轮（0 起）
  offer: number | null      // 当前报价；这一轮还没开够为 null
}
```

  `boxes` 只在服务端。

- **每日计数**：`bar.deal` 记开局次数，`bar.deal.news` 记新闻条数。
- **tuning** 在 `bar` 下新增：

```
deal: {
  cost: 10000,
  dailyMax: 3,
  prizes: [
    { kind: 'food', level: 1, num: 1 }, { kind: 'food', level: 1, num: 3 },
    { kind: 'food', level: 2, num: 2 }, { kind: 'master', level: 1, num: 2 },
    { kind: 'food', level: 3, num: 2 }, { kind: 'food', level: 4, num: 2 },
    { kind: 'food', level: 5, num: 2 }, { kind: 'master', level: 3, num: 2 },
    { kind: 'master', level: 5, num: 2 }, { kind: 'master', level: 5, num: 5 }
  ],
  opens: [3, 2, 2, 1],
  offerRates: [0.5, 0.65, 0.8, 0.95],
  valueRate: 0.5
}
```

- **校验**：
  - `opens` 和 `offerRates` 的长度一样；
  - `opens` 之和 = 奖品数 − 2（最后剩自己的箱子和另一个）；
  - `level` 在 1~5；
  - 奖品数在 3~16（16 个以内前端排得下）。
- 新闻的“最大奖”是奖品表里商店价最高的那一份，开局时记下它的编号。

## 7. 接口

| 方法 | 路径 | 请求 | 返回 |
|---|---|---|---|
| GET | `/bar` | – | `BarDto` 加 `deal`：入场费、今天已玩、上限、箱子数、每轮开几个、进行中的局（或 null） |
| POST | `/bar/deal/start` | – | `DealDto` |
| POST | `/bar/deal/pick` | `{ box }` | `DealDto`，选自己的箱子 |
| POST | `/bar/deal/open` | `{ box }` | `DealDto`，开一个箱子；这一轮开够时带 `offer` |
| POST | `/bar/deal/answer` | `{ deal: boolean }` | `DealDto`：成交就结束；不成交就进下一轮，最后一轮不成交就开自己的箱子并结束 |

**`DealDto`** 的内容：
- `count`（箱子数）、`mine`、`round`、`toOpen`（这一轮还要开几个）；
- `opened`：`Array<{ box, foodsId, num, value }>`；
- `left`：剩下没开的箱子里还有哪些奖品，按价值排的清单，不说在哪个箱子里，相当于电视节目里的奖池板；
- `offer`；
- `result: 'deal' | 'box' | null`：成交还是开了自己的箱子；
- 结束时多带：`coin`（成交得到的银币）、`prize`（自己箱子里的东西）、`all`（全部箱子的内容）。

**错误**：

| 情况 | 错误 |
|---|---|
| 已有局 | `ALREADY_DONE` `what: 'bar_round'` |
| 次数用完 | `limitReached('bar_daily')` |
| 银币不够 | 原有的 `NOT_ENOUGH coin` |
| 没有局 | `invalidState('no_round')` |
| 已经选过自己的箱子 | `invalidState('deal_picked')` |
| 还没选就开箱 | `invalidState('deal_pick_first')` |
| 这一轮已经开够了，要先回答报价 | `invalidState('deal_offer')` |
| 没有报价时回答 | `invalidState('deal_no_offer')` |
| 箱子编号越界、开自己的箱子、开已开的箱子 | `badInput('box')` |

状态原因的名字开头都带 `deal_`，免得和已有的原因撞名。

## 8. 前端

- 酒吧页加第 10 个胶囊“一掷千金”。
- **开局前**：
  - 写规则，列出 10 份奖品；
  - 写“今天还能玩 n 局”；
  - 按钮“开一局（1 万银币）”。银币不够或次数用完时变灰，并写原因。
- **箱子**：
  - 10 个编号方块，两行，每行 5 个。
  - 先提示“选一个当你的箱子”。
  - 选好后，自己的箱子标“你的”。已开的箱子显示里面的食材名和数量，变灰。
  - 一轮开够了，箱子不能点，下面出现银行家的报价：
    - “银行家出价：12,300 银币”；
    - 两个按钮：“成交”“不成交，继续开”。
- **奖池板**：箱子下面列出还没开出来的奖品，按价值从高到低。
- **结束**：
  - 写拿到了什么：“成交，得到 12,300 银币”或“打开你的箱子：五级万能食材×5”。
  - 公布全部箱子；成交的话，顺带写“你的箱子里是……”。
  - 下面是“再来一局”。
- **读屏**：
  - 有一个固定的播报区，念刚开出的东西和报价。
  - 箱子按钮的标签写编号和状态（你的、已开：××）。

## 9. 测试

**服务端**
- 报价函数（纯函数）：剩余平均 × 0.5 × 本轮系数，四舍五入到百位。
- 开局：
  - 扣 1 万银币；返回和概览里不含箱子内容；
  - 每个“N 级食材”定成了这一级的一种普通食材；
  - 计次数，第 4 局被拒；
  - 银币不够时不扣、不计次数；
  - 已有局时被拒。
- 选箱子：选两次被拒；没选就开被拒。
- 开箱子：
  - 越界、开自己的、开已开的都被拒；
  - 每开一个返回里面的东西；
  - 开够本轮个数后有报价；有报价时再开被拒。
- 成交：得到银币，局面删掉，公布全部箱子。
- 不成交：进下一轮；第 4 轮不成交，开自己的箱子、发食材、结束。
- 新闻：最后自己的箱子是最大奖才写，同一天第二次不写。
- 数值校验：非法配置被拒。

**前端**：面板测试覆盖开局、选箱子、开箱、报价两个按钮、结束显示、出错时重新读、读屏播报区；酒吧页 10 个胶囊。

**端到端**：开一局，选 1 号箱子，按顺序开别的箱子，每轮都不成交，直到开出自己的箱子；检查拿到了食材、显示了全部箱子。
