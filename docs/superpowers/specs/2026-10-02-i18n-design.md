# 多语言（问题记录 272、42）

## 1. 目标

玩家界面和游戏数据支持五种语言：简体中文（zh-CN，默认）、繁体中文（zh-TW）、英语（en）、法语（fr）、西班牙语（es）。先搭框架，翻译分批做。

## 2. 用户确认的裁定

1. **翻译来源**：
   - 繁中用 OpenCC 从简中自动转换（含台湾用语）；
   - 英、法、西由 Claude 分批翻译、提交进仓库，用户抽查；
   - 缺译显示中文。
2. **游戏数据全部翻译、分批做**：
   - 先做食材、道具、天气、街道这些常见数据，菜名放最后；
   - 菜名用通行英文译名，没有的意译。
3. **管理后台只用中文**，区服数值说明（632 条）也不翻。
4. **选语言**：
   - 第一次按浏览器语言自动选；
   - 登录页和「我的账号」可以改；
   - 改了存到账号，换设备也保持；
   - 系统邮件也按这个语言。
5. **技术方案 A**：自己写带类型检查的翻译，缺翻译时类型检查报错、CI 过不了；不加依赖。

## 4. 前端

### 4.1 翻译文件

- `apps/web/src/i18n/locales/<locale>/<区域>.ts`，按区域拆文件：`common`、`errors`、`news`、`events`、`home`、`market`……
- 每种语言的 `index.ts` 汇总成一个对象。
- 值是字符串，或者带参数的函数 `(p: { n: number }) => string`。复数、语序差异都写在函数里，例如英文 `(p) => p.n === 1 ? '1 item' : \`${p.n} items\``。
- 简中的对象就是类型的来源：`export type Messages = typeof zhCN`。其他语言写成 `const en: Messages = { ... }`，少一个 key、多一个 key、函数参数不对都会让类型检查报错。

### 4.2 使用

- `useT()` 返回当前语言的翻译对象（computed）。模板里直接取属性：`{{ t.home.signIn }}`、`{{ t.home.activeToday({ n: total }) }}`，全程有类型提示，不用字符串 key。
- 语言状态放在 Pinia（`stores/locale.ts`）。简中打包进主包；其他语言按需动态加载，切换时先加载再切。
- 切换时同时设置 `<html lang>`。
- 数字和日期按语言格式化：`formatNum` 改用 `Intl.NumberFormat(locale)`，日期用 `toLocaleString(locale)`。
- 现有的 `errorMessage`、新闻文案、日志文案改为读当前语言的翻译。

### 4.3 抽取进度的守卫

- 新增一个测试：扫描玩家界面的 `.vue` 文件，注释以外不能有汉字。
- 还没抽取的文件列在白名单里，每批抽完就从白名单删掉，直到清空。
- 管理后台（`views/admin`、`components/admin`）不在扫描范围内。

### 4.4 选语言

- 没登录：用浏览器里存的选择；没有就按 `navigator.language` 判断：
  - `zh-TW / zh-HK / zh-Hant*` → zh-TW；
  - 其他 `zh*` → zh-CN；
  - `fr*` → fr，`es*` → es；
  - 其余 → en。
- 注册时把当前语言带给服务端。
- 登录后用账号上的语言；账号还没设过（老账号）就用当前语言并保存。
- 登录页右上角和「我的账号」里有语言选择，改了立刻生效；登录状态下同时存到账号。

## 5. 服务端

- `account.lang`（迁移）：text，取值限于五种语言，可为空；空表示还没选过。
- `/account/me` 返回 `lang`；新增 `POST /account/lang {lang}`；注册接口接受可选的 `lang`。
- 支持的语言列表放在 `@dt/shared`（`LOCALES`），前后端共用。
- 服务端自己产生的中文（逐个查过，共约 80 行）按用途处理：

| 类别 | 地方 | 处理 |
|---|---|---|
| 发到邮箱的邮件 | 验证邮箱、重置密码（`account/service.ts`） | 服务端按账号语言选模板（`@dt/shared` 里放这几条的五种语言） |
| 系统站内信 | 活动未领奖励补发、合力名次奖励（`activity/settle.ts`）、系统补偿（`admin/grants.ts`）、邀请奖励和新手礼包（`invite/scan.ts`）、赞助帽子升级（`ops/scan.ts`）、举报结果和违规通知（`report/admin.ts`） | 存模板键 + 参数，前端按语言渲染；管理员手写的部分（违规说明、补偿邮件正文）原样显示 |
| 事件预测自动出题 | 四类题的题目、说明、判定依据，作废原因（`predict/auto/*`） | 存代码 + 参数，前端渲染；管理员出的题是原文 |
| 接口直接返回的台词 | 镇长、大胃王等 NPC 台词（`town/*`）、外卖意外（`takeaway/rules.ts`）、神秘食谱鉴定失败（`mysterious/service.ts`） | 返回代码或序号，前端渲染 |
| 名字类 | 加成来源名（`effects/naming.ts`）、今日星愿前缀（`restaurant/service.ts`）、论坛"匿名"（`forum/view.ts`） | 返回类型和 id，前端按目录取名字 |
| 存进数据的名字 | 赞助帽子名"玉•xx之帽"、默认店名"餐厅N"、蟹黄堡公告 | 是玩家可见的数据，保持原样不翻 |
| 只给运营看的 | 命令行用法、上线检查说明 | 不翻 |

- 已有的数据保留原中文文字；新数据才用代码 + 参数。

## 6. 游戏数据

- 翻译数据：`packages/config/data/i18n/<locale>/<种类>.json`，按 id 对应 `{ "name": "...", "desc": "..." }`。种类包括 goods、foods、cookbooks、weather、streets 等。
- 构建配置时：
  - 校验 id 存在、字段合法；
  - 繁中用 OpenCC 从简中数据自动转换，人工修订写在 `data/i18n/zh-TW-overrides.json`；
  - 生成每种语言的名称表。
- 道具目录接口 `/world/catalog?lang=xx` 按语言返回名字和说明，没翻译的回退到中文。前端缓存按"配置版本 + 语言"分开。
- 前端显示名字一律经过道具目录。新闻、日志里的名字本来就是前端按 id 取的，切换语言后自动变。

## 7. 繁体中文的生成

- 开发依赖 `opencc-js`。
- 脚本 `pnpm -F @dt/web i18n:tw` 把 `locales/zh-CN/*.ts` 的源码整体转换（只影响汉字，代码不变），生成 `locales/zh-TW/*.ts`。文件头写明"自动生成"，人工修订写在覆盖表里，转换后再套用。
- 测试检查生成结果和提交的文件一致：改了简中却没重新生成，CI 会报错。

## 9. 测试

- 类型检查保证各语言的结构和函数参数一致。
- 运行时测试：每种语言的翻译对象和简中的键完全一致（防止 `as` 之类绕过类型）。
- 繁中生成结果和提交的文件一致。
- 抽取守卫：玩家界面除白名单外没有汉字。
- 配置构建：翻译数据的 id 存在，目录接口按语言返回，缺译回退中文。
- 账号语言：注册带语言、设置、`/me` 返回；非法值被拒。
- 前端：浏览器语言判断、切换后界面和数字格式变化、登录后用账号语言。
- e2e：登录页切到英语，进首页看到英文。
