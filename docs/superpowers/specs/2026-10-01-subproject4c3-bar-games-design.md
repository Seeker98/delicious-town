## 1. 目标与范围

酒吧新增三个游戏，规则和随机数都在服务端，前端只提交选择或点击时刻。

| 游戏 | 一句话 |
|---|---|
| 魔鬼辣杯 | 6 杯里有 1 杯特辣酒，玩家和调酒师轮流喝；调酒师喝到，玩家赢走翻倍的奖池；玩家喝到，输掉押注并宿醉 1 小时 |
| 记忆调酒 | 调酒师依次闪出 3 / 5 / 7 种配料，玩家按顺序点出来；每过一关拿一次奖励，可以继续挑战更长的配方 |
| 飞镖 | 准星在靶上左右摆动，点一下投出；三镖总分超过老板就赢 |

### 1.1 用户已确认的决定

| # | 问题 | 决定 |
|---|---|---|
| 1 | 名字 | 魔鬼辣杯 / 记忆调酒 / 飞镖 |
| 2 | 魔鬼辣杯玩法 | 轮流喝到底，不能中途收手；每活过一杯奖池 ×1.4 |
| 3 | 宿醉惩罚 | 1 小时上座率 -10%，显示在首页"生效的加成"里 |
| 4 | 防作弊 | 题目和随机数由服务端出，前端只回答案或点击时刻；服务端核对时间窗；记忆调酒和飞镖每天各限 20 局；奖励不超过现有酒吧玩法 |

## 2. 规则

所有游戏都用神秘礼券当筹码，每局都计每日活跃"酒吧娱乐"。每家店同一种游戏同时只有一局，状态存在服务端，刷新页面后能接着玩。

### 2.1 魔鬼辣杯

- **开局**：选押注，可选 1、5、10、20 张礼券。扣押注后，服务端随机定下特辣酒在 6 杯里的位置，不告诉前端。
- **喝**：玩家选一杯没喝过的。
  - 是特辣酒：玩家输，押注没收，宿醉。
  - 不是：玩家活过的杯数 +1，调酒师随机喝一杯剩下的。
    - 调酒师喝到特辣酒：玩家赢，得 押注 × 1.4^玩家活过的杯数 张礼券，四舍五入（终审改：原来向下取整，押 1 张时活过 1、2 杯都只拿回本金）。
    - 没喝到：轮到玩家继续。
- 玩家先喝，所以玩家最多喝 3 杯。各种结局等可能，期望回报约为押注的 1.0 倍（不算宿醉），纯运气。
- **宿醉**：1 小时内上座率 -10%。再次宿醉时重新计时，不叠加。
- **结束**：返回特辣酒的位置，以及每一杯是谁喝的。
- **新闻**：玩家活过 3 杯（拿到 ×2.744）时写新闻。

### 2.2 记忆调酒

- 8 种配料：朗姆、伏特加、金酒、柠檬、薄荷、糖浆、冰块、苏打。
- **开局**：每局 1 张礼券，每天最多 20 局。服务端生成第 1 关的配方（3 种，可以重复），连同展示节奏一起发给前端。
- **展示**：每种配料闪 600ms，间隔 200ms。
- **作答**：玩家按顺序点出整串配料，一次提交。服务端检查两件事：
  - 时间：从发出配方算起，最早要等展示完（允许提前 300ms），最晚是展示完后 3 秒 + 每种配料 1.5 秒。不在这个窗口里，按答错算。
  - 内容：顺序完全一样才算对。
- **奖励**：
  - 答对第 1 / 2 / 3 关（3 / 5 / 7 种），分别得奖励等级 2 / 4 / 8 的随机奖励（酒吧共用的随机奖励，不出礼券），当场发放。
  - 答对后可以"继续"挑战下一关（不再扣礼券，生成新配方），也可以"收手"结束本局。
  - 答错或超时，本局结束，已经拿到的奖励不收回。
- **新闻**：三关全过写新闻。

### 2.3 飞镖

- **开局**：每局 2 张礼券，每天最多 20 局。服务端按权重给老板抽三镖的分数（50 分 10%、25 分 30%、10 分 35%、5 分 20%、0 分 5%），在结束前不告诉前端。
- **每一镖分两步**：
  1. **瞄准**：服务端随机定下摆动周期（900~1400ms）和起点相位，记下发出时间，返回给前端。前端按这两个参数画准星，位置在 -1 到 1 之间来回匀速摆动（三角波）。
  2. **投掷**：前端提交从拿到瞄准参数到点击经过的毫秒数。服务端检查这个数不能大于服务端实际经过的时间 + 100ms，也不能比它早 1500ms 以上（网络延迟的余量），否则这一镖记 0 分。通过检查后，用这个时间算出准星位置。
- **得分**：按离靶心的距离 |x| 计分：≤0.05 得 50，≤0.15 得 25，≤0.3 得 10，≤0.5 得 5，更远得 0。
- **结算**：三镖投完后比较总分。
  - 玩家总分大于老板：赢，得奖励等级 5 的随机奖励。三镖都是 50 分时改为奖励等级 10，并写新闻。
  - 平局：退 1 张礼券。
  - 输：什么都没有。
- 结束时公布老板三镖的分数。

### 2.4 防作弊和收益控制

- 特辣酒位置、老板分数、随机数都只在服务端，结束前不发给前端。
- 记忆调酒的配方必须展示给玩家，飞镖的准星轨迹必须画给玩家，所以脚本可以照着答。服务端做三层限制：
  - 时间窗：太快、太慢都无效。
  - 每天各 20 局。
  - 奖励封顶：随机奖励最高等级 8~10，和猜酒杯、转数字相当。
- 记录可疑数据，供以后的后台查看：每日计数 `bar.memory.perfect`（三关全过）、`bar.darts.bull`（50 分的镖数）。本子项目不做后台页面。

## 3. 数据

**迁移 0015**：新建 `bar_round`，一家店一种游戏一行，只放进行中的局。

| 列 | 类型 | 说明 |
|---|---|---|
| `rest_id` | integer | 店 |
| `game` | text | `devil` / `memory` / `darts` |
| `state` | jsonb | 各游戏的局面 |
| `started_at` | timestamptz | 开局时间 |
| `updated_at` | timestamptz | 最后一步的时间 |

- 主键是 `(rest_id, game)`。
- 一局结束就删掉这一行，所以开新局时不会和旧局冲突。

**各游戏的 state**（只存在服务端）：
- 魔鬼辣杯：`{ stake, spiked, cups: Array<'me' | 'bartender' | null>, survived }`
- 记忆调酒：`{ level, seq: number[], shownAt, passed }`；`passed` 为 true 表示本关已答对、等玩家选继续或收手。
- 飞镖：`{ boss: number[3], throws: number[], aim: { period, phase, at } | null }`

**宿醉**：加成来源 `sourceType = 'bar'`、`sourceId = 1`，效果 `{ atRate: -0.1 }`，到期时间为当前时间加 1 小时。用 upsert 写入，所以再次宿醉会重新计时。显示名称是"宿醉"。

**tuning** `bar` 下新增：

```
devil: { stakes: [1, 5, 10, 20], cups: 6, rate: 1.4, hangoverMinutes: 60, hangoverAtRate: -0.1, newsSurvived: 3 }
memory: { cost: 1, dailyMax: 20, ingredients: 8, lengths: [3, 5, 7], awardLevels: [2, 4, 8], flashMs: 600, gapMs: 200, earlyMs: 300, answerBaseMs: 3000, answerPerItemMs: 1500 }
darts: { cost: 2, dailyMax: 20, periodMs: [900, 1400], futureMs: 100, latencyMs: 1500, rings: [[0.05, 50], [0.15, 25], [0.3, 10], [0.5, 5]], bossOdds: [[50, 10], [25, 30], [10, 35], [5, 20], [0, 5]], winLevel: 5, perfectLevel: 10, tieRefund: 1 }
```

## 4. 接口

| 方法 | 路径 | 请求 | 返回 |
|---|---|---|---|
| GET | `/bar` | – | 原有 `BarDto`，新增 `devil`、`memory`、`darts` 三块：进行中的局（不含秘密）、今日已玩局数和上限 |
| POST | `/bar/devil/start` | `{stake}` | `DevilDto`（当前局面） |
| POST | `/bar/devil/drink` | `{cup}` | `DevilDto`；结束时含 `result: 'win' \| 'lose'`、`spiked`、`payout`、`hangoverUntil` |
| POST | `/bar/memory/start` | – | `MemoryRoundDto`：`{ level, seq, flashMs, gapMs, answerMs }` |
| POST | `/bar/memory/answer` | `{answer: number[]}` | `{ correct, level, award, canNext, finished }` |
| POST | `/bar/memory/next` | – | `MemoryRoundDto` |
| POST | `/bar/memory/stop` | – | `{}` |
| POST | `/bar/darts/start` | – | `DartsDto`：`{ throws, aim: null }` |
| POST | `/bar/darts/aim` | – | `{ period, phase }` |
| POST | `/bar/darts/throw` | `{elapsedMs}` | `{ x, score, throws }`；第三镖后含 `boss`、`result`、`award` |

**错误**：
- `ALREADY_DONE` 加 `what`：
  - `bar_round`：同一种游戏已有进行中的局；
  - `cup_taken`：这杯已经喝过。
- `invalidState`：
  - `no_round`：没有进行中的局；
  - `not_passed`：本关还没答对，不能继续；
  - `no_aim`：没有先瞄准就投掷。
- `limitReached('bar_daily', {max})`：今天的局数用完了。
- `badInput`：押注不在可选范围、杯号越界、答案长度不对。

## 5. 前端

- 酒吧页把游戏标签改成两行可换行的胶囊（`.dt-pills`），共 7 个游戏。页面标题用 `.dt-page-title`，右侧显示礼券数。
- **魔鬼辣杯**：选押注后开局。6 个杯子排成两行，已喝的标出是谁喝的。点一杯后先显示玩家喝的结果，再显示调酒师喝的结果。结束时亮出特辣酒的位置，提示输赢和宿醉。
- **记忆调酒**：8 个配料按钮排成网格。展示阶段依次高亮配方里的配料，这时按钮不能点；展示完后玩家依次点选，选满就提交，可以撤回最后一个。答对后可以选"继续"或"收手"。
- **飞镖**：一条横向的靶子，中间是靶心色带，准星用 `requestAnimationFrame` 按服务端给的参数摆动。点"投掷"后提交经过的毫秒数，显示这一镖的落点和得分。三镖后公布老板分数和输赢。
- 每局结果用 toast 提示，奖励文案沿用酒吧现有的奖励显示。
- 首页"生效的加成"里显示"宿醉"，归在"其他"分组。
