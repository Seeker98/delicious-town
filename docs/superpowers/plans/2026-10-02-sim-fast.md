# 快速数值模拟（问题记录 160）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在内存里跑主线成长的快速模型（`pnpm sim:fast`），结算直接调用游戏代码；支持多套数值并排对比、旁支产出表、分布报告和核对命令。

**Architecture:** 先把三段"读库 + 纯计算"拆开，抽出共用纯函数：`toSettleInput`、`computeEffectAgg`、`strengthGain`，真实服务和快速模型都调用它们。快速模型在 `apps/server/src/sim/fast/` 下分层：
- `state`：内存状态；
- `ops`：资源、道具、食材、奖励、行为计数这些原语，照抄真实服务的规则；
- `world` 和 `round`：一轮结算；
- `market`、`bot`、`side`：菜场、机器人、旁支产出；
- `run`：跑一套数值；
- `variants`：多套数值、多线程；
- `report`：报告；
- `calibrate`：核对。

**Tech Stack:** TypeScript strict、Node `worker_threads`、Vitest、现有 `@dt/config` 和 `@dt/shared`。

**Spec:** `docs/superpowers/specs/2026-10-02-sim-fast-design.md`

## Global Constraints

- 快速模型不连数据库和 Redis（核对命令里的全真那一侧除外）。
- 每 4 分钟一轮（`ROUND_MS`），一天 360 轮；机器人的画像和上线时间和 `sim/bot.ts` 的 `PERSONAS` 一致。
- 每次上线的动作顺序和 `sim/bot.ts` 的 `botTurn` 一致。
- 旁支来源只能是 `town`、`hiphop`、`bar`、`yard`、`tower`、`temple`、`takeaway`、`equip`；参与度默认 `{ diligent: 1, normal: 0.7, casual: 0.4 }`；所有数值都向下取整，常驻加成不打折。
- 多套数值：基准加其他套最多 8 套；`--set` 一次只能写一个；覆盖文件格式是 `{ "tuning": {...} }`，深合并后用 tuning 的 schema 校验。
- 报告：和基准相差超过 10% 的格子标颜色；曲线画中位数，基准另画 10%~90% 阴影带。
- 核对容差：等级差不超过 1、星级相同、银币差不超过 20%、食谱数差不超过 15%；不通过时退出码为 1。
- 三个共用函数的重构不能改变任何现有行为，现有测试全部通过。
- vitest 从仓库根目录跑；中文注释和中文输出。

## Review Focus

1. 两套数值完全一样时（比如 `--set` 只给了当前值），结果必须和基准完全一样（公共随机数）。
2. 机器人银币是 0、或者油用完停业时，不能报错或卡死：要么跳过这个动作，要么等着下次上线加油复业。
3. 旁支产出表里某个来源只有高等级段（比如厨塔从 10 级起）时，低等级的机器人得到 0，不是报错。
4. `--days` 很小（1 天）时，"第 7、14、30 天等级"这些列显示"—"，不能是 NaN 或报错。
5. 某个画像一个机器人都没有时（`--personas diligent`），报告只出现这个画像的数据，其他画像不出空表，也不报错。

`aggregate.ts` 增加 `computeEffectAgg`。内容是从 `getEffectAgg` 里搬出来的"汇总加收藏派生"：

```ts
export interface ActiveEffectLike extends EffectLike {
  sourceType: string;
  sourceId: number;
}

/** 加成汇总（真实服务和快速模型共用）：来源汇总 + 牌匾、勋章、盆栽、名画、纪念牌匾的收藏派生 */
export function computeEffectAgg(
  sources: ActiveEffectLike[],
  owned: ReadonlySet<number>,
  config: GameConfig,
  tuning: Tuning,
  now: Date,
): EffectAggregate {
  const live = sources.filter((s) => !s.expiresAt || s.expiresAt > now);
  const { agg, nextExpireAt } = aggregateEffects(live, now);
  let plaques = 0;
  for (const id of owned) {
    const g = config.goods.get(id);
    if (g && g.type === GOODS_TYPE.device && g.deviceType === DEVICE_TYPE.plaque) plaques += 1;
  }
  let honors = 0;
  let pots = 0;
  let paintings = 0;
  for (const s of live) {
    if (s.sourceType !== 'honor') continue;
    honors += 1;
    const dt = config.goods.get(s.sourceId)?.deviceType;
    if (dt === DEVICE_TYPE.pot) pots += 1;
    if (dt === DEVICE_TYPE.painting) paintings += 1;
  }
  const derived = collectionEffects(
    { plaques, honors, pots, paintings, an2023: owned.has(GOODS.an2023Plaque),
      an2025: owned.has(GOODS.an2025Plaque), mdcg: owned.has(GOODS.mdcgPlaque) },
    tuning.collection,
    config.bundle.potTiers,
    config.bundle.paintingTiers,
  );
  for (const [k, v] of Object.entries(derived)) agg[k] = (agg[k] ?? 0) + v;
  return { agg, nextExpireAt };
}
```

`getEffectAgg` 改成：读 `listActiveEffects` 和持有的道具 id，然后调用 `computeEffectAgg`，写缓存，返回 `agg`。行为不变。如果 `collectionEffects` 放在 `collection.ts`、导入它会造成循环引用，就把 `computeEffectAgg` 放进 `collection.ts`，记 Ruling。

`strength.ts` 增加：

```ts
/** 一次体力恢复（真实定时任务和快速模型共用）：已满返回 null */
export function strengthGain(
  r: { strength: number; strength_max: number; luck: number },
  agg: Record<string, number>,
  tuning: Tuning,
  rng: Rng,
): { add: number; cap: number } | null {
  const cap = r.strength_max + (agg.holyBless ?? 0);
  if (r.strength >= cap) return null;
  const base = rng.chance(luckRate(r.luck + (agg.luckValue ?? 0))) ? tuning.strength.luckyRegen : tuning.strength.regen;
  const mult = (agg.autoReStrength ?? 0) > 0 ? agg.autoReStrength! : 1;
  return { add: Math.round(base * mult), cap };
}
```

`regenStrength` 的循环体改成调用 `strengthGain`。

import { toSettleInput, type SettleSource } from '../../modules/settlement/globals';
import { settleRestaurant } from '../../modules/settlement/settle';

import { aggOf, gainCoin, gainExp, gainOil, gainRenown, grantGoods, spendCoin, subFoods } from './ops';
import type { FastCtx, FastRest } from './state';

export function fastSettleSource(r: FastRest, agg: Record<string, number>, now: Date): SettleSource {
  return {
    rest: { id: r.id, level: r.level, star: r.star, oil: r.oil, oilMax: r.oilMax, coin: r.coin, streetId: r.streetId,
      renown: r.renown, luck: r.luck, cteOn: r.cteOn, cookfoodsFlag: r.cookfoodsFlag },
    tables: r.tables,
    levels: r.levels,
    counts: r.counts,
    agg,
    special: null,
    cupboard: r.cookfoodsFlag > 0 ? new Map([...r.foods].filter(([, n]) => n > 0)) : null,
    now,
  };
}

/** 一轮结算写回，规则和 settlement/runner.ts 的 settleOne 一致 */
export function settleRound(c: FastCtx, r: FastRest, g: SettleGlobals): 'settled' | 'closed' | 'skipped' {
  if (r.state !== 1) return 'skipped';
  const agg = aggOf(c, r);
  const res = settleRestaurant(toSettleInput(fastSettleSource(r, agg, c.now)), g, c.rng);
  if (res.closed) {
    r.state = 2;
    return 'closed';
  }
  r.tables = res.tables;
  gainCoin(c, r, res.coin, 'settlement');
  gainExp(c, r, res.exp, 'settlement');
  if (res.oil > 0) r.oil -= res.oil;
  if (res.renown !== 0) gainRenown(c, r, res.renown);
  for (const d of res.drops) grantGoods(c, r, d.goodsId, d.num, 'settlement', d.hours);
  for (const f of res.foodsUsed) subFoods(c, r, f.foodsId, f.num);
  autoRefuel(c, r, agg);
  return 'settled';
}

function autoRefuel(c: FastCtx, r: FastRest, agg: Record<string, number>): void {
  if ((agg.autoAddOil ?? 0) <= 0) return;
  if (r.oil >= c.tuning.settlement.autoRefuelThreshold) return;
  const need = r.oilMax - r.oil;
  if (need <= 0 || r.coin < need) return;
  spendCoin(c, r, need, 'oil.auto');
  gainOil(c, r, need);
}

export function regenRound(c: FastCtx, r: FastRest): void {
  const g = strengthGain({ strength: r.strength, strength_max: r.strengthMax, luck: r.luck }, aggOf(c, r), c.tuning, c.rng);
  if (g) r.strength = Math.min(r.strength + g.add, g.cap);
}

13. **买菜**：用 `foodsNeedFor(全部食谱, levels, 1, needOf)` 算出缺口。在日常和特价货架上买，留出"油壶 + 2 万 + 要攒的钱"。然后按 `sim/bot.ts` 的规则报名竞猜。

15. **合成**：照抄 `composeSurplus`：
    - 当天的免费次数 = `freeHandleBase + freeHandlePerStar × 星级`，减去当天已用；
    - 每种 1~4 级食材的余量 = 持有 − 学菜还要用的 − 5；

- [ ] **Step 3: 实现**

`metrics.ts`：
- `percentile`：排好序后取下标 `Math.min(n - 1, Math.floor(p * n))` 的元素，空数组返回 null。
- `keyTable`：每套数值、每个画像算一行，单元格有：
  - `star<N>Days`：到达 N 星的中位天数，没有人到达就是 null；
  - `star<N>Never`：最后都没到 N 星的人占的比例；
  - `day7Level`、`day14Level`、`day30Level`：超过模拟天数就是 null；
  - `coinPerDay`：每天净银币的中位数，按"最后一天银币减第一天银币，再除以天数"算，含旁支；
  - `stuckRate`：卡住的人占的比例。

`report.ts`：
- 单个 HTML 文件，样式内联。
- 依次输出：说明段、关键指标表、每个画像的曲线、旁支收入占比、卡点明细。
- 和基准相差超过 10% 的格子着色：天数越少越好，等级和银币越多越好。
- null 显示成"—"。
- 曲线：复用 `sim/report.ts` 的 `lineChart`，给它加一个可选参数 `band`（10%~90% 区间），对现有调用没有影响。
- 同时写出每张表的 CSV，复用 `toCsv`。
- 画像的中文名：勤快、普通、休闲。

`calibrate.ts`：
- 用 `sim/run.ts` 的 `runSim` 跑全真模拟：每种画像 1 个机器人，`days` 和 `seed` 与快速模型相同，`dbName` 用 `dt_sim`。
- 快速模型同样的设置，不算旁支。
- `compareCalibration`：按画像，比较每天的中位数（各画像只有 1 个机器人，就是那一个）。容差：
  - 等级差不超过 1；
  - 星级相同；
  - 银币差不超过 20%：分母取两边较大的那个，两边都是 0 时算通过；
  - 食谱数差不超过 15%。
- 打印对照表，超出的标"✗"；最后打印"通过"或"不通过"，不通过时设 `process.exitCode = 1`。

`cli.ts`：
- `fast` 子命令跑完之后调用 `writeFastReport`，打印每套的用时和报告路径；
- 带 `--calibrate` 时走核对流程，不写多套报告。

`docs/sim-fast.md`：写给要调数值的人，内容按设计 §10：
- 怎么跑；
- 怎么读报告；
- 怎么改产出表；
- 怎么做多套对比；
- 什么时候跑核对；
- 不模拟的内容。
