# 秘制调料（几 A 几 B）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 酒吧加第 9 个游戏“秘制调料”：猜 10 种调料里 4 种的排列，回答几 A 几 B，最多 8 次，按第几次猜中分档发奖。

**Architecture:** 完全照最后一颗糖（#190）的结构：
- 局面存在 `bar_round`（`game = 'spice'`），配方只在服务端；
- 每日次数用 `bar.spice`，新闻次数用 `bar.spice.news`；
- `/bar` 概览沿用 `peekRounds`、`getDailies`；
- 计分是纯函数，放在 `rules.ts`；
- 前端加 `SpicePanel`。

**Tech Stack:** Fastify + Kysely + Postgres；Vue 3；zod；vitest。

**Spec:** `docs/superpowers/specs/2026-10-06-bar-spice-design.md`

## Global Constraints

- 文案四种语言：zh-CN、en、es、fr。zh-TW 用 `pnpm -F @dt/web i18n:tw` 生成。
- 叫法和现有酒吧文案一致：
  - en：Mystery Vouchers、bartender、renown；
  - es：vales misteriosos、barman、renombre；
  - fr：bons mystère、barman、renommée。
- 规则文案里不出现字母变量（k、n 之类）。
- `.vue` 里不写中文。
- 不加迁移；`/bar` 查询预算（10）不升。
- 新数值每个都要在 `setting_docs.json` 里写说明；状态原因名不能和已有的撞（先 grep `errors.ts`）。
- 改了 config、shared 后要 build。
- 提交末尾 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`；`git add` 只加明确路径。
- 数值：

```
spice: { cost: 2, dailyMax: 5, kinds: 10, length: 4, tries: 8,
  tiers: [ { maxTries: 4, awardLevel: 8, renown: 5, news: true },
           { maxTries: 6, awardLevel: 5, renown: 2, news: false },
           { maxTries: 8, awardLevel: 3, renown: 0, news: false } ] }
```

## Review Focus

1. 配方在结束前不会出现在任何返回里：开局、猜、`/bar` 概览、错误参数都不行。
2. 非法的组合（长度不对、有重复、越界、不是整数）被拒，而且不算一次。
3. 第 8 次猜中算赢（小奖），不算输。
4. 同一天第二次拿大奖不再写新闻；新闻计数和开局次数是两个 key。
5. 礼券不够、次数用完：不扣、不计、不建局。

### Task 1: 数值（config）

- 文件：`packages/config/src/tuning.ts`、`data/game/tuning.json`、`data/game/setting_docs.json`、`build.test.ts`、`tuning.test.ts`。
- 测试：
  - build 后的值等于上面的数值；
  - 校验：`length > kinds` 拒绝；`kinds > 10` 拒绝；`tiers` 的 `maxTries` 不递增拒绝；最后一档不等于 `tries` 拒绝。
- 实现：

```ts
const spiceTier = z.object({ maxTries: int.min(1), awardLevel: int.min(1), renown: int.min(0), news: z.boolean() });
spice: z.object({ cost: int.min(0), dailyMax: int.min(1), kinds: int.min(2).max(10), length: int.min(1), tries: int.min(1), tiers: z.array(spiceTier).min(1) })
  .refine((x) => x.length <= x.kinds, 'length must be <= kinds')
  .refine((x) => x.tiers.every((t, i) => i === 0 || t.maxTries > x.tiers[i - 1]!.maxTries), 'tiers.maxTries must increase')
  .refine((x) => x.tiers.at(-1)!.maxTries === x.tries, 'last tier must equal tries'),
```

  `setting_docs.json` 给每个新 key 写说明，`bar` 分组的说明里加上“秘制调料”。
- 跑 `pnpm -F @dt/config build && npx vitest run --project config`；提交。

export const barSpiceGuessBody = z.object({ guess: z.array(z.number().int().min(0).max(99)).min(1).max(10) });

### Task 3: 计分（纯函数）

- 文件：`apps/server/src/modules/bar/rules.ts`、`rules.test.ts`。
- `export function spiceScore(secret: readonly number[], guess: readonly number[]): { a: number; b: number }`
- 测试：
  - `[0,1,2,3]` 猜 `[0,1,2,3]` 得 4A0B；
  - 猜 `[4,5,6,7]` 得 0A0B；
  - 猜 `[3,2,1,0]` 得 0A4B；
  - 猜 `[0,2,1,9]` 得 1A2B。
- `export function spiceTier(tries: number, tiers): number`：返回第一个满足 `tries ≤ maxTries` 的档位下标。测试：1→0、4→0、5→1、6→1、7→2、8→2。
- 先跑失败，再实现；提交。

### Task 4: 服务端玩法、接口、概览

- 文件：
  - 新建 `apps/server/src/modules/bar/spice.ts`、`spice.test.ts`；
  - 修改 `round.ts`（`BarGame` 加 `'spice'`）、`view.ts`、`service.ts`、`routes.ts`。
- `spice.ts`：
  - `SpiceState = { secret: number[]; guesses: SpiceGuessDto[] }`。
  - `spiceView(s, t)`：`{ guesses, left: t.tries - guesses.length, result: null, secret: null, tier: null, renown: 0, award: null }`。
  - `spiceStart(o)`：
    - 检查 `assertNoRound`；
    - 检查次数（`getDaily` 对 `bar.spice` 和 `dailyMax`）；
    - `consumeGoods`、`incrementDaily`；
    - 配方用 Fisher–Yates：从 `0..kinds-1` 洗牌，取前 `length` 个；
    - `saveRound`；`emitAction('bar.play')`、`emitAction('bar.spice')`。
  - `spiceGuess(o, guess)`：
    - 先校验：长度等于 `length`、每个都是 `0..kinds-1` 的整数、不重复，否则 `badInput('guess')`；
    - 读局面，没有就报 `no_round`；
    - 用 `spiceScore` 计分，push 进记录；
    - `a === length` 时赢：
      - `tier = spiceTier(guesses.length)`；
      - `gainRenown`；
      - `randomAward(level)`；
      - 这一档 `news` 为 true 时，用 `incrementDaily('bar.spice.news')`，结果 === 1 才 `opNews(o, 'bar.spice', { tries })`；
      - `endRound`；`restLog('bar.spice', { result: 'win', tries })`；
      - 返回时带 `secret`。
    - 否则次数用完时输：`endRound`、`restLog`，返回带 `secret`。
    - 否则 `saveRound`，返回 `spiceView`。
  - `NEWS_TYPES` 加 `'bar.spice'`，位置在 `packages/shared/src/news.ts`。四种语言的新闻文案在 `news.ts` 里加（Task 5）。
- `view.ts`：`getDailies` 加 `'bar.spice'`；`spice` 块的 `round` 用 `spiceView`，不含配方。
- 测试（`spice.test.ts`；随机数用 `sequenceRng` 加 script，写法同 `nim.test.ts`）：
  - 开局：
    - 扣 2 张；
    - 返回和概览里都没有配方（`JSON.stringify` 里不含 `secret` 的值，`secret: null`）；
    - 计次数，第 6 局拒绝；
    - 礼券不够不扣；
    - 再开拒绝。
  - 非法组合（长度 3、`[1,1,2,3]`、`[0,1,2,10]`）被拒，`left` 不变。
  - 猜：记录 a、b，`left` 减 1。
  - 直接写局面测赢：
    - 已猜 0 次时猜中：第 0 档，声望 +5，有新闻；
    - 同一天再来一局第 1 次猜中，不再写新闻；
    - 已猜 4 次后猜中，即第 5 次：第 1 档，声望 +2；
    - 已猜 7 次后猜中，即第 8 次：第 2 档，赢，声望 +0。
  - 已猜 7 次后猜错：输，有 `secret`，没有奖励，局面删掉。
  - 没有局时猜：`no_round`。
- 跑 `spice.test`、bar 全部、`perf/budget.test`；提交。
