# 收购玩法 PR 3（页面、新闻、后台、默认开）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 玩家能用上收购：收购页（身价榜、在售、投资榜、我的）、对方餐厅页的收购卡片、首页“你的餐厅归某某所有”、确认框、报错文案、新闻、后台可疑数据页的拦截记录、更新记录和攻略；功能开关改成默认开。

**Architecture:** 服务端只做小改动：收购的报错带 `scope: 'acquire'`（原因名和别的玩法重名，比如 `not_owned`、`npc`），前端按 scope 查收购自己的文案表；强收、买挂牌、赎身到 1,000 万以上发新闻；餐厅总览带上老板；Wiki 攻略的数带上收购的几项；后台可疑数据加一个接口。前端新页面 `AcquireView`，卡片组件 `AcquireCard` 放在对方餐厅页，首页加一行。

**Tech Stack:** Vue 3 + Pinia + vue-router + Bootstrap（apps/web），Fastify + Kysely（apps/server），vitest + @vue/test-utils。

**Spec:** `docs/superpowers/specs/2026-10-06-acquire-design.md`（§1.5、§3.4、§5 第 3 条、§6 页面）

## 裁定（写计划时定的）

1. **身价榜不逐行写“不能收购的原因”。** 逐行算原因要给 50 家各查当天次数、同一对、关联账号，身价榜一次要上百条查询。改成：点“收购”时先读这家店的收购信息（`GET /acquire/rest/:id`），不能收就提示原因，能收再弹确认框。对方餐厅页的卡片照设计直接写原因。
2. **赎身新闻也用 `newsMinPrice` 门槛。** 设计只在强收那条写了门槛；赎身不设门槛的话，10 万的小店赎身也上新闻，会刷屏。
3. **报错按 scope 区分。** 收购的原因名 `not_owned`、`npc`、`star` 等已经被别的玩法用了（文案不同），服务端收购的 `invalidState` 都带 `scope: 'acquire'`，前端先看 scope。
4. **确认框里的税按前端算**：`AcquireRestDto` 加 `taxRate`；对方得 = floor(价格 × (1 − 税率))，和服务端 `share` 同样先换成百万分比。
5. **首页的老板信息放进 `/restaurant/overview`**（第一条查询 left join，不多一条查询），不在首页另调 `/acquire`。

## Review Focus

1. 价格在确认框弹出后变了（零点重算、别人刚收购）：服务端报 `price_changed`，前端提示新价格并刷新，不扣钱。
2. 功能关着的区服：更多菜单、对方餐厅页、首页都不出现收购的东西，也不发请求。
3. 蟹老板、自己的店：对方餐厅页不显示收购卡片。
4. 窄屏（手机）上收购页的表格、按钮不撑出屏幕。
5. 英法西文案和中文的键一致，带参数的文案不出现 undefined。
