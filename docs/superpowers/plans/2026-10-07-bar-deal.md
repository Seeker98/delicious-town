# 一掷千金 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 酒吧加第 10 个游戏“一掷千金”：10 个箱子，选自己的，分 4 轮开别的，银行家按剩余平均价值 × 0.5 × 本轮系数报银币买断价；成交拿银币，一直不成交拿自己箱子里的食材。

**Architecture:** 照最后一颗糖、秘制调料：
- 局面存 `bar_round`，`game = 'deal'`；
- 每日计数 `bar.deal` 记开局次数、`bar.deal.news` 记新闻条数；
- 概览沿用 `peekRounds`、`getDailies`；
- 报价函数是纯函数，放在 `rules.ts`；
- 前端面板 `DealPanel`。

**Spec:** `docs/superpowers/specs/2026-10-07-bar-deal-design.md`

## Global Constraints

- 同前两个游戏：
  - 四种语言，zh-TW 最后生成；
  - 叫法一致：en Mystery Vouchers / bartender / renown / coins；es barman / renombre / monedas；fr barman / renommée / pièces；
  - 规则文案不出现字母变量；`.vue` 不写中文；
  - 不加迁移；`/bar` 查询预算不升；
  - 新数值都写 `setting_docs`；
  - 状态原因带 `deal_` 前缀；
  - 改了 config、shared 后要 build；
  - 提交末尾写 Co-Authored-By；`git add` 只加明确路径。
- 前端从一开始就做：
  - 固定的读屏播报区；
  - 按钮标签带状态；
  - 任何错误都先用概览里的局面，局面没了才回到开局；
  - 格子用 `minmax(0, 1fr)`，名字允许折行。
- 数值：

```
deal: { cost: 10000, dailyMax: 3,
  prizes: [ {kind:'food',level:1,num:1}, {kind:'food',level:1,num:3}, {kind:'food',level:2,num:2}, {kind:'master',level:1,num:2},
            {kind:'food',level:3,num:2}, {kind:'food',level:4,num:2}, {kind:'food',level:5,num:2}, {kind:'master',level:3,num:2},
            {kind:'master',level:5,num:2}, {kind:'master',level:5,num:5} ],
  opens: [3, 2, 2, 1], offerRates: [0.5, 0.65, 0.8, 0.95], valueRate: 0.5 }
```

## Review Focus

1. 箱子内容在开出来之前不泄露：开局、选箱子、开箱子、概览、报价，`left` 奖池板只给出奖品清单、不说在哪个箱子里。
2. 状态机不能被绕过：
   - 没选箱子就开；
   - 有报价时继续开；
   - 没报价时回答；
   - 开自己的箱子或已开的箱子；
   - 结束后再操作。
3. 最后一轮不成交就开自己的箱子、发食材；成交只发银币、不发食材。
4. 银币不够、次数用完：不扣、不计、不建局。
5. 新闻只在“不成交、开出最大奖”时写，每家店每天最多一条。

### Task 3：报价（纯函数）

- `rules.ts`：`export function dealOffer(values: readonly number[], rate: number, valueRate: number): number`，结果是 `round(avg × valueRate × rate / 100) × 100`。
- 测试：
  - `[70000, 1200]`、0.95、0.5 得 16900；
  - 10 个默认值、0.5、0.5 得 4000（161200 / 10 × 0.25 = 4030 → 4000）。
- 提交。

### Task 4：服务端

- 新建 `deal.ts` 和 `deal.test.ts`；修改 `round.ts`（`BarGame` 加 `'deal'`）、`view.ts`、`service.ts`、`routes.ts`。
- `DealState`：`{ boxes: DealPrizeDto[]; mine: number | null; opened: number[]; round: number; offer: number | null; top: number }`。`top` 是商店价最高那份奖品所在的箱子编号。
- **开局**：
  - 检查已有局、次数；`spendCoin(cost)`；计次数。
  - 对每份奖品：
    - `food`：从 `level === L`、`odds === 100`、没下架的食材里按 `weight` 抽一个；
    - `master`：取 `FOODS.masterBase + L`；
    - 价值 = 这种食材的商店价 × 数量。
  - Fisher–Yates 洗牌；`top` 记最大价值的箱子（价值相同时取先出现的）。
  - 保存局面；`emitAction('bar.play')`、`emitAction('bar.deal')`。
- **视图**：
  - `toOpen` = 本轮应开的个数 − 本轮已开的个数（有报价时为 0）。本轮已开的个数 = 已开总数 − 前几轮应开之和。
  - `left`：没开的箱子（含自己的）的奖品，按价值从高到低。
- **pick**：已选过报 `deal_picked`；编号越界报 `badInput('box')`。
- **open**：
  - 没选报 `deal_pick_first`；有报价报 `deal_offer`；
  - 编号越界、是自己的、已开过，报 `badInput('box')`；
  - 记下开的箱子；本轮开够了就用 `dealOffer` 算报价。
- **answer**：
  - 没报价报 `deal_no_offer`。
  - 成交：`gainCoin(offer)`，结束；`restLog('bar.deal', { result: 'deal', coin })`。
  - 不成交：
    - 还有下一轮：`round + 1`，`offer = null`，保存。
    - 没有了：用 `addFoods` 发自己箱子里的食材，结束。自己的箱子是 `top` 时，用 `incrementDaily('bar.deal.news')`，等于 1 才写新闻 `bar.deal`，参数 `{ foodsId, num }`。`restLog` 写结果 `box`。
- 测试照 spec §9。随机数用 script 控制；测成交、最后一轮、新闻时，直接写局面。
- 跑 bar、budget 测试；提交。
