# 收购玩法 PR 2（分红和打理）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 被收购的店每天给老板分红（前一天结算 × 5%，打理过 ×1.5，满 90 轮才发，每个老板按自己的收入封顶），被收购的店每天能替老板打理一次（得 5 份食材）；记下每家每天的分红和每个老板的累计分红，读接口带上。功能开关仍然默认关。

**Architecture:** 在 PR 1 的 `apps/server/src/modules/acquire/` 里加：`rules.ts` 加分红的纯函数，新文件 `dividend.ts` 是发分红的任务（每个老板一个事务，`runSystemOp` 锁老板的店加银币），`jobs.ts` 加第三个每天的任务 `acquire-dividend`，`service.ts` 加 `tend` 并在读接口里带上分红和打理。打理记在新表 `acquire_tend (rest_id, day)`，不用 PR 1 的 `acquire_state.tended_day`（见裁定 1）。

**Tech Stack:** Fastify + Kysely + Postgres（apps/server），zod（packages/shared），vitest。

**Spec:** `docs/superpowers/specs/2026-10-06-acquire-design.md`（§1.4、§3.1、§3.2、§3.3、§6 分红 / 打理）

- 分红 = floor(前一天结算银币 × dividendRate × (打理过 ? 1 + tendBonus : 1))；前一天结算不满 minRounds 轮不发。
- 封顶：一个老板一天的分红合计 ≤ floor(老板自己近 priceDays 个完整游戏日结算银币合计 / priceDays × dividendCapRate)；超了每家按比例压（整数，向下取整，合计不超过封顶）。
- 发给任务跑的时候（00:05 以后）的老板；老板账号被封不发；被收购的店账号被封照常算。
- 流水来源 `acquire.dividend`；打理的食材来源 `acquire.tend`。
- 打理：被收购的店每个游戏日一次；tendFoods 份食材，每份从随机奖励的食材池（`awardFoodsPool`，按店的等级）抽，带个人缺料倾向（`opNeedPick`）；没有老板报 `not_owned`，今天打理过报 `tended`。

## 裁定（写计划时定的）

1. **打理另记一张表，不用 `tended_day`。** `tended_day` 只存最近一次：玩家 00:00~00:05 之间打理今天，会把昨天的标记盖掉，分红任务就看不到昨天打理过。新表 `acquire_tend (rest_id, day)` 主键防重复，迁移 0051 删掉 `tended_day`（PR 1 加的，功能一直关着，没有数据）。
2. **分红任务每天一次，不补发。** 每个老板一个事务，某个老板失败只记日志、不影响别人；整个任务失败当天不补：补发时已经不知道 00:05 的老板是谁（之后可能换过人、新收购的店会被错发）。分红记录主键 (rest_id, day)，同一天重跑不会重复发。
3. **封顶的“近 7 天”用 priceDays**（默认 7，和身价同一个区间：今天之前的 7 个完整游戏日，不满 7 天的按 0 算）。
4. **只给满 minRounds 轮的店写分红记录**；压到 0 的也写（coin = 0），页面上能看出“发了但被封顶压没了”。老板被封时整个老板跳过，不写记录。
5. **分红记录、打理记录留 30 天**，在 `acquire-day` 里按区服清（同交易记录）。

## Review Focus

1. 打理在 00:00~00:05 之间（分红任务跑之前）：昨天的打理照样 ×1.5（裁定 1；Task 3 有测试）。
2. 老板名下几家店、合计超过封顶：每家按比例压，合计不超过封顶，不会因为取整多发 1 个银币（Task 2、3）。
3. 同一天任务重跑：不重复加银币、不重复加累计（Task 3）。
4. 老板自己的收入很低（新店）：封顶也低，分红可能是 0；不报错（Task 3）。
5. 打理时并发点两次：只成功一次，食材只发一份（Task 4，主键 + 锁店）。

**Interfaces:**
- Produces:

  - `dividendCap(ownerCoinSum: number, t: T): number` —— `share(Math.floor(ownerCoinSum / t.priceDays), t.dividendCapRate)`。
  - `capDividends(raw: number[], cap: number): number[]` —— 合计 ≤ cap 原样返回；否则每项 `floor(raw × cap / 合计)`（BigInt 算，免得超过 2^53）。

### Task 3: 发分红的任务

**Files:**
- Create: `apps/server/src/modules/acquire/dividend.ts`
- Modify: `apps/server/src/modules/acquire/jobs.ts`（加 `acquire-dividend` 任务；`runAcquireDay` 清 30 天前的分红、打理记录）
- Test: `apps/server/src/modules/acquire/dividend.test.ts`、`jobs.test.ts`（清理）

**Interfaces:**
- Consumes: Task 2 的 `dividendOf`、`dividendCap`、`capDividends`；`incomeSums`（income.ts）；`priceWindow`（state.ts）；`runSystemOp`、`restLog`（core/op）；`gainCoin`；`isBanned`。
- Produces: `payDividends(d: GameDeps, shardId: number, now: Date, t: T, log?): Promise<{ owners: number; rests: number; coin: number; failed: number }>`，发的是 `addDays(gameDay(now), -1)` 那天的。

做法：

1. 一条查询：本区服被收购的店（`acquire_state.owner_rest_id is not null`）join 老板的店和账号（封号字段）、left join 前一天的 `rest_income_day`、left join 前一天的 `acquire_tend`。
2. 按老板分组；老板被封（`isBanned`）跳过；每家 `dividendOf`，null 的不要。
3. 一条查询算所有老板近 priceDays 天的收入（`incomeSums`），`dividendCap` → `capDividends`。
4. 每个老板 `runSystemOp(d, shardId, ownerId, { source: 'acquire.dividend', now })`：
   - `insert into acquire_dividend ... on conflict do nothing returning rest_id, coin`；
   - 插进去的合计 > 0 时 `gainCoin(op, total, { source: 'acquire.dividend' })`，`acquire_holder` upsert `dividend_total += total`，`restLog(op, 'acquire.dividend', { day, n, coin })`（n = 插进去的家数）；
   - try/catch：失败 `log.error` 并计入 failed，接着下一个老板。
5. 任务：`{ name: 'acquire-dividend', feature: 'acquire', period: 00:05 以后 → 'acquire-dividend-<day>', run: payDividends }`，排在 `acquire-day` 后面。
