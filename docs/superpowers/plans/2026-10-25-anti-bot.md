# 游戏接口防脚本 实现计划（PR①：签名、节奏标记、白名单）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 写请求带上只有本站网页才会生成的签名，服务器校验（默认只记录、开关打开后拦截），并按账号统计操作节奏、在后台“可疑数据”里标出像机器的账号，支持账号白名单。

**Architecture:** 签名协议（拼串、HMAC、请求头名）放在 `@dt/shared`，网页和服务端共用同一份代码；服务端在防重复提交之后挂一个 `preHandler` 钩子校验、决定拦不拦，并用 Redis 按“账号 × 小时”计数；worker 每小时把上一小时的计数写进 `play_rhythm` 表；后台新标签页读这张表打分排序。

**Tech Stack:** Fastify 钩子、ioredis、Kysely 迁移、WebCrypto（浏览器和 Node 都有 `globalThis.crypto.subtle`）、Vue 3、vitest。

**Spec:** `docs/superpowers/specs/2026-10-25-anti-bot-design.md`（第 1~5 节、白名单、上线方式）。第 6 节（可疑号人机验证）、第 7 节（签名代码混淆）**不在这个 PR**，这个 PR 合并后另写计划，不要叠 PR。

## Global Constraints

- 默认模式“只记录”：`tuning.ops.antibot.mode` 默认 `"log"`；开发区服、e2e 一律保持 `"log"`。
- 拦截时只让这一下操作失败，返回 `ErrorCode.CLIENT_UNVERIFIED`（HTTP 403），不扣东西、不处罚账号。
- 不按点击快慢拦截；频率、节奏只计数、只在后台展示。
- 后台接口（`/api/v1/admin/*`）永远只记录、不拦。
- 环境变量 `ANTIBOT_FORCE_LOG=true` 时强制只记录，优先于区服设置。
- 白名单账号拦截模式下也不拦，照样记录；节奏列表里标“白名单”、排最后。上线时名单为空。
- 不签、不校验：没登录的请求、开放接口 `/api/v1/open/*`、测试接口 `/api/v1/test/*`、所有读请求（读请求只带版本号）。
- 拦截模式下只有环境检查的两项硬条件直接拒绝：`navigator.webdriver` 为真、浏览器标识含 `HeadlessChrome`；其余环境位只记录。
- “距离最近一次真人操作”只计数，不拦。
- 请求钩子里不写数据库；Redis 计数失败只记日志，不影响请求（照 `registerPlayTrace`）。
- 节奏表保留 30 天，由现有清理任务删。
- 玩家看的简中文字用半角括号、英文冒号逗号（`: `、`, `）；繁中 `zh-TW` 是生成的，改完简中后跑 `pnpm i18n:tw`，不要对它跑 prettier。
- 推送前跑 lint、`prettier --check .`、三个包的测试；类型检查分包跑看退出码。
- 只 `git add` 明确路径。

## Review Focus

1. **玩家重新登录（或改密码）后旧页面还开着**：服务器会话的密钥换了，旧密钥签的请求对不上。期望：只记录模式下这一次算“签名不对”，服务器回 `x-dt-resign: 1`，网页清掉缓存密钥，下一次就对了；拦截模式下网页收到 `CLIENT_UNVERIFIED` 后重取密钥、换新随机数自动重试一次并成功。→ Task 3、Task 6 各有测试。
2. **同一个防重复提交 key 的合法重试**（网络抖动后网页重发同一个请求）必须拿到缓存响应，不能被当成重放拦下。→ Task 3 测试。
3. **手机时间不准**（差几个小时）：网页用取密钥时服务器给的时间算偏移，签名时间戳按服务器时间。→ Task 6 测试。
4. **不该校验的请求**：注册、登录、开放接口、测试接口、读请求，拦截模式下也照常。→ Task 3 测试。
5. **Redis 计数出错**不能让请求失败。→ Task 4 测试（用会抛错的假 redis 对象，不用 `vi.mock`）。

**Interfaces:**

- Produces:
  - `export function hourKey(d: Date): string` — UTC 整点，`'2026-10-25T03'`
  - `export function recordRhythm(redis: Redis, e: { accountId: number; at: Date; method: 'GET' | 'POST'; route: string; verdict?: Verdict; idle?: number | null; idleMs: number; ua: string | null; deviceId: string | null; ip: string }): Promise<void>` — 一个 pipeline 完成；`route` 用 `req.routeOptions.url`（带 `:id` 的模板，不带具体值）

- Redis 结构（键都带 3 小时过期）：
  - `rh:<hour>:<accountId>` 哈希：`posts`、`gets`、`gap_n`、`gap_sum`、`gap_sq`、`gap_min`（用 Lua 或读后比较，builder 定）、`bursts`、`no_view`、`idle_long`、`v:<verdict>`、`r:<route>`

  - `rhl:<accountId>`：上一次写请求时间（毫秒）；`rhg:<accountId>`：最近一次读请求，过期 300 秒
