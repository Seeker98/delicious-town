# 快速数值模拟

在内存里模拟玩家的主线成长。想调一个数值时，用它在一分钟内看到勤快、普通、休闲三种玩家 30 天的成长节奏和经济。设计文档见 `docs/superpowers/specs/2026-10-02-sim-fast-design.md`。

现有的全真模拟器（`pnpm sim`）照常保留，用来核对快速模型准不准，见"什么时候跑核对"。

## 怎么跑

```
pnpm sim:fast                                    # 默认 30 天，每种画像 20 个机器人，只跑当前数值
pnpm sim:fast --set settlement.expMultiplier=4,6 # 当前数值加上两种经验倍率，一共 3 套并排对比
pnpm sim:fast --variant 慢=slow.json --variant 快=fast.json
pnpm sim:fast --set settlement.expMultiplier=4 --set market.dailyKinds=6  # --set 可以写多次
```

| 参数 | 说明 |
|---|---|
| `--days 30` | 模拟天数 |
| `--bots 20` | 每种画像几个机器人。越多分布越准，也越慢 |
| `--seed 1` | 随机种子。同样的参数和种子，结果完全一样。它只决定机器人自己的运气（比如开礼包开到了什么），**不改变**天气、菜场上货、老鼠、痞老板和体力恢复：这些按区服和时间算，换种子也一样 |
| `--personas diligent,normal,casual` | 跑哪几种画像 |
| `--set 路径=值1,值2` | 对一个数值扫几个取值，每个取值算一套。路径相对 tuning，比如 `market.dailyStock` |
| `--variant 名字=文件` | 可以写多个。文件格式和区服覆盖一样，比如 `{ "tuning": { "settlement": { "expMultiplier": 6 } } }` |
| `--side 文件` | 换一张旁支产出表；写 `none` 就不算旁支 |
| `--ops` | 旁支产出再加上运营发放（兑换码、邮件），表在 `side-income-ops.json`；默认不算 |
| `--out 目录` | 报告放哪。默认 `sim-out/fast-<时间>/` |
| `--stuck-days 5` | 等级够了，但超过几天升不了星，就算"卡住" |
| `--start 2026-10-01T00:00:00+08:00` | 模拟从哪个时间开始。天气、菜场、月度主题按这个时间算 |
| `--calibrate` | 跑核对，见"什么时候跑核对"。这时 `--days`、`--bots` 不写默认是 5，写了就按写的 |

天数、机器人数、`--stuck-days` 要是正整数，`--seed` 要是整数，画像只能是 `diligent`、`normal`、`casual`，`--start` 要能解析成时间；写错时直接报错退出。

当前数值总是作为"基准"一起跑，基准加其他套一共最多 8 套。每套在一个线程里跑，所以几套一起跑的总时间和只跑一套差不多。在开发机上，30 天、每种画像 20 个机器人，一套大约 40~50 秒。

几套数值用的是同一组随机数，差异只来自数值本身，不来自运气。

## 怎么读报告

`report.html` 是单个文件，直接用浏览器打开，内容从上到下是：

1. **说明**：这次的参数，以及快速模型**不模拟**的内容。
2. **关键指标**：每套数值、每种画像一行，都是中位数。
   - "N 星天数"是到达 N 星的中位天数；"没到 N 星"是到最后都没到的人占比。
   - 后面几列依次是第 7、14、30 天的中位等级、每天净银币、卡住的人占比。
   - 和基准相差超过 10% 的格子会上色：绿色更好，红色更差。没有数据的格子显示"—"。
3. **曲线**：每种画像画等级、星级、银币、学会的食谱数四张图。每套数值一条中位线，阴影是基准 10%~90% 的人所在的范围，用来看运气差的玩家会不会被甩开。
4. **收入来源**：银币和经验来自结算、旁支（按来源细分）、任务、活跃、其他的比例。旁支占比很高时，结论要打折扣，因为旁支是估出来的。
5. **银币流入与流出**：每人每天平均流入多少、花掉多少（按用途：买菜、升星凭证、餐桌、设施、加油、扩油箱、搬街等）、净额。只算快速模型里会做的事，旁支玩法自己的花费（外卖开通、厨具强化、一番赏、交易所手续费等）不在里面。
6. **卡点**：卡住的机器人和原因：
   - `cookbooks`：会做的菜不够；
   - `certs`：缺升星凭证；
   - `coin`：没钱买凭证；
   - `foods:食材名`：学菜缺的食材。

同一目录下还有每张表的 CSV（`key.csv`、`days.csv`、`income.csv`、`spend.csv`、`stuck.csv`）和原始结果 `results.json`。

## 怎么改旁支产出表

厨塔、神殿、酒吧、外卖、广场 NPC、嘻哈、厨具这些玩法不逐个模拟，而是按 `apps/server/src/sim/fast/side-income.json` 每天发一次平均产出。2026-10-12 按线上核对加了三项：没模拟的玩法的支线任务（`quest`）、厨具一键卖（`equipSell`）、黑市金币袋（`black`）；兑换码和邮件（`ops`）是运营发的，单独放在 `side-income-ops.json`，写 `--ops` 才算。依据见 `docs/design/快速模拟收入核对-2026-10-12.md`。

- `participation` 是三种画像的参与度，0~1。实际得到的 = 表里的数值 × 参与度，向下取整。
- `rows` 每行是一个来源的一个等级段。同一来源取 `minLevel` 不超过当前等级的最高一行；没有一行满足的等级段，就什么都不发。
- 可以写的数值：`coin`、`exp`、`diamond`、`strength`、`renown`、`goods`（道具 id 和数量）、`effects`。
  - `effects` 是常驻加成，比如 `coinRate`。它不打折扣，升到新的等级段时整体换掉。
  - `randomFoods` 是随机奖励里的食材（问题记录 50 验证时加的）：每项写 `times`（每天平均抽几次）、`level`（奖励等级），酒吧小游戏再写 `bar: true`。
    - 抽法和真实的 `award/random.ts` 一样：普通随机奖励只出权重 100 的普通食材，等级不超过 min(奖励等级, 5)；酒吧按奖励档次的等级范围出，可以出稀有。
    - 和真实一样带个人缺料倾向，幸运翻倍按幸运率。
    - 次数乘参与度后随机取整（比如 0.56 次是 56% 的天抽 1 次），不是向下取整，免得小数次数全被抹掉。
    - 现在酒吧、厨塔写了；次数、等级都是估算，估法见那两行的 `note`。
    - 缺料清单按天近似：一天算一次。真实是每局小游戏、每次胜利各算一次，当天抽到的会让清单变短，这里不回头减。
- `note` 写清楚这个数是怎么估出来的。

写错来源名、道具 id 或加成键时，命令会直接报错，并指出是第几行。

## 什么时候跑核对

```
pnpm sim:fast --calibrate --days 3 --bots 5
```

不写 `--days`、`--bots` 时默认 5 天、每种画像 5 个。只有核对要连 Redis（全真模拟器用），平时跑 `sim:fast` 不需要 `REDIS_URL`。

快速模型的成长动作（学菜、买菜、升星等）是照着游戏规则在内存里重写的。改了结算、成长、菜场、任务的规则以后，这两边可能对不上。核对命令会：

1. 用同样的种子，快速模型和全真模拟器各跑一遍，都不算旁支；
2. 逐天比较每种画像的中位数：
   - 等级差不超过 1；
   - 星级相同；
   - 银币差不超过 20% 或 1 万；
   - 学会的食谱数差不超过 15% 或 2 道。
3. 打印对照表，最后给出"通过"或"不通过"。不通过时退出码是 1。

全真那边用一次性库 `dt_sim`，每天大约 30 秒乘以机器人数的倍数。

两边的天气、菜场上货、老鼠、痞老板用的种子相同，所以看到的世界一样；不同的只是机器人自己的运气，比如开礼包开到了什么。机器人太少时，这种运气差异会被放大，所以核对默认每种画像 5 个。

## 机器人什么时候搬街

只能学、升级所在街道的菜（问题记录 312），新手街只有 69 道，不够升 2 星，所以机器人会搬街：

- 在新手街到 13 级就搬（2026-10-12 线上核对：玩家 5~19 级、中位 13 级离开新手街）；
- 在别的街，下一星还差食谱数，而本街没学过的菜都学了、或者连续 3 天没学到新菜就搬；
- 都搬到没学过的菜最多的街；
- 有搬家处工作证免卡，否则用搬家卡；没有卡就花钻石在黑市买一张，钻石不够就不搬；
- 付 餐桌数 × 餐桌A 价格的一半（幸运时再减半），换街道勋章。

离开新手街以后收入会跳一大截：新手街勋章把挑剔顾客几乎压没了（spRate −0.35），别的街挑剔顾客按整道菜的价钱付。

## 机器人怎么凑食材

- 按缺口买本街食谱学到 1 品级还缺的食材；
- 缺 L+1 级食材时，在日常货架多买 L 级的当原料（缺 1 个买 6 个），合成上去；
- 合成先用当天的免体力次数，用完以后只要上一级还缺料就花体力接着合（留 20 点体力）；学菜用不到的食材不留余量；
- 从没合成过时先合成 2 个，做主线"合成或分解一次食材"。

全真模拟器（`sim/bot.ts`）的搬街、合成、买原料用同一套规则。

## 任务

主线、支线、章末能领就领。算旁支产出时（平时都算）：

- 主线里没模拟的玩法的一次性引导（好友、酒吧、特色菜、神殿、厨具、厨塔、一番赏、广播、论坛、克拉肯）按已完成算，线上玩家进章当天就做完；外卖除外（开通要 888 万）；
- 限时活动按不可用算（菜园 2026-10-13 删掉了）；
- 这些玩法支线的奖励按产出表的 `quest` 行折算。

`--side none` 和核对时照规则算，和全真模拟器一致。

## 快速模型不模拟什么

- 好友互动、论坛、邮件、举报；
- 真人玩家抢菜：同一套数值里的机器人共用货架，只和彼此抢；
- 特价菜"同一网络 10 分钟只能抢一次"的冷却：每个机器人当作不同网络；
- 厨具强化过程：厨具带来的加成按产出表折算；
- 区服里的蟹老板 NPC 店；
- 特色菜的售卖；
- 依赖旁支玩法的支线任务（好友数、外卖等）：这些任务在快速模型里完成不了，奖励按产出表的 `quest` 行折算；
- 运营发放（兑换码、邮件）：默认不算，写 `--ops` 时按 `side-income-ops.json` 折算。

## 已知差异（从待办挪过来，2026-10-13）

各 PR 终审记下的、只影响模拟准确度的地方。调数值前看一眼，修掉一条删一条。

**和全真模拟、线上的差异**
- 快速模型的冰箱只进不出：不解冻，也不收入库费、仓储费（线上 2026-10-22 起收，见冰箱收费）。
- 快速机器人买菜后会减少缺口，全真机器人不减：同一种菜在日常和特价货架都有时，全真会买两遍。
- 未穿戴的厨具在快速模型里不占仓库格，快速机器人“仓库满了”会来得晚一点。
- `buyable` 判断“永久”用的是 `invalidHours`，真实用 `goodsEffectHours`（还看 `value.time`）；机器人目前不买勋章，不影响。
- 开局几个小时的天气和巡街和全真不同：全真开局就按最近时段重掷，快速模型要到下一个天气时刻和巡街时刻。
- 旁支的常驻加成要到第二天第一次上线才换等级段，最多晚一天。
- 买设施、摆设施没检查设施本身的 needStar（只查了格子）；现在只买便宜设施，不受影响。
- `starBlockers`：缺凭证、银币分别够两笔但不够两者之和时，只报 certs 不报 coin（只影响卡点原因）。
- 不模拟每周任务（每周 3 张探险图不在它的数里）；`TASK_EXTRA` 不认经营、支线扩充 B 的新计数和状态，这些支线的奖励不进经济模拟。
- 机器人不花声望，看不到声望商店的四、五级食材随机券对升星的影响。
- 旁支产出表里厨具那几行是粗估的银币、经验加成，没区分套装和厨具收益加成；不模拟特色菜卖出。
- 厨塔的声望还是“5 次 × 6”的粗估。

**随机数和统计**
- 机器人整局用一个随机流：两套数值的决策一分叉，之后的随机数就不再对齐；可以按（种子, 机器人, 轮）派生。
- 旁支的随机食材用机器人自己的随机数流：缺料倾向开关时两边从第一次抽取起就错开；可以单独建一条流（参考 run.ts 的 hashSeed）。
- 分位数用 `floor(p·n)`，偶数个时中位数取偏上的那个。
- 每次抽随机食材都重建食材池，开销可以忽略。
- 测试没覆盖幸运翻倍、酒吧稀有比例；统计新增食材只看橱柜，不看冰箱。

**概率核对工具（sim/odds）**
- 厨具、神殿、神秘菜谱按设定的幸运算期望，没像酒吧那样读店里当时的幸运。
- 和服务端测试共用测试库，跑的时候会清空重建；以后可以换一个单独的库。
