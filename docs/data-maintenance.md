# 游戏数据维护

改游戏数据（`packages/config/data`）和写改玩家数据的迁移时要注意的事。

## 新街道数据（问题记录 284）

新街道的菜谱、食材、勋章由另一个 agent 生成，放在仓库外的 `data/新街道菜谱`，菜名译名在 `data/i18n`。那边改了数据后：

1. 重跑导入：`pnpm -F @dt/config import-streets`
   - 整份替换 `data/designed/` 下的 `*_new.json`，8~10 品级按老数据的换料频率重新生成（种子 284，结果固定）。
   - 已经不存在的新菜谱译名会自动删掉；新增的街道会自动补进 `street_medal_map.json`（勋章 id = 92000 + 街道 id）。
   - 上次导入过的新菜谱 id 这次没了、或者换了街道时，脚本什么都不写、直接退出（多半是那边顺移了 id）。确认确实要删或改，再加 `--allow-removed` 重跑。
   - 去掉一条街时，`street_medal_map.json` 里那一行要手删（构建会报错提醒）。
2. `pnpm -F @dt/config build`，构建会检查菜谱、售价表、勋章对照的一致性。
3. **新菜谱 id 已经上线，要求那边固定 id，不能顺移。** 改了 id 等于删掉老菜、加一道新菜，学过的店会丢记录。

## 改已学食谱的迁移

- 删菜、移街用迁移 0039 的 `reviseCookbooks(db, deleted, moved)`：按清单清掉已学字节、调整已学计数和各街计数，并删掉点了被删菜、还能接的外卖单。0040 也复用它。
- **改这个函数要保证不传 `restIds` 时行为不变**：已经跑过的迁移在新库上还会再跑一遍。`restIds` 只给测试用，免得测试改到共享测试库里别的店。
- 0039 一次把所有店的已学记录读进内存（开发库 1366 家约 25MB）。以后在大库上跑类似迁移，要改成在 SQL 里过滤或分页。

## 下架道具、食材（问题记录 367）

用不到的道具、食材不删定义，记进下架名单 `packages/config/data/game/retired.json`：

- 玩家手上已有的照常显示、能用能卖；不再从任何途径产出：退出商店、随机奖励池、各等级食材池（菜场、合成、神殿、礼包、兑换券都从这里抽）、交易所和开放接口（Wiki）。
- 构建时检查：下架的东西还被奖励、礼包、兑换、食谱、特色菜、区服数值里的奖励引用，或者代码里用到（`itemRefs.ts` 的 `CODE_GOODS`），构建报错并列出引用处。后台按区服改数值时也查同一套。
- 名单用道具整理工具改：`pnpm -F @dt/server items`（默认端口 5199，只在本机监听），打开 http://127.0.0.1:5199/。
  - 每行列出来源、用途、原版来源（`dataset/goods_sources`）和有条件才成立的说明（“只能靠菜园获得”“食谱只在品级上限调到 10 时用到”）；可以按“没有来源”“没有用途”等筛选。
  - 来源按配置和服务端的规则函数算（`apps/server/src/items/analyze.ts`，默认区服数值）。新加了产出食材或道具的玩法，要在那里补上，不然工具会误报“没有来源”。
  - 勾选、写备注后保存：先按新名单构建一次，过不了就不写文件、在页面上列出原因。
- 保存后 `pnpm -F @dt/config build`，再重启开发服务器生效；提交 `retired.json`。
- 要恢复：在工具里取消勾选再保存。
